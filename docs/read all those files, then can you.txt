How the Enforcement Works

If Elai is going to be the ultimate deterministic vibe-coding engine, it absolutely must handle Python, TypeScript, Go, or anything else you throw at it.

Here is how the architecture actually decouples the strictness of the execution from the language being executed:
1. The Validation Layer is an Adapter, Not a Hardcoded Command

Tier 3 and the integration test runners don't literally run cargo check under the hood for everything. They run a dynamically assigned command inside the BashSandbox.

What command gets run is determined during the PLANNING / FEASIBILITY phase. When the system indexes the project (or when the Designer proposes a new one), it establishes the validation contract.

    For Rust: It sets the validation command to cargo check.

    For Python: It sets the validation command to python -m py_compile (for syntax), mypy (for types), or ruff check (for fast linting).

    For TypeScript: It sets the command to tsc --noEmit.

2. The FailureTaxonomy (The Universal Translator)

This is the actual secret sauce from Phase 4B. When Elai runs a validation command or a test, it gets raw bash stdout/stderr back. It never asks the LLM, "Did this pass?"

Instead, the orchestrator pipes that raw output through the FailureTaxonomy, which uses 9 deterministic regex categories to classify the failure, regardless of the language:

    Syntax/Parse Errors: Catches Python IndentationError or JS SyntaxError.

    Missing Imports: Catches Python ModuleNotFoundError or TS Cannot find module.

    Type/Logic Errors: Catches mypy strictness failures or TypeError.

    Test Failures: Catches pytest assertion errors or Jest failures.

If the regex matches a failure category, the orchestrator instantly constructs a structured error payload and bounces the LLM back to the execution loop. The LLM sees: "Validation Failed (MISSING_IMPORT): 'requests' module not found" instead of a raw, confusing stack trace.
3. Tree-sitter is Naturally Multi-Language

Remember Tier 2 (<10ms AST Parse)? The Data Knowledge Graph (DKG) is powered by tree-sitter. Because tree-sitter has grammars for almost every language, Elai can instantly verify if a Python file has a missing colon or a TypeScript file has a mismatched bracket without ever invoking a Python or Node runtime. The Rust orchestrator does this entirely in memory.
4. Dynamic Integration Wiring

In the Baby Step cycle, the final check is "Integration Wiring" (is the new code reachable from the entry point?).

    In Rust, this checks mod and use statements from main.rs.

    In Python, the exact same graph logic queries the DKG to see if the new def rate_limiter(): is imported and called anywhere from main.py or app.py.

The determinism isn't achieved by forcing everyone to use a specific compiler; it’s achieved by forcing the LLM to pass a generic Execution -> Sandbox -> Taxonomy -> Pass/Fail loop.
