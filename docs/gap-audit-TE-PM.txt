STEP A-42: TOKEN RECLAMATION TECHNIQUES [TE section 9]
  READ: docs/specs/guide/token-efficiency-design.txt
    -> section 9 (TOKEN RECLAMATION TECHNIQUES: 5 techniques, formatting removal
       research grounding 24.5% savings, language-specific Python preservation)
    -> section 9 (FORMATTING REMOVAL: 4 sub-points with implementation details,
       output formatting restoration via tree-sitter)
  READ: docs/specs/guide/steps/phase-3E.txt (context budget assembly pipeline)
  What: implement 5 token reclamation techniques in context budget assembly:
    1. FORMATTING REMOVAL (applied to CodeContext slot):
       Strip leading/trailing whitespace per line, collapse multiple blank lines,
       remove trailing comments that repeat the code.
       PRESERVE: string literals, docstrings, significant indentation (Python).
       Language-specific: Python preserves indentation. All others strip.
       Research-grounded: 24.5% token reduction, zero accuracy degradation.
    2. OUTPUT FORMATTING RESTORATION:
       After LLM generates code, apply tree-sitter pretty-print to restore
       proper indentation before writing to disk. Model generates minimally
       formatted code, system restores deterministically.
    3. PATH ABBREVIATION:
       src/middleware/auth.rs -> middleware/auth.rs (strip common prefix).
       Model can infer src/ from context.
    4. IMPORT COLLAPSING:
       Show as "// [12 imports]" with expand-on-request. Full imports waste
       small model attention. Expand only if model requests specific import.
    5. DEDUPLICATION:
       If same type appears in 3 snippets, define it once with reference.
       Use symbol names instead of full signatures when context is clear.
  Touches: context_budget.rs (phase 3E assembly), orchestrator/ (output restoration)
  Prerequisites: A-10 (context budget adaptation)
  Estimated scope: ~250-350 LOC

  What: implement the Oracle Mode 7-phase research pipeline:
    Phase A — QUERY FORMULATION (LLM): user question -> 2-4 search queries.
      Structural rephrasing, not creative. Queries logged in SSB.
    Phase B — SEARCH EXECUTION (deterministic): execute queries via WebSearch,
      collect URLs + snippets, deduplicate by URL.
    Phase C — SOURCE TIER CLASSIFICATION (deterministic, no LLM): classify
      every URL against lookup table. LLM has ZERO input on tier assignment.
      Uses source-tiers.toml from A-45.
    Phase D — FACT EXTRACTION (LLM, constrained): extract ExtractedFact from
      T1/T2 sources. EXACT QUOTE field is critical — prevents misrepresentation.
      Facts without exact_quote = UNSUPPORTED (logged but not used).
    Phase E — CROSS-VERIFICATION (deterministic): count supporting sources per
      claim. VERIFIED (2+ T1/T2), SUPPORTED (1 T1/T2), WEAK (T3 only),
      UNSUPPORTED (no exact quotes). Set intersection, not LLM reasoning.
    Phase F — SYNTHESIS (LLM, constrained): receives ONLY ExtractedFacts,
      not raw pages. Every sentence must cite a fact. Uncited sentences removed
      by post-processing regex. Output: answer + evidence chain + confidence.
    Phase G — POST-VERIFICATION (deterministic): 4 checks — citation completeness,
      tier consistency, "I don't know" enforcement, hallucination guard.
      Re-synthesis max 2 retries, then escalate with raw evidence chain.
    Types: ResearchQuery, SourceTier (T1-T4), SourceClassification,
      ExtractedFact (with exact_quote), VerificationLevel, VerifiedClaim,
      ResearchAnswer (with confidence + caveats + unanswered_parts),
      AnswerConfidence (HIGH/MEDIUM/LOW/UNKNOWN).
    ~800-1200 LOC. Touches orchestrator/ and cli/.
