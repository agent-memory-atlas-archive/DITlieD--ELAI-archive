Technology choices (HARD RULE — override training defaults):

Hashing: blake3 only. Never blake2, never sha2 for non-RFC uses.
Logging: tracing only. Never the log crate. Never println!/eprintln!.
Error handling: thiserror for library crates, anyhow for binaries. Never Box<dyn Error>.
Async mutex: tokio::sync::Mutex when lock held across .await.
Async traits: native async fn in traits (Rust 1.75+). Never async-trait crate.
ONNX: ort stable releases only. Never -rc / pre-release.
Python HTTP: FastAPI + uvicorn. Never http.server.
Python inference: model.generate() with LogitsProcessor. Never manual token loops.
Python torch: torch.inference_mode() not torch.no_grad(). torch_dtype= not dtype=.
Python JSON: orjson over stdlib json for hot paths.
Connection pooling: deadpool (async) or bb8. Never r2d2 unless provably sync-only.
Glob: globset or ignore crate. Never glob 0.3.
No .unwrap()/.expect() in production code. Use ?/.ok_or()/.map()/Result propagation.
  Acceptable ONLY in: test code, main() entrypoint, const/static init with provably valid literals.
No as casts for numeric narrowing. Use .try_into().
No magic numbers. Named constants for all limits/thresholds/dimensions.

  - commit as "A-N: <description>" (or "3K.N:" or "B-N:") with test results in message
  - push after commit
