## Context
Why this matters: the entire wedge — RRA replay (G-2), canvas-as-truth (J-31/J-60), "derive status from the journal" (I-39), "trust the journal" — assumes the journal is COMPLETE. It is not provably so: a hash-chain proves nobody EDITED a row, never that every real effect WROTE one. An agent (or a bug, or a non-mediated tool) can produce a side-effect with no journal row, and the chain stays valid, the RRA replays clean, the canvas shows no anomaly. This is a definition-of-completeness failure the integrity machinery is structurally blind to (exactly the wiring-enforcement insight one level up: "an append-only log cannot know it is incomplete"). The technical fix is mediate-the-critical-set + observe-the-rest + reconcile-missing=FAIL (E1, the J sub-track). The K-native job is the DISCIPLINE: a binding pre-gate so the E1 executor builds it fail-closed from the start (a dropped-event must SCREAM, not shrug) and so no downstream copy ships a "complete / full / tamper-proof / fully-auditable journal" over-claim when the honest claim is "every COVERED effect class left a row." Mechanism: one .claude/rules/ doctrine file (conditional-routing loads it on completeness/side-effect/observer tasks) + a K-1 lint recogniser so positioning copy cannot ship a completeness over-claim without the covered-scope qualifier.

THE FOUR-CLAUSE JOURNAL-COMPLETENESS INVARIANT (the rule K-21 ships; binds future E1 / side-effect-mediation / kernel-observer / reconcile / trust-the-journal work):
  JC-1 COMPLETENESS-IS-NOT-INTEGRITY: a hash-chain (I-18/J-69) proves no row was ALTERED; it CANNOT prove every real side-effect PRODUCED a row (an append-only log cannot know it is incomplete). Any claim that rests on completeness — "trust the journal", "the RRA replays the whole run", "the canvas shows everything", "status is derived from the journal" — is an OVER-CLAIM unless the covered effect set is mediated-or-observed (JC-2) and reconciled (JC-3). Integrity and completeness are ORTHOGONAL axes; proving one is not proving the other.
  JC-2 MEDIATE-OR-OBSERVE-THE-COVERED-EFFECT-SET (never assume-journaled): a DECLARED high-value effect class (write-opens, network egress, child-process spawn/exec, privilege changes) must either be MEDIATED — the effect cannot complete unless its SSB row commits ATOMICALLY with the approval (SECCOMP_RET_USER_NOTIF through Tier-C, EXTENDING the shipped G-3 FS/egress gate, not new architecture) — or independently OBSERVED at the kernel layer (eBPF/LSM, Tetragon/Falco-class) into an INDEPENDENT feed. A side-effect that is neither mediated nor observed is OUT-OF-SCOPE and must be NAMED as such (JC-4), never silently assumed-journaled. A normalization layer is MANDATORY (observer FPs are SCHEMA-MISMATCH — temp-file churn, path aliasing, retries — not hallucinated events).
  JC-3 RECONCILE-MISSING=FAIL + MONITOR-THE-MONITOR: any independently-observed sensitive effect with NO matching journal row inside a bounded window is a DETERMINISTIC FAIL (the wiring-enforcement R1 missing=FAIL doctrine applied to completeness; absence of proof is proof of absence for the reconcile gate). The reconciler is deterministic — the LLM never adjudicates a match (TD-3). MONITOR-THE-MONITOR: dropped-event counters FAIL CLOSED; "observer impaired / feed unavailable / counter nonzero" is a FIRST-CLASS verdict (a dead evidence path SCREAMS, wiring R2), NEVER silent continuation. OBSERVE-ONLY first (GD-4: the reconcile gate runs observe-only, measuring the unmatched-and-FP rate, before it blocks on >=3 real runs).
  JC-4 HONEST-COVERAGE-SCOPE + PLATFORM-RESIDUE (named, never papered over): the honest claim is "every COVERED effect class left a row," NEVER universal completeness. A privileged host/kernel adversary defeats BOTH logs (the host-trust ceiling — needs Rekor/TPM-IMA anchoring, a rider on I-18/G-8, NOT claimed by completeness alone). The observer leg is LINUX-ONLY (remote-3090-gated, like G-3); the Windows dev box gets a MEDIATION-ONLY fallback (no independent observer there) and must NEVER advertise the cloud observer guarantee on the local lane (CL-4/GD-5). Every completeness claim carries its covered-set + its platform + its host-trust ceiling.
