# D-21: Mode-routing coverage benchmark

Objective: 200 synthetic claims with hand-labeled ground-truth modes
(A/B/C/D/E); evaluate D-10 select_grounding_mode F1 + per-mode confusion
matrix; gate at F1 ≥ 0.85 across 5 modes with no class collapse.
Estimated effort: 1-2 sessions.
Pre-requisites: D-10 (predicate exists).
Parallel-safe with: D-19..D-25.

## Context

D-10 ships the predicate; D-21 measures it. Without quantitative coverage
evidence, the 90% F1 claim in D-10 Cloud test A is anecdotal.

Synthesizing 200 ground-truth claims:
- 40 per mode × 5 modes = 200.
- Each labeled with the canonical expected mode + rationale.
- Coverage scenarios: clearly-Mode-A (compile check), clearly-Mode-D
  (sandbox experiment), clearly-Mode-E (ethical/aesthetic question),
  ambiguous-A-vs-D (math claim that COULD be checker OR experiment), edge
  cases (no alt-family → Refuse instead of FalsifiabilityCrossFamily).

## Tasks

1. **Fixture authoring** at .elai_cc/benchmarks/mode_routing/fixtures/:
   - 200 claim files in JSON: { claim_id, statement, claim_type, domain,
     intrinsic_signals, expected_mode, rationale }.
   - 40 per mode; varied wording; mixed easy + hard.

2. **ModeRoutingBenchmark** in new file
   .elai_cc/crates/orchestrator/src/benchmarks/mode_routing_runner.rs:
   - `struct ModeRoutingBenchmark { fixtures_dir: PathBuf }`
   - `struct ModeRoutingReport { total: u32, correct: u32, per_mode_confusion:
     HashMap<(GroundingMode, GroundingMode), u32>, f1_macro: f32, f1_per_mode:
     HashMap<GroundingMode, f32>, verdict: GatingVerdict }`
   - `fn run(&self) -> ModeRoutingReport`:
     - Load fixtures; for each, build OrchContext mock + call
       select_grounding_mode; compare to expected.
     - Compute F1 macro + per-mode + confusion matrix.

3. **Gate logic**:
   - Pass if: F1 macro ≥ 0.85 AND each mode F1 ≥ 0.70 (no class collapse).
   - FailBelowBaseline otherwise.

4. **CLI subcommand `elai bench mode-routing`**:
   - In .elai_cc/crates/cli/src/bench_mode_routing.rs.

5. **Decision doc** workflow/reasoning/D-21-decisions.md (3 decisions):
    - (a) Why 40 per mode (not 20 or 100): 40 gives reasonable sample noise
      floor (~±5%) while keeping fixture authoring manageable.
    - (b) Why F1 macro 0.85 + per-mode 0.70: macro guards against
      total-system failure; per-mode guards against class collapse.
    - (c) Why hand-labeled (not generated by another LLM): ground truth
      must be human-vetted to avoid circularity.
