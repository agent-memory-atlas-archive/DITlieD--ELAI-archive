# J-43 doctrine_propagation_keystone

- Track J | lever DOCTRINE-PROPAGATION (Track 1, the LENS) | grounding docs/strategy/ELAI-DETERMINISM-DOCTRINE.md (D1-D5) + .claude/rules/maintainability-review.md (precedent template) + wiring-enforcement R8/R9 + the deep-research governance vote (DP design addendum c) | nature BUILD (harness meta-rule + thin floor, maintainability-review-shaped) | effort M | WAVE DPW-1 | depends maintainability-review.md, gate_freeze_check.py, the auditor agent
- The determinism doctrine ("the model is a cog, not a brain") today exists only as a PASSIVE LENS: an 8-question checklist you hand a reviewing model. A passive lens is a soft gate, and a soft gate an agent applies to its OWN work rubber-stamps (D1, Berkeley RDI Apr-2026 in-boundary artifacts gamed ~100%). The doctrine is the GENERAL LAW of which wiring-enforcement, production-caller-gate, maintainability-review, tracing-test-assert, the F-4 cant-lie gate and freeze-the-gate are already SPECIFIC INSTANCES. So propagating it is doing for the whole doctrine what wiring-enforcement did for one sub-doctrine: a thin frozen deterministic FLOOR for the few STRUCTURAL anti-patterns + a cross-family ADVISORY review for the semantic core that has no mechanical oracle + a fail-closed DEBT LEDGER for known gaps. The doctrine's own D3/D5 dictate this shape: a single comprehensive scorer would have to LIE about coverage (D3) or smuggle an LLM verdict onto the gating path (D5) to enforce D1-D5 — self-refuting. This keystone is the meta-rule + the floor; DP-2..DP-5 add the method-track, advisory calibration, measurement, and the program falsifier.

## Integration

It WRAPS, never edits, the existing instance gates (wiring/production-caller/maintainability/tracing-assert stay exactly as they are — the meta-rule names them as instances, it does not re-implement them). It is a HARNESS leg: done-gate is JD-1 (a real audit session ran the floor over a real changeset and produced the off-agent finding rows + a frozen-gate check), not "the file exists in .claude/". Honest residue (DP design section 9 + C1): the semantic core is unmechanized BY DESIGN — the floor catches only the structural tells; a subtle boundary violation (a proxy dressed as an objective, a model judgement laundered through a mechanical-looking wrapper) passes the floor and is DP-3's advisory + DP-4's debt-rate aggregate to catch; Rust static recall is the weakest technical leg.

## Open questions / risks
- doctrine-debt-ledger.toml location: .claude/ (harness-owned, the floor reads it) vs beside .elai_cc/wire-dark-allowlist.toml (the literal "beside" of the design). Lean .claude/ since the floor + auditor are harness-side and the doctrine governs harness features too; re-decide at edit.
- DD-3 SAME-FAMILY-CRITIC detection needs the producer's model family AND the critic's at the dispatch site — recoverable from agent-dispatch metadata, but the family of a model-id is a lookup table that must be maintained (a stale table is a silent miss). Flag as a maintained constant.
- The floor cannot prove DD-4 mechanically (an LLM-verdict-on-gate is a semantic judgement); it stays WARN and leans on DP-3's advisory. Do not promote DD-4 to BLOCK on the floor alone.
- Doctrine-theater: the floor passing does not mean the feature is doctrine-clean (only that the structural tells are absent). DP-4's debt-rate is the aggregate backstop; a subsystem with an implausibly-zero debt rate is itself suspect.
