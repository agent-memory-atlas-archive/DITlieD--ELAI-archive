## Premise

ELAI verifies FIDELITY (did we build what the plan said) but never AIM (was the plan the right thing). The fidelity machinery is SHIPPED and strong: load_phase_context (plan_skeleton.rs:837) keeps the whole skeleton resident in Slot 3, extracts the phase's contracts plus adjacent-phase contracts one hop, and raises a StalenessWarning when a detail file lags the skeleton version — it carries the spec down to every baby step with ZERO drift. The sting: that same machinery faithfully propagates whatever direction it is given, so a mis-aimed idea becomes clean, coherent, fully-wired baby steps that solve the WRONG problem and pass every gate. The forward leg user > elai > model is the thin half: prompt-transform reformats ONE prompt (not a stateful spec), B-40 IdeaFramer is dark-flagged, /grill and /cook are user-invoked-only (never autonomous), and J-32 routes a message to a LANE but does not reconstruct or validate the intent inside it. J-35 builds the intent-control layer the task lane needs: a typed intent spec, a structurally-forced premise-check, an outcome+reversibility route, journaled assumptions, and an inspectable decision-card — composing J-32 (router) + B-40 (framer) + J-31 (card) + the rules-engine (promotion) + the SSB journal (revealed-behaviour defaults), restating none of them.

## Design doctrine (the hard question answered)

"Can ELAI verify it solved the RIGHT problem?" — NO, and that is principled, not a gap to engineer away. Aim is the Validation half (right product) vs Verification (product right); the literature is unanimous that the validation standard is the stakeholder's perceived need — subjective, often tacit, sometimes only knowable post-hoc — so no benchmark measures true-need validation and ELAI must NOT pretend to gate it. J-35 therefore does THREE things and never a fourth:
1. STRUCTURALLY FORCE the cheap surface-and-confirm the model will not volunteer. False-premise correction is suppressed inside a task context (the model knows but does not correct, and the tendency worsens with capability/reasoning-tuning) — so a premise-check that depends on the model spontaneously objecting is fail-open. The check is a separate subpass, not the model being "more careful."
2. BUILD the automatable AIM-ADJACENT FLOOR (premise-check against code/grounding; ambiguity route) and label it FLOOR, never aim.
3. SURFACE the irreducible human residual as an inspectable decision-card (J-31), so a mis-aimed direction is catchable by LOOKING, cheaply — never buried in baby steps.
The fourth thing it must never do: emit an aim-verified verdict. A "goal-alignment" check that actually measures fidelity-to-stated-goal dressed as aim is a fail-open aim gate (wiring R4: measure the objective, not the proxy) — structurally absent here. This is TD-3 on the intake surface: the LLM PROPOSES the spec reconstruction and the candidate premises; deterministic checks + the journal + the user DISPOSE. The reconstruction is non-deterministic in its PROPOSAL and deterministic in its DECISION (route) and recorded.

## Steal/build (6 legs)

1. TYPED INTENT SPEC (not a rewritten prompt). The intent-reconstruction output is a TYPED artifact { goal, constraints, hidden_assumptions, non_goals, validation_contract }, REUSING the shipped BabyStepSpec 8-block + IntentPair + WiringContract shapes (re-grep the runtime types at edit; ship SystemBinding-style new types ONLY if absent). It rewrites the messy multi-turn context into ONE low-entropy spec BEFORE the plan_skeleton factory ever decomposes — memory/RAG does NOT substitute (it raises answerability while MASKING latent goal uncertainty, so the reconstruction runs BEFORE retrieval). The rewrite is SHOWN on the decision-card (leg 5), never hidden — a hidden rewrite can flatten the user's real objective into the system's favourite formulation (the mediator-imposes-framing failure mode).

2. PREMISE-CHECK SUBPASS (separate, format-independent, structurally forced). Before the spec reaches decomposition, a DETERMINISTIC-FIRST subpass extracts the premises embedded in the request and checks each against the DKG / code / grounding methods (phase-2B FILE/SOURCE/TEST/WEB) — NOT conditioned on the user's requested output format (the suppression failure mode is exactly task-framing). The model PROPOSES candidate premises; the CHECK is deterministic (existence + contradiction against the DKG, the runtime analog of /grill's flat contradiction-surfacing). A flagged false premise surfaces on the card and BLOCKS decomposition until confirmed/corrected — it never tunnels silently into execution. This is the aim-adjacent Layer-2 floor; composes B-40's critic categories.

3. OUTCOME + REVERSIBILITY ROUTE (ask / proceed-under-logged-assumptions / refuse). The route is a DETERMINISTIC decision over { J-32 confidence + AmbiguityScorer, premise-flag, reversibility/cost class, GateMode (interactive/autonomous), Phase-3A RiskLevel }. ASK ONLY when a question is expected to improve execution AND the action is costly/irreversible — never on every ambiguity (over-asking has a non-monotonic tax; naive "just ask" degrades outcomes). Interactive: high-ambiguity + costly -> the J-32 CLARIFY chip; else proceed under logged assumptions. Composes J-32 router + D-16 conformal tau (route threshold graduates from the chip tuples) + B-22 GateMode + RiskLevel.

4. AUTONOMOUS DEFAULT FROM REVEALED BEHAVIOUR (never a majority prior) + JOURNALED ASSUMPTIONS. With no user present, the default for an ambiguous fork is sourced from the SSB OUTCOME JOURNAL (the user's revealed behaviour on past similar forks), NOT a population/majority prior (LLM agents are hypersensitive to nudges; a hidden default steers harder than it would a human, and a majority prior mis-specifies the user more cleanly than the raw model). Where the journal has no signal: the minimally-presumptive REVERSIBLE action + a logged assumption; HIGH/irreversible still escalates via the shipped TreeAutoAdvancePolicy.high_risk_pauses. Every injected assumption is an AssumptionLogged journal row the user audits/overrides after the fact — the verbalize-assumptions pattern as the autonomous safety net and the interactive alternative to asking.

5. INSPECTABLE DECISION-CARD (the aim-visibility surface, via J-31). The card = { reconstructed goal, chosen route/lane, injected assumptions, flagged premises, reversibility class, intervention handle } — a DECISION SURFACE, not raw reasoning (overseers miss buried mistakes in long traces; expose the goal/assumptions/forks, not the chain-of-thought). It rides J-31 canvas-system-mode (the direction made inspectable + evidence-bound) and the J-32 ACK/RESULT cards. A mis-aimed direction is caught by reading the card BEFORE the FSM decomposes, the cheapest place to kill a wrong direction.

6. SELF-IMPROVEMENT OF THE LAYER (compose the SHIPPED rules-engine; build NO new mechanism). The premise-check ruleset and the accumulated aim-pattern / anti-pattern library are DATA in the shipped rules-engine SQLite (phase-3F); candidates are learned from SSB OUTCOMES and promoted to load-bearing ONLY through SHADOW -> ACTIVE (fpr<5% + tpr>80% + causal>50%) — CURATION OVER ACCUMULATION (unvalidated self-generated patterns are net-negative; sparse beats bloated). The library compounds aim-patterns on the user's RECURRING task families (NOT "best at anything" — unsupported), kept sparse + garbage-collected. ELAI already owns the rarest piece self-improvement needs: a validator OUTSIDE the artifact (the held-out + rules-engine gate) — which is precisely what makes this safe rather than degrading, so J-35 reuses it, never re-authors a self-improvement engine.

## observable_effect (done-gate, W-1)

A task message carrying an embedded false premise ("speed up the synchronous sync loop in foo.rs" where the DKG shows foo.rs's loop is already async) -> a PremiseFlagged row naming the premise + the DKG contradiction, surfaced on the decision-card, and decomposition does NOT proceed until the user confirms or corrects (in OBSERVE-ONLY Tier-1: the flag + a non-blocking notice, then blocking after the >=3-run FP bound). An ambiguous-but-reversible-and-cheap task in autonomous mode -> RouteDecided(proceed) + AssumptionLogged rows whose default is sourced from a prior journal outcome (NOT a population prior), recomputable from the journal (GD-2), and auditable after. An ambiguous + HIGH/irreversible task in autonomous mode -> still escalates (shipped high_risk_pauses), RouteDecided(escalate). The reconstructed spec is SHOWN on the card (Tier-2 J-31), never hidden.
NEGATIVE (R2): the flag off -> today's straight-to-decomposition behaviour, loudly surfaced (R1 fail-closed, never a silent pseudo-check); a premise-check arm that conditions on the user's requested output format FAILS the contract test (it must run format-independent — the whole point); an autonomous default sourced from a majority/population prior instead of the journal FAILS the contract test; an arm that emits an "aim-verified" / "right-problem-confirmed" verdict FAILS (the Layer-4 conflation is banned — the layer surfaces aim, never gates it); a rewrite that silently replaces the user's literal goal without the card showing it FAILS (the rewrite must be shown).
