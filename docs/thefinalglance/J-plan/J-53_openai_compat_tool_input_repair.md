## Steal/build (3 legs, mirrors the J-51 seam->surface->consume shape)

1. REPAIR SHIM at the seam (`crates/providers/src/tool_input_repair.rs`, NEW ~180 LOC). `repair_tool_input(tool_name, raw_args, input_schema) -> RepairOutcome`. Validate-then-repair, NEVER preprocess-then-validate (the post's load-bearing inversion — a greedy preprocess corrupts valid-but-unusual content, e.g. a writeFile body that is itself JSON-shaped). Order: (a) parse as-is; if it parses AND structurally matches the tool's declared `input_schema` types, ship UNTOUCHED (valid inputs are never rewritten). (b) On parse/shape failure, walk the schema's declared type at each failing field and apply the four ordered open-model repairs — json-array-parse (a `"[\"a\",\"b\"]"` string where an array is declared) BEFORE bare-string-wrap (`"foo"` -> `["foo"]` where an array is declared), single-arg-`{}`-unwrap (a placeholder object where an array is declared), and null-of-optional DROP (omit, never send `null`) — the ORDER is load-bearing (bare-string-wrap before array-parse double-wraps `'["a","b"]'` into `['["a","b"]']`). (c) typed-path unwrap: for `input_schema` fields tagged path-typed, strip the degenerate markdown auto-link `[text](url)` ONLY where link-text == url-without-protocol (the chat-distribution leak; real links `[click](https://x.com)` pass through). (d) re-validate. RepairOutcome = ShipUnchanged | Repaired{kinds} | Unrepairable{model_readable_msg}. NO new dependency: a minimal structural type-matcher against the declared `input_schema` "type" (the four shapes are detectable structurally — declared-array-got-string/object/scalar, declared-object-got-string); the full `jsonschema` crate is a DEFERRED option flagged for explicit user confirmation (no-new-dep HARD RULE). No `.unwrap()`; no blake2/sha2.
2. WIRE the shim + kill the silent blob (`openai_compat.rs` MODIFY ~40 LOC). `parse_tool_arguments` gains the tool's `input_schema` (thread a `name -> input_schema` map onto the client from the request `tools` it already sends; the response tool_call carries only `name`+`arguments` today, :813). Replace the `{"raw": arguments}` fallback: ShipUnchanged/Repaired -> the corrected `Value`; Unrepairable -> a MODEL-READABLE `tool_input_invalid` value (the structured "what was wrong" message, NOT a raw serde error, NOT a silent `{"raw"}` blob) that rides E-18's one-shot-retry/fixer path as the fallback AFTER deterministic repair. UPDATE the test at :1096 — it currently pins the anti-pattern; it must instead assert the four shapes repair and that an unrepairable arg surfaces the readable error (this is the contract this plan intentionally changes, not gate-gaming). Relational-invariant default (the offset/limit class) lands at the TOOL DISPATCHER, not the parser (per-tool semantics, the post put it in the function): `limit` alone -> `offset=0`, `offset` alone -> `limit=<tool default>`, and SURFACE the chosen default back in the ToolResult with NO `Error:` prefix so the model self-corrects next turn.
3. TELEMETRY feeding the J-51 family (`+ToolInputRepaired` SSB). Every non-ShipUnchanged outcome emits a journal row carrying provider+model+tool+repair-kind. Repair-RATE per (provider, model, tool) is the sibling FORMAT signal to J-51's SEMANTIC adherence — high repair-rate = low FORMAT adherence on a cloud lane that can't be masked — so the rate lands on the SAME ModelCapabilityProfile / failure-taxonomy family J-51 consumes (self_mod_proposal.rs already auto-grows `failure_taxonomy` from misses), WITHOUT merging the two metrics (format-repair-rate != semantic-adherence). Default-ON kill-switch `ELAI_TOOLCALL_REPAIR_DISABLE` (W-2, NOT a new ENABLE); disabled -> the legacy passthrough, logged, never a silent flip.
