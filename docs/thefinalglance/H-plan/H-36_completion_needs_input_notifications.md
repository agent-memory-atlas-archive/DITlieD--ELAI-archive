# H-36 -- completion / needs-input dev-event notifications

- Track 4 (UX + USER-MEMORY) | lever STEERING | grounding MODERATE | nature BUILD | effort S | WAVE 4 | depends H-35
- Premise: a developer who fires a long autonomous ELAI run walks away from the terminal; today nothing tells them when the run FINISHED or when it is BLOCKED waiting for a human decision. The terminal foreground is silent, the dashboard toast only fires if a browser tab happens to be focused, and the intervention path is an explicit no-op (NotificationManager.svelte:114-118, B-36 gap). The #1-cited missing QOL in terminal coding agents is "tell me when you're done or stuck." This ships a terminal BEL/OSC9 escape + an OS notification driven FROM a real SSB row (not stdout), firing on BOTH task-completion and needs-input, with an `agent_notification_emitted` SSB row as the off-agent artifact.

## Steal/build
BUILD (nature=BUILD, not ACTIVATION): the producer side does not exist. The FSM transition machinery, the AutonomyDecision::RequestHuman signal, the PhaseComplete terminal row, the SSB write_loop, and the dashboard NotificationManager poll ALL exist and are PROD-WIRED, but no code converts a completion/needs-input event into a terminal escape sequence or an OS-level notification, and there is no SSB action_type that records "a notification was emitted." We BUILD a thin notifier that subscribes to the two terminal signals already on the SSB journal and emits (a) a terminal escape + (b) an OS notification + (c) the recording SSB row. We REUSE the existing emission sites as triggers rather than inventing a new event stream.

Prior art (codeagentswarm notifications guide; developer terminal-agent discourse 2026): the canonical pattern is an OSC 9 desktop-notification escape (iTerm2/WezTerm/Kitty/Ghostty) with a BEL (`\x07`) urgency fallback for terminals that ignore OSC 9, plus a native OS notification API call (`notify-send` on Linux, `osascript -e display notification` on macOS, `powershell` toast / `BurntToast`-equivalent on Windows) for when the terminal is unfocused. The escape is the cheap always-fires leg; the OS notification is the focus-independent backstop. We REIMPLEMENT this dispatch matrix in Rust; no Python port.

REJECT (personal_agent_risk: companion drift): no engagement framing, no "vacation mode," no learned per-user notification threshold, no quiet-hours preference store, no notification-frequency adaptation. Those all require a durable per-user preference store and bias the system toward an attention-seeking persona -- exactly the personal-agent drift the H-plan doctrine forbids (NOT-A-PERSONAL-AGENT). This is a DECLARATIVE DEV-EVENT alert ONLY: a finite, code-defined set of two events (task done, needs human input) fires a fixed notification. The only user control is a single binary opt-out env gate (no thresholds, no schedules, no learning).

## WIRING_CONTRACT
- produces: `agent_notification_emitted` SSB row (action_type, Pattern-2 single-variant, schema 221); a terminal escape sequence on stdout when TTY; an OS-notification process spawn when ELAI_NOTIFY_ENABLE=1.
- consumes: the EXISTING terminal triggers it did NOT author -- the PhaseComplete row (task_runner.rs:9610) via the dispatch_stop hook (hook_dispatcher.rs:1146), and the AutonomyDecision::RequestHuman GateDecision (task_runner.rs:1157-1162). Dashboard consumes the produced `agent_notification_emitted` rows.
- reachable_from: a REAL entrypoint -- `elai run` driving a task to terminal completion reaches NotificationDispatcher::notify via InProcessHookDispatcher::dispatch_stop (hook_dispatcher.rs:1146); a fix_and_rerun-cap exhaustion during `elai run` reaches it via task_runner.rs:1162. NOT a test shim calling notify() directly.
- stub_ban: no `todo!()`, no empty platform arm, no `let _ = notify(...)` drop, no silent `.ok()` that swallows the SSB write error (mirror hook_dispatcher.rs:1302-1306 warn-on-failure). The os-notification Command spawn MAY fail (binary absent) -- that is a recorded surfaces_succeeded bit-clear, NOT a swallowed error.
- observable_effect (W-1 done-gate): a long `elai run` finishing (or hitting the fix_and_rerun cap = needs-input) emits an `agent_notification_emitted` SSB row that the agent authoring this feature did not write -- the row is written by the live notifier reached from the real production stop-hook / RequestHuman path, recording event_kind and the surfaces bitset. The done-gate is `wiring_contract_check --run-trigger PASS`: drive `elai run` to completion (and a separate run to the fix-cap), then query the SSB journal for the two `agent_notification_emitted` rows in the run window. Missing rows = FAIL (R1). cargo-green alone is NOT the gate.
