# H-51 -- cross-session sleep-time handoff: grounded topic-digest + auto-detect + tiered load
- Track 9 (CONTEXT LIFECYCLE) | lever CHEAPER/STEERING | grounding STRONG | nature BUILD-on-shipped (wire the user's handoff-protocol.md rule into the runtime + a sleep-time digest over the SSB journal) | effort M | WAVE 9 | depends H-50 (the in-session base + selective recover_stubs), H-6 (recover_stubs read-back); composes H-35 (/rewind, SessionDag), .claude/rules/handoff-protocol.md (the live rule)
- Premise: today ELAI's cross-session resume is MANUAL (/continue) AND it reloads the packed TRIMMED TRANSCRIPT -- on a local 25-32K model that is ~20-27K tokens landing before any work starts (it packs to the budget, it does not hand you a small digest). That is the exact context-pollution the user wants gone. Meanwhile the user's just-shipped handoff-protocol.md rule produces the RIGHT artifact -- a ~40-100-line, topic-keyed, curated SEMANTIC digest -- but only as a prose rule the main LLM follows by hand, unwired to the SessionDag/SSB runtime. H-51 makes cross-session continuation token-cheap and SEMI-automatic: a sleep-time pass auto-AUTHORS a grounded topic-digest from the journal, a fresh session auto-DETECTS an open one and OFFERS to resume (one-tap confirm, NOT blind auto-continue), and the resume loads the ~1-3K digest by default with the raw transcript lazy on demand. Full rationale: docs/thefinalglance/CONTEXT-LIFECYCLE-REGIME-AWARE-AND-HANDOFF-DESIGN-2026-06-05.md.

## Steal/build
Prior art (WebSearch-verified 2026-06-05): Letta sleep-time compute (letta.com/blog/sleep-time-compute) -- a "sleep agent" consolidates past conversations OFFLINE into "learned context"; same accuracy at 11K vs 20K tokens, ~5x lower test-time compute. Do the digest-authoring offline/at-idle, not in the user's latency window. Mem0 (arXiv:2504.19413) -- lazy salient-fact retrieval; >90% token savings vs full-context, +26% over OpenAI memory on LOCOMO. Load the digest, not the transcript; pull detail on demand. A-MEM (arXiv:2502.12110, NeurIPS 2025) -- Zettelkasten dynamic note linking (mirrors ELAI's own [[name]] memory links). Anthropic context engineering -- structured note-taking as external memory. Benchmarks: LongMemEval / LoCoMo / MemoryAgentBench (the measurable done-gate).
Reuse-from-shipped (GD-1): compact_session is the digest engine; the SSB journal is the off-agent ground truth (intervention rows = decisions, FileWrite rows = files); SessionDag is the topic/tip store; H-50's selective recover_stubs is the lazy detail-loader; the user's handoff-protocol.md is the digest TEMPLATE + trigger semantics. H-51 wires these together; it does not author a new memory store.

## REVISED scope (W-10 tiered)
SHIP NOW (Tier-1, vertical slice):
- SLEEP-TIME AUTHOR: at session end / idle, a sleep-agent pass authors/updates a TOPIC-keyed digest (stable slug = the problem, NOT session-id) from the SSB journal via compact_session: SUMMARY + DECISIONS (from intervention rows) + FILES (from FileWrite rows) + the FSM/plan cursor + open follow-ups, ~1-3K tokens. Append-if-exists-else-create with two living fields (CURRENT STATUS + INDEX) overwritten in place -- exactly the user's handoff-protocol.md, auto-generated and GROUNDED in the journal (not the LLM's recollection). The main LLM never hand-writes it; a `HandoffLifecycleEvent kind=DigestWritten` row is the off-agent proof.
- AUTO-DETECT + ONE-TAP CONFIRM: a fresh REPL checks for {open topic-handoff + non-IDLE FSM + active DAG tip} keyed on cwd/project; if found, surface ONE line ("prior session on <topic> at <FSM state>, N open follow-ups -- resume? [y/N]"). Detection automatic; continuation confirmed. Ambiguous -> list open topics. Emits `kind=ResumeOffered` then `kind=ResumeConfirmed`.
- TIERED LOAD: on confirm, load ONLY the ~1-3K digest into context by default; the full trimmed transcript + tool-result stubs stay in SSB, lazy-pulled via H-50's SELECTIVE recover_stubs ONLY when the model asks ("show me what we did on X"). Emits `kind=TieredLoad` with the measured loaded-token count. Default local resume cost drops ~20-27K -> ~1-3K.
- Cloud-cache safety (HD-2): the digest injects AFTER the cache breakpoint (or as part of the stable prefix) so on cloud it never busts the cached prefix.
DEFER (Tier-2): multi-topic merge-on-resume; digest-diff preview; auto-author on the 85% within-session handoff (not just session-end); cross-project handoff suggestions.

## WIRING_CONTRACT
- produces: `HandoffLifecycleEvent` rows (DigestWritten at session end; ResumeOffered + ResumeConfirmed + TieredLoad on resume); the topic-keyed digest file at workflow/handoffs/{slug}.md (grounded from the journal).
- consumes: `ssb::query_session_stream_asc` (ssb.rs:15353), `session_dag::{load_handoff (1682), recover_stubs (1507, selective via H-50)}`, the SSB intervention + FileWrite rows, .claude/rules/handoff-protocol.md (template/trigger). NOTE: `compact::compact_session` (compact.rs:96) was listed here but is NOT called by the shipped impl; the digest is purpose-built via `build_digest_body` (a ~1-3K topic summary, not turn-compaction). The hand-rolled path is the correct design for the tiered-digest target size; bolting on compact_session would overshoot the token budget. Declaration updated to match shipped reality.
- reachable_from: REAL entrypoints = the session-end / idle hook (DigestWritten), the fresh-REPL startup path `main.rs:712` (ResumeOffered), the `/continue`-or-confirm dispatch (ResumeConfirmed + TieredLoad). NONE a test shim (R3/R7).
- stub_ban: the digest DECISIONS MUST be extracted from SSB intervention rows + FILES from FileWrite rows -- a digest authored from the LLM's recollection (no journal grounding) is a FAIL; fail-closed if the journal row is gone. TieredLoad MUST load the digest (~1-3K), NOT the packed transcript -- a resume that loads >5K by default = FAIL. recover_stubs MUST be selective (lazy), not a whole-set re-inflate. No `.unwrap()` in the dispatcher.
- observable_effect (W-1 done-gate, LIVE trigger + off-agent artifact; missing = FAIL per R1/R2): end a real seeded session on topic T -> a `DigestWritten` row + a workflow/handoffs/{T}.md whose DECISIONS/FILES match the journal's intervention/FileWrite rows (off-agent). Then a FRESH `elai` in the same project auto-surfaces the resume offer (`ResumeOffered` row); on confirm, a `TieredLoad` row records loaded_tokens <= ~3K (NOT the ~20-27K transcript) and the model can still pull an early detail via selective recover_stubs. A no-open-session start surfaces NO offer and emits NO rows (the smoke manifest distinguishes no-op from a dead path). GD-2: the resume token cost is recomputable from the journal under ELAI_SEED.
