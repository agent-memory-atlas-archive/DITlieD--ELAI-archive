# H-34 -- MCP defer-loading + Tool-Search emulation for the live STDIO MCP servers
- Track 4 (UX + USER-MEMORY) | lever CHEAPER | grounding STRONG | nature BUILD | effort M | WAVE 4 | depends none (composes C-35 lazy cache + H-4 catalog-shaper but is distinct from both)
- Premise: the live MCP-server lane (local-rag / pod-lifecycle / notion, reached via the STDIO `McpServerManager`) discovers EVERY server tool's full `inputSchema` at startup and the runtime carries them verbatim. On the ~25-32K local Qwen2.5-Coder window that per-turn schema mass is the single largest fixed tax before any task content lands. H-34 FIRST measures the per-turn MCP-schema token baseline, THEN defer-loads: only a small always-available floor + RAG-selected tools carry full schemas per turn; the rest resolve their schema on demand the first time the model names them. The reduction is a MEASURED delta recomputable from the SSB journal, never a literature figure.
