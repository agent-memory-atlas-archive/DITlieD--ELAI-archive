# H-35 -- /rewind over the SSB journal
- Track 4 (UX + USER-MEMORY) | lever STEERING | grounding STRONG | nature BUILD-UI-over-journal | effort M | WAVE 4 | depends H-33 (window-budget governance), composes G-2 (RRA)
- Premise: a user mid-session wants to undo back to a known-good point (a bad edit, a wrong turn, an over-eager refactor) WITHOUT losing the audit trail. The user-need is "take me back to before that," scoped to conversation-only / code-only / both, plus "summarize-from-here" to free the window. ELAI already has the strongest possible substrate for this -- a seeded, append-only, byte-replayable SSB journal -- so /rewind is a UI + restore-path BUILD over an existing journal, never a new checkpoint store and never a shadow-git.

## Steal/build
Claude Code's checkpointing/rewind is the MEASURED most-loved agentic-coding feature (46% of surveyed users name it, vs Cursor's 19% equivalent; Pragmatic Engineer 2026 dev-tooling survey, dated snapshot 2026-06-04). What is worth STEALING is the user-facing affordance and the conversation/code/both scoping, NOT its implementation: Claude Code uses an out-of-band local checkpoint store. ELAI must BUILD the affordance over its OWN substrate, which is strictly stronger because it REPLAYS deterministically under ELAI_SEED rather than snapshotting blobs.
Reimplement-from-MIT prior art (odysseus, reference only -- never port Python):
- The "summarize-from-here" trim is the odysseus context-trim semantic: `docs/.source/odysseus-main/src/context_compactor.py:174 trim_for_context(messages, context_length, reserve_tokens=512)` (drop oldest while reserving fixed headroom) and `:263 maybe_compact`. ELAI analog already exists as `crate::compact::compact_session` (see ground truth) -- /rewind's summarize mode CONSUMES it, it does not reimplement it.
- The order-independent short-circuit fingerprint (skip redundant work when nothing changed) -- `memory_extractor.py:32 _fingerprint_entries` (sorted, hash over id+text+category) -- is the pattern for the rewind's idempotence guard: a /rewind to a target seq that equals the current head is a NO-OP that emits no row. Reimplement with blake3 (Anti-Stale rule, NOT odysseus's hashlib) over the (seq, action_type, event_blake3) triple of the truncated stream tail.
BUILD (genuinely new, no prior caller): the `/rewind <n>` CLI subcommand, the dashboard rewind control, the `session_rewound` SSB beacon, and the restore dispatcher that maps a rewind-target seq onto the existing replay-resume + recover_stubs paths.

## REVISED scope (W-10 tiered)
SHIP NOW (Tier-1, the vertical slice):
- `elai rewind <target> [--scope conversation|code|both] [--summarize]` CLI subcommand. `<target>` is an SSB seq (default) or `--turn <n>` (the n-th user turn, resolved to its seq via the ASC stream) or `--checkpoint <label>` (a prior RRA seal point). Read the session stream via `query_session_stream_asc`, locate the target seq, then dispatch by scope:
  - conversation: trim the message stream past target (drop turns after it), folding the tail into a summary via `compact_session` when `--summarize` is set; rehydrate any stubs at/before target via `recover_stubs`.
  - code: mint a `ReplaySessionId::derive` from the target checkpoint + an empty patch and run the replay-resume restore through `ssb_resume_from` (fail-closed against LockedKeysAuditor) to reconstruct the file state at that seq.
  - both: conversation trim THEN code restore, in that order.
- One `session_rewound` SSB beacon per successful rewind (the off-agent done-gate artifact; see WIRING_CONTRACT). Pattern-2 single-variant convention.
- Idempotence guard: a rewind whose target seq == current head is a NO-OP that emits NO row (blake3 fingerprint of the truncated tail equals empty). Prevents a graveyard of no-op rows.
- Dashboard rewind control on CommandWindow.svelte (a "Rewind to here" affordance on each transcript turn) wired to a new Tauri command `rewind_session(session_id, target_seq, scope, summarize)` that drives the same restore dispatcher and emits the same beacon.
DEFER (Tier-2, follow-on H-plan): branch-and-fork (keep both timelines), multi-checkpoint diff preview, code-restore for cloud-model runs where the RRA guarantee_level is VerifyDivergence (the model fingerprint is opaque -- restore is best-effort, flagged, not proven). Local-token discipline: /rewind injects NOTHING into the prompt by default; the summarize mode is the only window-affecting path and it SHRINKS the window. Staleness: not applicable -- the journal is append-only and the rewind is a pointer-move, so there are no superseded rows to narrate; history before the target stays intact and queryable.

## WIRING_CONTRACT
- produces: SSB row `session_rewound` (action_type tag `session_rewound`, payload `SessionRewoundPayload`); on `--scope code|both`, transitively one `agentic_observability_event` kind=`replay_resume` row from the consumed `ssb_resume_from`.
- consumes: `ssb::query_session_stream_asc` (ssb.rs:15353), `compact::compact_session` (compact.rs:96), `session_dag::recover_stubs` (session_dag.rs:1507), `observability::replay::{ReplaySessionId::derive (replay.rs:84), ssb_resume_from, ReplayOutcome (replay.rs:99)}`.
- reachable_from: REAL entrypoint = the CLI subcommand dispatch `main.rs CliAction::Rewind -> rewind_cmd::run_rewind` (the `elai rewind <n>` invocation), AND the Tauri command `rewind_session` invoked from CommandWindow.svelte. NEITHER is a test shim. The done-gate drives `elai rewind <target> --scope both` against a seeded fixture session.
- stub_ban: no `todo!()` / placeholder restore; the code-restore arm MUST actually call `ssb_resume_from` and propagate its `ReplayOutcome` (Refused/PredicateUnavailable/Accepted) into the beacon -- a hardcoded `Accepted` is a FAIL. No `.unwrap()` in the dispatcher (Result propagation; CLI driver/main entrypoint may `?`).
- observable_effect (W-1 done-gate, MUST be a live end-to-end trigger leaving an off-agent artifact): running `elai rewind <seq> --scope both` against a seeded SSB fixture under a fixed `ELAI_SEED` (a) lands exactly one `session_rewound` row in the journal that the executing agent did not author, with `target_seq` and `head_seq_before` matching the trigger, AND (b) the restored state replays byte-identically -- re-`build_rra` over the post-rewind stream and `verify_rra` returns `Verified` (the RRA root recomputes). `wiring_contract_check --run-trigger` PASS requires the row to be present AND the verify to be Verified; missing row or non-Verified verdict = FAIL (R1/R2). A no-op rewind (target==head) correctly produces ZERO rows -- the smoke manifest distinguishes the no-op case from a dead path.
