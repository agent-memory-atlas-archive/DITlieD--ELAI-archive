# H-52 — deterministic snippet->hunk finding-anchoring + line-less finding schema (the reviewer cockpit's missing primitive; stolen from alibaba/open-code-review)
- Track 10 (REVIEW-ANCHORING) | lever VERIFIED-BEFORE-SEEN | grounding STRONG | nature BUILD | effort M | WAVE 10 | depends G-5 (the cockpit consumer + the DSR denominator), C-7 (the hunk_id space); composes E-41 (the PR-reviewer comment-anchoring consumer — its GitHub leg DEFERRED to a follow-on once C-40/E-41 ship), F-4 (a vouch to anchor)
- Premise: G-5's reviewer cockpit attaches a per-hunk vouch (an F-4 stdout_hash-bound passing test, an F-1/F-2a write-gate CWE verdict, a grounding-sweep citation) and computes DSR = (lines needing attention) / (total changed). But the JOIN from a vouch — or from a reviewer FINDING — to a SPECIFIC hunk is the cockpit's load-bearing weak point: G-5's OWN Open-Question #2 names it verbatim ("confirm the FileWrite diff and the TestOutcome/gate rows can be joined to the SAME hunk_id, or vouching attaches at the WRONG GRANULARITY — file-level fallback when hunk_id is None"). Trusting a MODEL-emitted line number to do that join is exactly the failure mode that makes naive LLM review 0-30% signal (G-5's own arXiv:2604.03196). H-52 ports the one primitive that closes it: alibaba/open-code-review's DETERMINISTIC snippet->hunk resolver — the model emits a VERBATIM code snippet and NEVER a line number; deterministic code computes the hunk/line; an unresolvable or ambiguous snippet returns 0,0 = "do not render inline, fall back to file-level." This is the off-agent-artifact doctrine pushed down into the review-finding SCHEMA: the model is STRUCTURALLY UNABLE to assert the load-bearing fact (where the finding lands), so it cannot fabricate it.

## Steal/build
Prior art (source-grounded 2026-06-05 against the CLONED repo docs/.source/open-code-review/, Apache-2.0; the algorithm is worth stealing, the marketing is not):
- THE ANCHORING RESOLVER (the steal): `internal/diff/resolver.go` + `internal/diff/hunk.go`. The review tool's `code_comment` schema (`toolsconfig/tools.json:33`) carries `content` + `existing_code` (+ optional `suggestion_code`) and NO line-number field; the model is told `existing_code` must match the diff verbatim. Resolution: `normalizeLine` strips whitespace + leading `+`/`-`; `resolveFromHunk` parses `^@@ -a,b +c,d @@` headers (`hunk.go`) and matches a consecutive normalized line-run against the NEW side (new-file line numbers) then the OLD side; `resolveFromFileContent` falls back to scanning the whole new-file content; on total miss, `relocation.go:19-69 ReLocateComment` makes ONE LLM call to regenerate the snippet verbatim and retries. A `0,0` result = positioning failed -> the CI action posts the finding as a SUMMARY, not an inline line.
- THE LINE-LESS SCHEMA (the schema steal): because `code_comment` has no line field, a hallucinated line number is STRUCTURALLY impossible — the deterministic resolver owns the line. ELAI's reviewer-finding schema must do the same: carry `{snippet, claimed_vouch_handle}`, NEVER a model-asserted line or a bare verdict.
- TYPED EXCLUDE-REASONS + SKIP-NOT-TRUNCATE (the denominator-integrity steal): `internal/preview.go whyExcluded` returns a typed `ExcludeReason` (binary | user_exclude | unsupported_ext | default_path | deleted) and `filterLargeDiffs` reports an oversize file as SKIPPED, never silently truncated — so the DSR changed-line denominator stays explainable and ungameable.
- SKEPTICAL CAVEATS (port WITH fixes, not verbatim): `matchConsecutive` is literal-equality-after-normalization -> it MISSES on paraphrase/reflow and pays an LLM round; first-occurrence-wins -> it MIS-ANCHORS a duplicate line-run with no hunk-locality tiebreak. H-52 adds (a) a duplicate-snippet -> `Ambiguous` guard (>1 normalized match in scope -> never guess, return file-fallback) and (b) a hunk-proximity tiebreak (prefer the match inside the hunk the finding's file-write touched). REUSE ELAI's existing diff parser for hunk parsing instead of their regex `hunk.go` (GD-1; do NOT re-author a diff parser ELAI already has — confirm the symbol at authoring per W-7).
- EXCLUDED as VAPORWARE (grep-verified ABSENT from the open-code-review Go source — see docs/.source/open-code-review/_SUMMARY.md): "smart file bundling" and a "reflection module" are README marketing with no implementation; do NOT cite them as prior art, do NOT plan against them. The only real second accuracy module is RE-LOCATION (the Tier-2 LLM retry), DEFERRED here.
