# H-49 -- reversible LLM edits: undo / redo / branching file time-travel + lossless session history
- Track 8 (REVERSIBILITY / TIME-TRAVEL) | lever STEERING/TRUST | grounding STRONG | nature BUILD-on-shipped (CAS object store over E-25 edit_checkpoints + an undo-tree HEAD over the SessionDag) | effort L | WAVE 8 | depends H-35 (/rewind affordance + SessionRewound beacon), E-25 (edit_checkpoints snapshot/restore engine), H-6 (recover_stubs activation); composes G-2 (RRA), E-29 (transcript), C-23 (BranchTree UI), E-44 (saga compensation)
- Premise: every change the LLM makes to a file must be reversible AND re-appliable (redo) at ANY point, and undoing must never destroy a timeline. The user-need: "back up every file the LLM touches, undo any change at any moment, and if i undo then change my mind, redo it forward -- and never let a big session hide its own start." This is EXACTLY the follow-on H-35 explicitly DEFERS (H-35:32 "DEFER ... branch-and-fork (keep both timelines), multi-checkpoint diff preview, code-restore for cloud-model runs"). H-35 shipped the conversation/code/both rewind affordance over the journal; H-49 adds (a) a content-addressed per-edit file store so backing up EVERY edit is cheap enough to be default-ON, (b) redo + branch-on-divergence via an undo-tree HEAD over the existing SessionDag (the model that "never loses history"), and (c) a lossless, paged transcript so the first message of an arbitrarily long session is always reachable. Snapshot-restore (not deterministic replay) is the LOAD-BEARING file mechanism because it is model-agnostic and works on the production CLOUD lane, where H-35's replay path is only VerifyDivergence/best-effort (H-35:32). Full design rationale: docs/thefinalglance/UNDO-REDO-TIMETRAVEL-DESIGN-2026-06-05.md.

## Steal/build
Prior art (WebSearch-verified 2026-06-05; the affordance is worth stealing, the implementation is not):
- Cursor checkpoints: zip the pre-change state before every agent edit, local hidden store separate from git, per-message restore, "continue from a reverted state by writing a new message." KNOWN FOOTGUN to avoid: it tracks ONLY agent edits, so a user's manual edits get clobbered on restore (cursor.com/docs/agent/chat/checkpoints). RV-1 is the fix.
- Cline/Roo checkpoints: a SHADOW git repo (core.worktree -> project, snapshot = add+commit, restore = clean + reset --hard) and a separate "Restore Files Only" vs conversation restore. KNOWN FAILURE: checkpointing is silently DISABLED when the workspace is not a git repo (Roo-Code #8164) and nested-git data-loss (Roo-Code #7765). This is why ELAI's OWN content-addressed store is the default engine and shadow-git is only an optional backend (docs.cline.bot/features/checkpoints).
- Aider: a git commit per edit + `/undo`; crucially it COMMITS the user's pre-existing uncommitted work FIRST so it is never lost (aider.chat/docs/git.html). That guard = RV-1.
- Vim 7 / Emacs undo-tree: undo history as a branching TREE, not a linear stack, so undo-then-edit branches and nothing is ever lost; persistent-to-disk variants survive a restart (dr-qubit.org/undo-tree.html, github.com/mbbill/undotree). This is the data model H-49 puts over the SessionDag.
Reimplement-from-shipped (do NOT build a new store): the byte-exact snapshot/restore engine ALREADY exists and passes a test -- H-49 wraps it in a content-addressed layer and a HEAD, it does not re-author it (GD-1).

## J-15 AMENDMENT — event_id-anchored forks + mutate-then-replay rider + DO-NOT-COPY auth storage (source-cited)
Grounding: determinism triage ledger item 6
(workflow/reasoning/steal-determinism-repos-2026-06-11.md); AnshKanyadi/culpa fork-point finding
(agent det-repos-H2/H3 verdicts); llm_recorder mutate-then-replay footnote rider; J-14
repro-pack fixture format (the `rra export-fixture` spec + auth-scrub counter-design).

### (a) Fork points key on stable event_ids, NEVER positions
H-49's undo-tree fork points MUST key on stable SSB event ids (the `seq` or
`event_id` column), NEVER on positional indices (row N in the journal). The culpa
finding: positional fork anchors do NOT survive replay reordering. If the SSB
journal is replayed with a different scan order (e.g., a filtered replay, a
compaction-then-reconstruct, or a cross-session merge), position N points at a
different event and the fork silently lands on the wrong node. Event ids are
content-stable across replay; positions are not. The `EditHistoryEvent` payload
already carries `node_id`/`parent_id` — these MUST be event-id-derived, not
position-derived. The `head` pointer on the snapshot node references an event id,
not a row offset.

### (b) Mutate-then-replay as an adversarial-testing rider
Add a mutate-then-replay affordance as an adversarial-testing rider on the
existing replay path (NOT a new production feature — a testing tool). The
mechanic: take a recorded RRA, modify ONE recorded response (swap a tool output,
inject a malformed response, change a model completion), then replay downstream
from that point. This tests the undo-tree's divergence guard (RV-1) and the
fork-capture path under controlled perturbation. Pairs with J-14's fixture
format: the mutated fixture is a J-14 `rra export-fixture` with one row replaced;
the replay engine consumes it via the same content-hash-keyed fixture contract
(see I-49 J-15 amendment). The mutate-then-replay path is LLM-free (deterministic
fixture substitution + deterministic replay); it is an auditor tool, not an
executor tool.

### DO-NOT-COPY — verbatim auth-header storage (culpa)
culpa stores auth headers verbatim in session JSON. H-49's CAS store and
EditHistoryEvent payload MUST NOT carry auth headers, credentials, or secrets.
The `file_manifest` carries file paths + blake3 hashes; the `EditHistoryEvent`
carries node ids + hashes + paths. J-14's `rra export-fixture` scrubs auth before
archive — H-49's CAS inherits that scrub. A CAS blob or manifest that carries an
auth header is a credential leak, not an undo artifact.
