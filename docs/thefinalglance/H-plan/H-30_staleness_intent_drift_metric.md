# H-30 -- staleness / intent-drift INSTRUMENT (the measure-before-trust keystone)
- Track 4 (UX + USER-MEMORY) | lever PROVABLE | grounding STRONG | nature BUILD | effort M | WAVE 4 | BLOCKING (gates H-31 + H-32; nothing in the durable-user-memory write/read path is trusted until this fires)
- Premise: before ELAI writes a single durable user fact (H-31) or injects one into a model prompt (H-32), the system must be able to PROVE, from its own append-only journal, that a superseded preference can NEVER reach a prompt and that the agent acts on the latest belief. ELAI's own doctrine (W-1 measure-the-real-objective, R4) forbids trusting a memory feature on cargo-green; we build the instrument FIRST so the H-31/H-32 done-gates have an off-agent number to clear. STALE arXiv:2605.06527 measures the field at <10% conflict-resolution for most frameworks and the best model at 55.2% with a 76%-recognition / 39%-application gap -- so an UNINSTRUMENTED memory feature is, on the literature's own evidence, ~9-in-10 likely to silently surface stale state.

## Steal/build
BUILD (the instrument does not exist; nothing in ELAI emits a staleness number). Two instruments, both reusing the shipped eval-runner pattern, neither inventing a persistence engine (GD-1):
- (a) a RUNTIME metric `stale_fact_reached_prompt / total_retrievals` emitted as SSB rows from the retrieval-into-prompt path, recomputable from the journal under ELAI_SEED;
- (b) a belief-revision EVAL harness (BeliefShift / BEAM-style Conflict-Resolution-Accuracy): a deterministic fixture asserts preference X, then a contradicting Y, and the harness checks the retrieval+adjudication path acts on Y and NEVER surfaces X, AND measures the recognition-vs-application gap (does the store soft-close X? does retrieval still serve it?).
Prior art to REIMPLEMENT in Rust (MIT odysseus, never port): the order-independent fingerprint short-circuit so the eval skips when nothing changed (memory_extractor.py:32-35 `_fingerprint_entries`, :441-443 short-circuit, :573 persist -- reimplement with blake3 over sorted (id,text,category), per Anti-Stale), and the read-time relevance gate semantic that low-signal facts are not surfaced (memory.py:255 `categorize_memory_by_relevance`, :291 `get_relevant_memories`). The >50%-deletion guard (memory_extractor.py:535-540) is a WRITE-side invariant H-31 owns; H-30 only ASSERTS the metric, it does not delete.

## REVISED scope (W-10 tiered)
SHIPS NOW (Tier-1, pure in-process Rust, no network/sidecar/model at gate time -- a whole vertical slice):
- A counting shim around the retrieval chokepoint: every `get_relevant_facts` call increments `total_retrievals`; every returned row whose `valid_to_ms.is_some()` OR whose `superseded_by.is_some()` (i.e. a superseded/closed row that should have been HARD-FILTERED, never narrated) increments `stale_fact_reached_prompt`. On the clean path the ratio is 0 by construction (retrieval already filters via list_current semantics); the instrument PROVES it stays 0 and SCREAMS when a deliberately-broken retrieval serves a superseded row.
- A deterministic eval-runner `StalenessEvalRunner` (mirrors crates/orchestrator/src/benchmarks/seccodeplt_runner.rs): an embedded fixture corpus via include_str! (filesystem-independent, seccodeplt_runner.rs:65 pattern), a `pub fn run(&self) -> StalenessEvalReport` (mirrors seccodeplt_runner.rs:312), a serde Report carrying COMPUTED `conflict_resolution_accuracy` + `recognition_rate` + `application_rate` + `recognition_application_gap` + `stale_fact_reached_prompt` + `total_retrievals` + `seed: u64` (seccodeplt_runner.rs:164) + `corpus_blake3` provenance pin (seccodeplt_runner.rs:166) -- before/after numbers COMPUTED, never literals (seccodeplt_runner.rs:23 honesty discipline). ELAI_SEED via crate determinism (crates/orchestrator/src/determinism.rs:48 ELAI_SEED_ENV, default 0).
- The fixture set: each case states preference X (e.g. FactType::Preference key="test_runner" value="cargo nextest"), then contradicting Y (value="cargo test"), runs the live supersession path (audit_conflicts / adjudicate_semantic), then queries retrieval and asserts: Y is returned, X is NEVER returned (application), AND the store recorded X.superseded_by=Y (recognition). The recognition-vs-application gap = (cases where X was soft-closed) - (cases where retrieval still served X); the STALE failure mode (76% recognise / 39% apply) is the case where the store KNOWS X is stale yet retrieval still surfaces it.
- The deliberately-broken arm: a `--broken-retrieval` fixture variant (or an injected `RetrievalFilter` that does NOT filter superseded rows) MUST make `stale_fact_reached_prompt > 0` and drop conflict_resolution_accuracy -- proving the metric is not vacuously 0 (R2 dead-evidence-path screams; a metric that is always 0 even when broken is itself wire-dark).
- CLI dispatch: `run_bench_staleness(json: bool)` registered in crates/cli/src/bench_cmd.rs alongside run_bench_seccodeplt (bench_cmd.rs:139) / run_bench_safedelta (bench_cmd.rs:149); writes a timestamped report under benchmarks/staleness/<ts>.json and emits ONE result SSB beacon (mirrors seccodeplt's InsecureRateMeasured beacon, seccodeplt_runner.rs:44).
DEFERRED (Tier-2, to H-32): the live retrieval-into-prompt wiring (memory ContextSlot + the conversation.rs get_relevant_facts call). H-30 instruments the CALL, not the not-yet-existent prompt slice. Local-token note: H-30 is offline (no model, no token cost); the eval reasons only over store rows and the deterministic adjudicator (semantic_contradiction.rs:115 DeterministicNliJudge, offline lexical, default-ON) -- the CLOUD-model contradiction pass is a WRITE-side concern (H-31), excluded here to spare the 7B.
STALENESS handling asserted (not built) by H-30: supersession is bi-temporal soft_close (newest-wins, NEVER delete -- DELETE breaks SSB replay); retrieval HARD-FILTERS superseded rows and MUST NOT narrate them as [OUTDATED] (the measured Graphiti +68%-token trap). The metric's whole job is to catch a regression of exactly that invariant.
