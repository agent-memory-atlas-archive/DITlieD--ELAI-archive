# H-31 -- Tier-B user-preference bi-temporal ledger (activate wire-dark crates/memory into a production user-decision path)
- Track 4 (UX + USER-MEMORY) | lever STEERING/TRUST | grounding STRONG | nature ACTIVATION | effort M-L | WAVE 4 | depends H-30
- Premise: a user states a durable WORK preference ("prefer tracing over the log crate", "always run the auditor before commit", "route confirmation-gated tasks to Opus") and ELAI honours it across sessions WITHOUT re-asking, then quietly retires it the moment the user states the opposite -- never narrating the dead rule, never silently auto-learning one. This is the steering substrate the trust product needs: ELAI must remember the user's verifiable decisions, and must be PROVABLY incapable of letting a stale decision (or a flattering injected one) leak into a prompt -- especially an auditor's prompt.

## Steal/build
ACTIVATION, not BUILD. The entire bi-temporal user-memory crate already exists and most of the WRITE-side reconcile loop is already PROD-WIRED in the live tick (live_cli.rs:2034/2076). H-31 builds exactly three missing wires and ZERO new storage: (a) a capture PRODUCER that routes an explicit `/remember` and a propose-on-repeated-correction into the existing `mem0_dispatcher::dispatch_batch` (today its only callers are #[cfg(test)]); (b) a retrieval CONSUMER that calls the existing `get_relevant_facts` (today wire-dark -- every caller is a test) into the prompt-assembly path behind a new ContextSlot; (c) one SSB beacon for the supersede event + a frozen smoke test. odysseus (MIT prior-art) supplies the read-time relevance-gate algorithm (memory.py:291 `get_relevant_memories`, memory.py:255 `categorize_memory_by_relevance`), the high-threshold dedup semantic (memory_vector.py:116 `find_similar` threshold=0.92), and the load-bearing >50%-deletion safety guard (memory_extractor.py:535-540) -- reimplement each in Rust against SSB, never port Python, never copy.

## REVISED scope (W-10 tiered)
SHIPS NOW (Tier-1, this plan):
1. CAPTURE producer, EXPLICIT-ONLY (no silent auto-write -- Cursor shipped-then-removed auto-Memories). Two triggers:
   - `/remember <text>` REPL/CLI command -> extract a single `ExtractedFact{ fact_type: Preference (or RiskTol for routing/spend, Mistake for footguns), key, value, confidence, evidence: [the user turn id] }` and call `dispatch_one` (capture reconcile gives ADD or UPDATE-via-supersede automatically).
   - PROPOSE-on-repeated-correction: when the same correction is observed >=N times (N=2, mirrors odysseus skill_extractor complexity-floor memory_extractor pattern), ELAI SURFACES a proposal ("remember this? Y/N") -- it does NOT write until the user confirms. The proposal itself is the only thing emitted unprompted.
2. WRITE-TIME supersession is already the dispatcher's UPDATE path (`supersede`, store.rs:208) -- H-31 only ensures the new fact's `valid_from_ms == now_ms` so older.valid_to_ms == newer.valid_from_ms exactly (the observable_effect invariant). Contradiction-detection runs on writes only via the EXISTING `audit_conflicts` + `adjudicate_semantic`; the CLOUD model is invoked ONLY on the cross-key residue (the deterministic judge handles the rest offline, live_cli.rs:2025) -- spares the 7B.
3. RETRIEVAL on-demand: add a `Memory` variant to `ContextSlot` and call `get_relevant_facts(store, user_id, &RetrievalFilter{fact_type: Some(Preference), ..}, k=8, now_ms)` from conversation.rs prompt-assembly. The `valid_to_ms IS NULL` hard filter (via list_current) means a superseded fact is STRUCTURALLY ABSENT -- it is never even a candidate, so it can never be narrated as [OUTDATED] (the measured Graphiti +68%-token trap). HALO per-class decay (decay.rs) is the BACKSTOP: a fact whose trust_score has decayed below its FactType threshold drops out of retrieval without ever being deleted.
4. LOCAL-TOKEN DISCIPLINE: memory is RETRIEVAL-ON-DEMAND, never an always-injected block. The new Memory slot is bounded to ~100-500 tokens (k<=8 facts, each one line). odysseus context_budget.py:21 headroom-clamp math is the prior-art for sizing against the ~25-32K local window (reimplement the headroom-clamp, NOT odysseus's 200K cloud hard-max).
5. HARD-EXCLUDE secrets/API-keys/PII/file-contents at the capture boundary (a blocklist+entropy reject in the `/remember` extractor BEFORE any insert -- never store a value that matches a secret pattern or exceeds an entropy floor; reuse the Stage-1 defense.rs blocklist seam noted in the ground bundle).
6. HIGH-STAKES-FLIP CONFIRMATION: if the superseding fact would flip a HARD RULE, a dependency choice, or a model-routing decision (key prefix in a small `HIGH_STAKES_KEYS` set), the supersede is GATED behind a Y/N confirm (reuse the InteractiveGate seam, H-37) rather than auto-applied. All other flips auto-supersede.
7. AUDITOR-OBJECTIVITY FIREWALL: the Memory ContextSlot is populated ONLY when the assembling role is a user-facing/executor role. For role in {auditor, critic, adversary} the slot is forced empty -- ZERO user-memory injection (Personalization-Trap arXiv:2510.09905: persona-injection measurably biases the model toward the user, which would corrupt ELAI's core trust product). This is a compile-time branch on role, not a flag.
8. Default-OFF behind `ELAI_USER_MEMORY_ENABLE` + a wire-dark-allowlist.toml [[flag]] row + a FROZEN smoke test (R3/R4/R9).

DEFERRED (Tier-2/H-32): vector/rerank-ranked retrieval (H-31 ships the trust-floor + last_observed ordering already in get_relevant_facts; DKG+rerank ranking is H-32's job), Scope promotion (project->global) gate, the periodic LLM "tidy/audit" pass (odysseus audit_memories memory_extractor.py:407 + the >50%-deletion guard) -- the guard is SPEC'd here but only ARMED when the tidy pass lands; until then the only bulk operation is per-fact supersede which cannot mass-delete.

STALENESS HANDLING (the #1 design constraint): fixed at WRITE time via bi-temporal supersession (soft_close older row, newest-wins, DELETE BANNED -- DELETE breaks SSB replay). Retrieval HARD-FILTERS superseded rows at the SQL layer (`valid_to_ms IS NULL`); it MUST NOT narrate them. Contradiction-detection runs on the CLOUD model on WRITES ONLY. Decay (HALO per-class half-life) is a BACKSTOP, not the primary mechanism.
