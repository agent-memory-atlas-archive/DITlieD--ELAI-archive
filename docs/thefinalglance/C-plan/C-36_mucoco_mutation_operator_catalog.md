# C-36: MUCOCO Mutation-Operator Catalog Behind Advanced-Operators Flag

Objective: extend the MetamorphicRelation enum (C-29) with the MUCOCO catalog of
semantic-preserving mutation operators, gated behind a default-off feature flag, and
publish a measured inconsistency-discovery rate against ELAI's existing test suite.

Pre-requisites: C-29 (testing trust T2/T3 IntentPair + Metamorphic) SHIPPED.
Parallel-safe with: C-35, C-37, C-38, C-39, C-40 (orthogonal). NOT parallel-safe with
any future patch that modifies the MetamorphicRelation enum definition — sequence
C-36 first.

Paper grounding (arXiv:2604.19086, 2026-04-21, verified abs page 2026-05-17):
"MUCOCO: Automated Consistency Testing of Code LLMs."
Measured claim: "About one in seven (15%) inputs generated by MUCOCO exposed
inconsistencies" (Abstract). The paper catalogs a family of semantic-preserving
mutation operators (variable renaming, dead-code injection, equivalent control-flow
rewrites, type-annotation toggling, etc) and runs them as input-perturbation
oracles. Open-source code release not confirmed in the abstract; treat operator
catalog as the transferable artifact.

## Context

ELAI's C-29 already ships a MetamorphicRelation enum with Identity / Inverse /
PermutationInvariance variants, of which only Identity and Inverse are enabled
by default per the elai_cc.toml [testing.metamorphic] section. The C-29 default
is conservative because not every test target survives permutation-invariance
oracles without false positives.

MUCOCO's contribution is a CATALOG of operators that are known-safe across most
code-LLM targets: variable renaming, whitespace normalization, comment removal,
loop-form rewriting (for ↔ while where semantics permit), branch-form rewriting
(if/else ↔ ternary), redundant-cast injection, type-annotation toggling on
dynamically-typed languages, dead-code injection at the end of a function body,
and import-order rewriting. Their measured 15% inconsistency rate establishes a
floor: any ELAI-trained or ELAI-served model that scores BELOW 85% pass rate
under MUCOCO catalog perturbation has a reproducibility problem.

This is a TRIVIAL patch: extend an enum, populate operator implementations,
expose behind feature flag, run pilot, publish the number alongside ELAI's
existing T2/T3 metrics.

## Tasks

1. **Source-grounding (4G.X)** — spawn paper-ingestor (mode=paper) against
   arXiv:2604.19086. Produces workflow/papers/mucoco-operator-catalog.md with
   verbatim operator descriptions, applicability per language, false-positive
   notes. Required before extending the enum.

2. **MetamorphicRelation enum extension** — append the following variants
   behind a `#[cfg(feature = "mucoco_operators")]` attribute (NOT a runtime
   flag — compile-time gate keeps the default binary lean):
   - VariableRename
   - WhitespaceNormalize
   - CommentStrip
   - LoopFormRewrite
   - BranchFormRewrite
   - RedundantCastInject
   - TypeAnnotationToggle (dynamic-typed langs only)
   - DeadCodeInject
   - ImportOrderRewrite

3. **operators/mucoco/ module (NEW)** — one file per operator. Each file
   exports a function `apply(ast: &TreeSitterNode, rng: &mut Rng) -> Result<MutatedSource, SkipReason>`
   plus a `supports_language(lang: Language) -> bool`. Operators that can't
   apply to a given AST return SkipReason::NotApplicable, not panic.

4. **elai_cc.toml [testing.metamorphic.advanced_operators] section** — add:
   ```
   [testing.metamorphic.advanced_operators]
   enabled = false  # default off; flip to true after pilot publication
   max_operator_chain_length = 3  # cap recursive mutation depth
   exclude_operators = []  # per-project denylist
   require_explicit_in_test = true  # opt-in per-test, not blanket
   ```

5. **Per-language applicability matrix** — Rust supports all 9; Python supports
   8 (LoopFormRewrite has edge cases with iterators); TypeScript supports 8
   (TypeAnnotationToggle is the inverse direction since TS is gradual-typed).
   Java, C++, Go, Swift, Kotlin, Ruby, PHP, C#, Scala, Dart, Lua, Bash, R,
   Julia, Haskell, OCaml support the subset documented in the paper-ingestor
   output, NOT extrapolated. Mark unsupported pairs explicitly in
   operators/mucoco/applicability.rs.

6. **SSB action types** — add 3 new strings: mucoco_mutation_applied,
   mucoco_inconsistency_detected, mucoco_skip_reason. Each carries operator_name,
   target_test_id, language. SCHEMA_VERSION bump required.

7. **Tests first (TDD)** — write before production wiring:
   - 4G.X.3: each operator's apply() returns either a syntactically-valid
     mutated source OR a SkipReason (never panic, never invalid syntax)
   - 4G.X.4: max_operator_chain_length enforcement prevents combinatorial
     explosion (chain of 4 returns at 3, doesn't continue)
   - 4G.X.5: VariableRename respects scoping rules (doesn't rename a global
     into a local-shadowed identifier without renaming the inner shadow too)
   - 4G.X.6: TypeAnnotationToggle on TS preserves semantics (no `: any` casts
     that change runtime behavior)
   - 4G.X.7: exclude_operators denylist honored

8. **Production wiring (4G.X.8)** — wire mucoco operators into the C-29
   MetamorphicRunner only when feature="mucoco_operators" AND
   advanced_operators.enabled = true AND per-test opt-in marker present.

9. **Pilot publication (4G.X.9)** — run mucoco operators against the EXISTING
   ELAI test suite (3,500+ tests per assessment file §3). Publish:
   - per-operator inconsistency-detection rate
   - per-language detection rate
   - false-positive rate (mutations the operator deemed valid but actually
     changed semantics — human-audited sample of 50)
   Target: match or exceed paper's 15% measured floor on at least one operator.
   Falls below 15%: operator implementation likely buggy, file as separate
   bug, do not block C-36 closure.

10. **Documentation** — add MUCOCO operator catalog to
    .elai_cc/docs/testing-trust.md (DETAILED_SUMMARY_01 §3 testing-trust section).

11. **Contract tests** — tests/contracts/mucoco_contract.rs verifying each
    operator's apply() signature and SkipReason taxonomy.
