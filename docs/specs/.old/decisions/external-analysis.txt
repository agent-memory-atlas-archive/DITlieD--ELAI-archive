Source: design_document.txt PART 16, PART 30.2-30.7, PART 31.


OH-MY-CLAUDECODE (OMC) — design PART 30.2

  What it is: Claude Code plugin (JS/TS). 19 agents, 13 skills, Gyoshu Bridge.
  Cloud-only, not standalone, not local-model-capable.

  REJECTED:
    - Agent catalog (19 named agents): our role-based GRC system is architecturally superior.
    - Workflow skills (autopilot, ralph): prompt-driven modes. Our FSM+evidence is more rigorous.
    - State management (.omc/ JSON): our SSB (SQLite WAL) is more robust.
    - Model routing (haiku/sonnet/opus): our VRAM-aware scheduling is hardware-conscious.

  ADOPTED:
    - SWE-bench benchmark (30.3): rotation set for self-modification benchmarking.
    - Failure taxonomy (30.4): deterministic error classification before auditor reasoning.
    - Structured execution markers (30.5): [CALL], [FINDING], [ERROR] etc. for trace output.
    - Parity audit pattern (30.7): migration manifest for tracking fork coverage.

  DEFERRED:
    - Gyoshu Bridge (30.6): sandboxed Python execution. Evaluate in Phase 4.

DAIRA (arxiv 2603.22048v2) — design PART 16.1

  Trace-first debugging. 80.8% resolution on medium bugs (SOTA).
  Ablation: -11.3% without TLSA, -8.1% without DAT, -5.4% without FSM workflow.
  Adopted: trace_execution() tool, GRC observe dynamic trace, adaptive scope reduction.
  Generalized: AdaptiveTool<T> wrapper for any variable-output tool.

  Adopted: code_simplify() as post-processing on executor output.
  Rules R4/R6 configurable (readability vs conciseness tradeoff).


TURBOQUANT-WASM — design session 8

  What it is: Zig compiled to WASM, two-stage vector compression (polar + QJL residual).
  ~3-5 bits/dim, 8-10x compression vs f32, <0.15 mean dot-product error.
  Demo: full client-side semantic search with Transformers.js embeddings.

  REJECTED:
    - WASM wrapper (we are a native Rust binary, not browser-based)
    - Zig FFI (rewrite algorithm in Rust, not FFI bridge)
    - Brute-force search (scan all vectors — no sub-linear, HNSW needed)

  ADOPTED (algorithm only, deferred to Phase 1C):
    - Polar + QJL quantization algorithm for compressed vector storage in knowledge/ crate.
    - Dot-product-on-compressed-bytes trick (similarity without decompressing).
    - Combine: HNSW for sub-linear search + TurboQuant algorithm for stored vectors.
    - Same pattern as FAISS Product Quantization.

  DEFERRED: evaluate during Phase 1C (vector search implementation).


FLASHRESEARCH (arxiv 2510.05145) — Efficient Tree-Structured Deep Research

  ADOPTED:
    - Tree-structured research expansion: replaces flat ResearchLoop with ResearchTree.
      Each node can spawn child sub-queries up to breadth_factor * depth_limit.
    - Speculative execution: begin child queries before parent converges (cloud API only).
    - Dual-threshold convergence: phi (goal satisfaction) + psi (quality) replace single
      convergence_threshold. Separates "answered?" from "well-sourced?"
    - Adaptive breadth/depth per query complexity.

  NOT ADOPTED:
    - Runtime orchestration monitoring (elai_cc already has SSB-based tracking).

  Applied in: pipeline-factory.txt section 5-6, implementation-plan.txt Phase 4D.


CMV (arxiv 2602.22402) — Contextual Memory Virtualisation

  ADOPTED:
    - DAG-based session state: replaces flat handoff.msgpack with SessionDag (SQLite).
      Snapshots form acyclic lineage. Supports branching and merging.
    - Structurally lossless trimming: 3-pass streaming algorithm preserves all user/assistant
      messages, stubs large tool results (>500 tokens) with recoverable references.
    - Branch-and-explore: snapshot + try approach A + revert + try approach B.
    - Prompt cache awareness: trimming preserves prefix tokens in cache breakpoints.

  NOT ADOPTED:
    - In-place session modification (elai_cc uses append-only SSB, never modifies).

  Applied in: orchestrator.txt section 10, implementation-plan.txt Phase 3H.


MURAKKAB (arxiv 2508.18298) — Resource-Efficient Agentic Workflow Orchestration

  ADOPTED:
    - SLO quality tiers: BEST/GOOD/FAIR/BASIC per agent role. Controls model selection
      and VRAM allocation. Maps to agent role system (auditor=BEST, memory-writer=BASIC).
    - GPU multiplexing: small models (<4GB) colocate on same GPU with headroom check.
    - Workload profiling: track tokens/latency/VRAM per agent per phase in SSB.

  DEFERRED (EVALUATE in Phase 2+):
    - MILP-based model placement optimization. Current heuristic scheduling may suffice.
      Only implement if Phase 2 metrics show heuristic is suboptimal.

  NOT ADOPTED:
    - Cloud-specific autoscaling (elai_cc is local-first, fixed hardware).
    - Multi-workload coordination (single-user system, not cloud platform).

  Applied in: providers.txt section 4, implementation-plan.txt Phase 2+.

DETERMINISTIC SIMULATION TESTING (DST) — new research, Advanced Testing Report

  ADOPTED:
    - Entropy quarantine pattern (FoundationDB/TigerBeetle/RisingWave):
      All time/randomness access through injectable traits (ClockProvider, EntropySource).
      Clippy deny rules ban raw std::time::Instant::now() and rand::thread_rng().
      Applied at fork time (Phase 0.8) because retrofitting is 10x harder.
    - Digital sibling reference model (ICSE 2024/2025):
      Simplified in-memory FSM model as infallible oracle for stateful PBT.
      FSM + SSB + BSP is already a state machine F(State, Event) -> State.
      Test: 10,000 random operation sequences, assert terminal states match.
    - madsim integration for IPC layer testing:
      Deterministic network simulator replaces tokio for IPC tests.
      Inject: packet loss, jitter, disconnects, agent crashes. All reproducible via seed.
      Validates Phase 4A IPC design before building real process isolation.
    - Stateful PBT + DST convergence:
      proptest generates random operation sequences (phase transitions, agent spawns,
      tool calls, crash injections). Executed inside madsim deterministic runtime.
      Shrinker isolates minimal failing sequence. Shrunk cases become permanent regression tests.
    - Adversarial state space exploration:
      Model demonic non-determinism (worst-case interleavings). Not angelic (happy path).
      Anti-spiral, evidence gates, context budget all tested under adversarial scheduling.

  DEFERRED (EVALUATE):
    - Antithesis hypervisor-level DST: closed-source, high cost. Evaluate if madsim
      proves insufficient for catching FFI leakage in ort ONNX bindings.
    - Coyote Q-learning exploration: .NET only, but the exploration heuristic
      (reinforcement learning for state space coverage) could inspire custom scheduling
      strategies in our madsim test harness. Low priority.

  NOT ADOPTED:
    - TigerStyle strict static memory allocation: too restrictive for a general-purpose
      tool. TigerBeetle can do this because it is a single-purpose database. elai_cc
      needs dynamic allocation for variable-size code contexts, vector embeddings, etc.
    - Full VOPR-style 24/7 fuzzing cluster: cost-prohibitive for personal-use tool.
      DST runs in CI and on developer machine. Not dedicated hardware.

  Applied in: core.txt section 4 (entropy traits), implementation-plan.txt Phase 0.8 + 3I.


SPECULATIVE DECODING (EAGLE-3 / TIDE) — Local LLM Performance research

  ADOPTED:
    - Speculative decoding evaluation in Phase 1F: draft model (same family, smaller)
      generates candidate tokens, main model verifies. EAGLE-3: 2x-6.5x on large models
      (arxiv 2503.01840, NeurIPS'25; lower on small models). Adopt if >1.3x on target hardware (RTX 3060).
    - TIDE temporal incremental draft: solves stale draft problem where draft model
      predictions diverge from target. 1.15x improvement over static speculative decoding.

  NOT ADOPTED:
    - OpenVINO optimization: Intel-specific, our target is NVIDIA GPUs.

  Applied in: providers.txt section 3, implementation-plan.txt Phase 1F.


OBSERVABLE INFERENCE / AUDIT TRAIL — Verifiable Audit Trail research

  ADOPTED:
    - Structured reasoning traces: every GRC step + tool call + grounding check
      stored as ReasoningTraceEntry in SSB. Machine-readable, not prose.
      Enables post-mortem debugging, compliance audit, and richer self-modification
      log-driven proposals.
    - Cognitive isolation metric: quantifies context savings from agent process
      isolation. On 8k local model, isolation may save >100% of context window
      (agents generate more reasoning tokens than the model's full context).

  NOT ADOPTED:
    - ReAct scratchpad pattern: elai_cc already has GRC which is structurally superior
      (grounded reasoning with verification, not free-form thought/action/observation).
    - External telemetry platforms (LangSmith, Arize Phoenix): elai_cc is local-first,
      all traces stored in SSB. No external service dependency.

  Applied in: orchestrator.txt section 7A, implementation-plan.txt Phase 3C.


INCREMENTAL COMPILATION FEEDBACK — Functional Determinism research

  ADOPTED:
    - Compilation-in-the-loop during EXECUTING: after each file write by executor,
      run cargo check / ruff / tsc / go vet. Feed errors back immediately via IPC.
      Expected: ~30% reduction in auditor BLOCK findings for syntax/type errors.
    - Max 3 retries per file to prevent infinite loops.

  NOT ADOPTED:
    - Monte Carlo Tree Search for code generation: requires process reward model
      training infrastructure. Too expensive for local inference.
    - Hardware-level DVR (Decode-Verify-Rollback): requires custom GPU kernels.
      Out of scope for Phase 0-4.

  Applied in: tools.txt section 10, implementation-plan.txt Phase 4B.


COGNITIVE ISOLATION AS CONTEXT EFFICIENCY — Post-DAG Orchestration research

  ADOPTED:
    - IPC as cognitive isolation mechanism: agent reasoning chains (potentially
      thousands of GRC tokens) never enter the orchestrator's context window.
      This is not just security — it is a context budget efficiency mechanism.
      On 8k local models, this may determine whether a task fits at all.
    - Supervision tree pattern for agent lifecycle: formalized restart policy
      (max 3 restarts per phase, then escalate or substitute model).

  NOT ADOPTED:
    - CRIU checkpoint/restore: too heavyweight for agent process restart.
      Our msgpack checkpointing is lighter and sufficient.
    - 9P filesystem semantics: interesting for capability-based access but
      adds significant complexity over visibility filter + mount namespace.

  Applied in: orchestrator.txt sections 7, 7A.


VECTOR CACHE INVALIDATION — Codebase Memory Engine research

  ADOPTED:
    - Immediate vector cache invalidation on SSB file_write event.
      Prevents stale embeddings being served for files edited in the current phase.
      Cost: 1 SQLite DELETE per file_write. Negligible.

  NOT ADOPTED:
    - TOON (Token-Oriented Object Notation): claims 40-60% token reduction over JSON.
      msgpack already provides comparable compression. EVALUATE if context budget
      analysis in Phase 1 shows serialization overhead is a bottleneck.

  Applied in: knowledge.txt section 3 (Layer 3).


SWE-WORLD (arxiv 2602.03419) — Docker-Free SWE Agent Training and Evaluation

  What it is: framework replacing Docker execution environments with a learned world model
  (LLM-based transition model) for predicting execution outcomes. Hybrid execution:
  deterministic sandbox for lightweight ops (file nav, grep, edits) + LLM transition model
  for execution-oriented commands (pytest, compile). Enables test-time scaling (TTS) by
  simulating evaluation outcomes without real submission. Qwen2.5-Coder-32B: 6.2% -> 52.0%
  resolve rate on SWE-bench Verified via Docker-free SFT, 68.2% with TTS.

  DEFERRED (EVALUATE in Phase 4G+):
    - Learned reward model for self-modification variant pre-screening:
      Train lightweight predictor on accumulated PipelineOutcome data (SSB logs).
      Score candidate config variants before committing to real staged evaluation.
      Could screen 100 variants in the time of 10 real runs.
      Precondition: >50 pipelines with outcome data.
      Only implement if MSI tracking shows variant selection is a bottleneck.
    - Learned transition model for FEASIBILITY_PROBE acceleration:
      Predict test outcomes for stub alternatives without running them.
      Conditional on having enough execution traces to train on.

  NOT ADOPTED:
    - CoT backfilling / distillation: GRC engine already provides structured grounded
      reasoning, architecturally superior to CoT distillation.
    - Replacing real test execution during AUDITING: safety model depends on deterministic
      validation. SWE-World is for training/screening, not production enforcement.
    - Docker-free SFT for local model fine-tuning: out of scope for Phase 0-4.
      Revisit if fine-tuning a local model becomes a goal.

  Applied in: implementation-plan.txt Phase 4G EVALUATE, risk-register.txt R53.

    target model hidden states. 1.15x improvement over static speculation.
  ICSE 2024/2025 DST literature: digital sibling methodology, oracle problem formalization,

  SWE-World (arxiv 2602.03419): Docker-free SWE agent environments with learned world model.
