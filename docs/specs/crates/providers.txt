  - Assistant prefill continuation for code output (design 31.13)


2. LLMPROVIDER TRAIT

  trait LlmProvider {
      fn complete(prompt, config) -> Stream<Token>;
      fn embed(text) -> Vec<f32>;
      fn token_count(text) -> usize;          // exact, real tokenizer
      fn token_count_estimate(text) -> usize;  // sampling-based, O(lines/N)
  }

  Sampling estimation (design 31.9):
    Sample every Nth line (N=10 default).
    Count tokens on sampled lines using real tokenizer. Multiply by N.
    Accuracy: 95%+ for files >100 lines. Exact for files <=N lines.


3. LAYERCONFIG

  Phase 0-1 (ollama — available immediately):
    OllamaConfig: temperature, top_p, grammar constraints (constrained decoding).
    All roles get temperature/top-p per role in elai_cc.toml.
    Executor: standard inference, rely on GRC for grounding.
    Auditor: low temperature (0.1-0.3), constrained output format.
    Tier 2 rule enforcement: grammar constraints enforce SCHEMA_REQUIRED predicates
    from rules.db (see rules.txt section 3-4). Model physically cannot produce output
    missing required fields. Predicates queried from SQLite at prompt construction time.
    Examples: opposing_thesis, trial_count, commission+slippage+spread.

  Phase 2+ (vLLM — after integration):
    VllmConfig: DoLa, TurboQuant, steering vectors.
    Executor (Gemma 4 31B): TurboQuant (3.8-6.4x KV cache compression) + DoLa (factuality).
    Auditor (DeepSeek-R1-32B): DoLa amplified + skepticism steering vectors.
    Prompt-engineer (Qwen 3.5 27B): constrained decoding only.
    Context-compiler: high temperature (0.7), completeness steering.

  CRITICAL: ollama is a black box — no layer-level intervention.
  DoLa/TurboQuant require vLLM or custom inference.


4. MODELPOOL (VRAM lifecycle)

  Tracks: {model_id -> ModelState(Loaded(gpu_id, vram_used) | Unloaded | Loading)}
  VRAM query: nvml-wrapper (NVIDIA) or sysinfo (cross-platform fallback).

  Priority levels:
    ACTIVE:  needed by running agent. Never unloaded.
    PRELOAD: needed by next agent (predicted from FSM). Background load if VRAM allows.
    IDLE:    not needed soon. Unloaded first on VRAM pressure.

  Predictive pre-loading (FSM-driven, deterministic):
    EXECUTING -> pre-load auditor. AUDITING -> pre-load executor.
    PLANNING -> pre-load prompt-engineer. TESTING_FIRST -> pre-load executor.

  Ollama integration:
    POST /api/generate (triggers load), DELETE /api/delete (unload).
    KEEP_ALIVE parameter controls auto-unload timeout.
    Dual-GPU: CUDA_VISIBLE_DEVICES per ollama instance or --gpu flag.

  Swap protocol:
    1. Determine next model needed.
    2. Fits alongside current? Load in parallel.
    3. Doesn't fit: wait for checkpoint, unload current, load new.
    4. Health check inference. Resume pipeline.

  vLLM integration (Phase 2+):
    vLLM manages own GPU memory. ModelPool delegates to vLLM scheduler.
    Multiple models via --served-model-name with tensor parallelism.


5. NODE-LEVEL CACHE (design 31.6)

  struct CachePolicy { key_fn, ttl_seconds }
  CacheKey: xxhash after normalization.
  Float normalization: NaN -> u64::MAX, -0.0 -> 0.0, round to 6 decimal places.
  In-memory HashMap<CacheKey, (Output, Instant)> per node. NOT checkpointed.
  TTL checked on access: expired entries removed.


6. ASSISTANT PREFILL CONTINUATION (design 31.13)

  On finish_reason=Length during EXECUTING phase code generation:
    Append partial response as assistant turn, send continuation.
    Max 3 continuations. Merged output validated by tree-sitter parse.
    SCOPE: code generation in EXECUTING only. Never applied to reasoning/planning.

9. TESTABLE INVARIANTS

  - token_count_estimate within 15% of exact for files >100 lines
  - ModelPool never exceeds VRAM capacity (load blocked if insufficient)
  - Model swap only at phase boundaries (never mid-agent-execution)
  - Cache hit skips model invocation entirely
  - Float normalization: key(-0.0) == key(0.0), key(NaN) == key(NaN)
  - Prefill continuation only triggers on finish_reason=Length in EXECUTING
