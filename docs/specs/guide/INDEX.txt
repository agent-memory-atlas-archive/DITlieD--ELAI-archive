Entry point for LLM phase-by-phase implementation of elai_cc.
Project scope: Rust-native LLM workflow engine, INTERACTIVE-first then AUTONOMOUS.
9 crates in dep order: core, providers, knowledge, reasoning, rules, tools,
plugins, orchestrator, cli. Base = claw-code-rust-port fork (~61K LOC, 684 tests).

  -> AUDITING -> MEMORIZING -> COMPLETE -> IDLE.

6) anti-staleness-enforcement.txt    (2026-04-13, audit-revised)
========================================================================
PROBLEM: LLMs default to frequency-based retrieval from training distribution.
Stale APIs (blake2 appearing 10,000x in training) win over current best practice
(blake3, used 50x near cutoff). ICSE 2025 data: Java 72% / Python 38% failure rate
on deprecated APIs, 2.74x more security vulns in AI PRs. ELAI audit found 9 critical
+ 14 high findings; root cause = training-era defaults beating current practice.

4-LAYER DEFENSE-IN-DEPTH:
  Layer 1 (pre-generation, ctx assembly):
    1.1 RAG FRESHNESS — exp decay (half-life 180d, doc 90d) + log access boost
        (cap 2.0x) in RRF scoring. Sidecar SQLite freshness_meta.db; no tantivy
        schema change.
    1.2 VERSION_GATE predicate — deprecated_patterns table; ecosystem-keyed
        (cargo/pip/npm/go/maven/nuget/bundler/composer); language-parameterized
        regex sets for both source imports AND manifest declarations.
        Self-discovery via ViolationRecord.replacement_name extension.
    1.3 CONSTITUTIONAL SPEC INJECTION — auto-generated CONSTRAINTS block
        appended to PhaseSpec content at assembly time (counts against PhaseSpec
        token budget, ~5-15 tok/constraint, max 200 tokens).

  Layer 2 (during generation):
    2.1 ETC LogitsProcessor — entropy d2H monitoring, observes without modifying
        scores; triggers external search between generations (not mid-token).
        Calibration required (default DISABLED, threshold=infinity); script
        metrics/calibrate_etc_threshold.py. Incompatible stacked with DoLa on
        <32B models (must be only LogitsProcessor on 7B/14B).
    2.2 FRESHNESS STEERING VECTOR — modern_api_preference computed from
        equal-length contrast pairs, mid-layer ActAdd injection (alpha=0.3).
        MEASURED neutral on 7B with generic pairs; ship DISABLED.
    2.3 CONSTRAINED DECODING FOR IMPORTS (vLLM-only) — positive allowlist via
        JSON Schema or EBNF (XGrammar); negative lookahead is PCRE and won't
        compile to FSM. Fallback skip if ollama.

  Layer 3 (post-generation):
    3.1 T1 HOOK VERSION_GATE — after T1/T2 fix (Priority 0 prereq), regex match
        imports+deps; BLOCK/WARN per severity. Generic "tool call rejected by
        policy" message (prevent gaming).
    3.2 T2 HOOK AST EXTRACTION — tree-sitter import/use AST per language;
        catches aliased/wildcard imports regex misses.
    3.3 DETERMINISTIC-FIRST AUDITOR — build/lint/VERSION_GATE/imports/lazy code
        BEFORE LLM judgment. Language-parameterized build cmds (Rust cargo,
        Python ruff, Go go vet, etc.).

  Layer 4 (maintenance, offline):
    4.1 NIGHTLY DEP AUDIT — query 7 ecosystems' registry APIs (crates.io,
        PyPI, npm, Go proxy, Maven Central, NuGet, RubyGems). reqwest-based
        CLI subcommand `elai dep-audit`.
    4.2 FRESHNESS DECAY RECALC — alongside audit.
    4.3 STEERING VECTOR REFRESH — when deprecated_patterns changes.

KEY TYPES: FreshnessConfig, DeprecatedPattern, VersionGatePredicate,
  SearchTriggerPayload, DepAuditResult/Entry; ETCLogitsProcessor (Python).
SCHEMAS: freshness_meta.db (file_freshness); deprecated_patterns table in rules.db;
  ViolationRecord gains replacement_name: Option<String>.

IMPLEMENTATION PRIORITY:
  P0 prereq: fix T1/T2 stubs + C-04 (model.generate migration).
  P1: VERSION_GATE + deprecated_patterns + constitutional inject + T1 wiring.
      Blocks 48% (23/48) of audit findings.
  P2: steering vec, ETC (after calibration), deterministic-first auditor.
  P3: RAG freshness, T2 AST, nightly dep audit.
  P4: vLLM constrained imports, decay/vector refresh automation.

Audit resolved: BLOCK-1..7, WARN-1..8 (each fix documented at end of file).
Reasoning integration: feeds Layer 1 FailureTaxonomy (MISSING_IMPORT → deprecated_patterns
lookup); ETC entropy = GG Signal 3; steering vector active during repair retries;
constrained decoding active in AB-MCTS branches.

7) code-completeness-enforcement-design.txt   (2026-04-13, audit+research-grounded)
========================================================================
TWO PROBLEMS: (1) LAZY GENERATION — todo!/pass/placeholders increase with task
complexity, esp. small models. (2) MONOLITH DRIFT — LLMs dump into single files;
500+ LOC exceeds attention ceiling → death spiral.

PRINCIPLE: responsibility-based file discipline (research-grounded: "optimal file
size = one responsibility, not arbitrary line count").
  TIER 1 (BLOCK, AST): cyclomatic complexity max 10/function; coupling max 15
    external symbols/file.
  TIER 2 (WARN, lines): per-language soft limits + 4x hard BLOCK:
    Rust/Go 100/200/400; Python/Ruby/Elixir 120/250/480; TS/JS 150/250/600;
    Java/C# 200/300/800; C/C++/Kotlin/Swift 150/250/600; default 150/250/600.
  Two-tier prevents Pass@1 drop from mechanical truncation (19.45% per research).

5-LAYER ENFORCEMENT:
  L1 Decomposition constraints (4D/4E):
    1.1 FILE_PLAN block in BabyStepSpec (REPLACES target_file). Tier-gated:
        MICRO 1+1, SMALL 1+2, MEDIUM 2+3, LARGE 3+5 (creates+modifies).
    1.2 LOC budget per file with cumulative FileLineTracker (HashMap in
        TreeNavigator, updated each baby step — prevents TOCTOU).
    1.3 ModuleTree template (language-specific Rust/Python/TS/Go/Java).
  L2 Template-enforced structure (4E):
    2.1 SKELETON-FIRST with fill protocol: orchestrator holds skeleton in
        memory; mini-critic per blank (tree-sitter parse + import ref check +
        ≥3 lines + T1 lazy regex); 2 fill-retries; write file once.
    2.2 BRIDGE FILE TEMPLATE — orchestrator deterministically generates
        mod.rs / __init__.py / index.ts / Usings.cs; never LLM.
    2.3 ENTRY POINT TEMPLATE — fixed structure per language (uses anyhow::Result).
  L3 Post-generation verification (3J.10):
    3.1 T1 LAZY CODE DETECTION — language-parameterized regex (todo!/pass/
        NotImplementedError/throw new Error("not impl")/panic(...)). Always
        WARN; T2 decides BLOCK.
    3.2 T1 FILE SIZE — language-specific limits; 4x hard BLOCK, else WARN/INFO.
    3.3 T2 AST COMPLETENESS — no ERROR nodes; empty-body detection with
        block-level test-context awareness (Rust #[cfg(test)], pytest test_*,
        Go Test*, TS describe/it, Java @Test, C# [Test/Fact]); function count
        vs FILE_PLAN; import completeness; magic-number AST (moved from T1);
        responsibility metrics (cyclomatic, coupling).
    3.4 T3 COMPILATION (language-specific build cmd).
  L4 Auditor (3C):
    4.1 Deterministic checks: file size census, lazy scan, completeness vs tree,
        module coherence (orphan detection).
    4.2 LLM auditor: semantic completeness (does body implement TASK behavior).
  L5 Recovery (4E BubbleUpHandler):
    5.1 ACCEPT-AND-COMPLETE (Plantain 72.7% recovery): if completeness_ratio
        ≥0.5, accept good functions, spawn dedicated completion baby steps for
        lazy ones. Else full structural retry.
    5.2 STRUCTURAL retries (no instructional — "try harder" empirically HARMS):
        Retry1=DECOMPOSE (MoTCoder +5.9), Retry2=TEMPLATE (interleaved +6),
        Retry3=FEW-SHOT (TDP +6.09).
    5.3 FILE-SIZE BUBBLE-UP — orchestrator splits rejected write buffer via
        tree-sitter into 3-5 functions/file, generates bridge, creates new baby
        steps. Deterministic, no LLM.

KEY TYPES: FilePlan/FileSpec/FileModSpec/FunctionSpec; ModuleTree/ModuleNode/Kind;
  LanguageLimits; FileLineTracker; CompletenessResult/LazyMatch;
  LanguageTemplateRegistry; ResponsibilityMetrics; TriageResult/RecoveryStrategy;
  MiniCriticResult/Verdict.
PREDICATE CHANGES: NO new predicate types. GREP_PATTERN gains optional language,
  file_context fields. FILE_SIZE_GATE = METRIC_GATE instance.

Audit resolved: B-1..B-9, W-1..W-7, I-2, I-4.
Research grounding: Aider (laziness 20→61% with diff+AST), SWE-Agent (ACI),
OpenHands (critic +22%), MoTCoder, Blueprint2Code (96.3% HumanEval), CRANE +10pp,
CodeFast +34-452% speed.

Integration: reasoning-architecture LAYER 1 expansion (LAZY_CODE, EMPTY_BODY,
FILE_SIZE_EXCEEDED categories with fix templates); MistakeBook records lazy-event
patterns; BubbleUpHandler.DiagnoseAndRetry runs reasoning pipeline before redecompose.

8) deterministic-harness-design.txt    (2026-04-13)
========================================================================
PROBLEM: every AI coding harness today (Claude Code, Cursor, Aider, etc.) puts
rules into .md files injected into prompt → probabilistic compliance (Claude
estimated 70-90%; local 2B much worse — rules compete with task instructions).
ELAI workflow itself: ~1500-2000 token rules MINIMUM/turn; for 3K MICRO budget
this is half the context and STILL gets violated.

CORE INSIGHT: "the rules should be the system, not the prompt." Difference
between "please don't" vs "the car physically can't accelerate."

3-TIER RULE CLASSIFICATION:
  Tier 1 DETERMINISTIC (no LLM, <1ms): regex/AST/structured query. Never in
    prompt. T1 hook in PostToolUse BLOCKs before write reaches disk. Zero
    token cost. Universal language coverage.
  Tier 2 AST-STRUCTURAL (no LLM, <10ms): tree-sitter parse + pattern check
    (e.g. Mutex::lock across .await; std::thread::sleep in async fn body).
    T2 hook. ~50 languages via tree-sitter grammars.
  Tier 3 SEMANTIC (LLM judgment or human review): in prompt for LLM/auditor
    BUT reduced to 3-5 most-relevant per baby step (~50-100 tokens vs 1500+).

UNIVERSAL RULE DERIVATION (3 sources):
  Source 1 — LANGUAGE BEST PRACTICES (linter delegation): clippy ~700 lints,
    ruff ~800, eslint ~300, golangci-lint ~100, checkstyle ~200, etc.
    ELAI doesn't reimplement; runs project's own linter as T1/T2 check via
    LINTER_GATE predicate. Linter IS the rule engine; uses project's own config.
  Source 2 — PROJECT CONVENTIONS (auto-detected): from ProjectProfile Tier 2.
    snake_case at >80% → WARN camelCase; uses thiserror → WARN Box<dyn Error>
    in public APIs. CONVENTION_GATE predicate.
  Source 3 — DOMAIN RULES (curated packs): trading/gamedev/security/ml/web .rules.db
    files, loaded by domain detection. Community-contributed rule packs (Phase 5+).

LINTER INTEGRATION: incremental linting with caching (lint_cache.db keyed by
(path, blake3 content hash)). Single-file lint mode (cargo clippy --, ruff check,
eslint single file). JSON output (--message-format=json / --output-format=json).
First-run full lint 5-30s (acceptable, once during indexing); incremental <1s;
cache <1ms. Degrade gracefully to regex-only if linter missing.

WHAT CHANGES:
  Phase 3F: add LINTER_GATE, CONVENTION_GATE predicate types; auto-seed from
    ProjectProfile; domain rule registry (+200-300 LOC).
  Phase 3J.10: load+evaluate rules from rules.db (P0 fix); LINTER_GATE eval
    (+150-250 LOC).
  Phase 3E: Slot 2 (Rules) shrinks dramatically (MICRO 50-80 tok vs 150;
    LARGE 200 vs 500). Freed tokens to CodeContext (+30-50 LOC).
  Phase 3C: agents get Tier 3 only; auditor deterministic-first (+50-80 LOC).
  Phase 4C/4D/4H: hook integration, designer convention awareness, self-mod
    rule proposal pipeline.

NEW PHASE 3L (DETERMINISTIC HARNESS):
  3L.1 LINTER_GATE predicate (+lint_cache.db)
  3L.2 CONVENTION_GATE predicate
  3L.3 Rule auto-seeding from ProjectProfile (CANDIDATE lifecycle, promote at 10)
  3L.4 Domain rule registry (+5 built-in packs)
  3L.5 .md→SQLite migration tool (`elai rules import`)
  3L.6 Context budget adaptation (Tier 3 only)
  3L.7 Deterministic-first auditor wire
  Total: 800-1200 LOC, 4-6 sessions.

DEPENDS ON: project-intelligence (for ProjectProfile + linter detection),
  token-efficiency (calibration), with anti-staleness + code-completeness as
  rule SOURCES that flow into the harness.

WHAT IT SOLVES: 47% increase in usable MICRO ctx; determinism (Tier 1/2 cannot
be violated); universality (linter delegation covers any language); scalability
(more rules = more enforcement, ZERO token cost); local model viability;
eliminates the prompt-level workarounds practitioners invent (personas, temp-file
memory, persona prompts).

3 SUGGESTED RESEARCH PROMPTS appended (deterministic vs prompt enforcement;
linter as enforcement layer; convention detection).

9) project-intelligence-design.txt    (2026-04-13, audit-revised)
========================================================================
GOAL: ELAI opens ANY project directory and within seconds knows: languages,
build/test/lint commands, conventions, frameworks, project type, test layout,
CI system. "Holy shit smart" effect comes from SYSTEM doing the understanding.

PROJECT PROFILE: central data structure stored at .elai_cc/project-profile.toml
(human-readable, editable). Overrides in separate file
.elai_cc/project-profile-overrides.toml (never auto-modified, merged on top).

3 TIERS (latency UNGROUNDED, must measure):

  TIER 1 STRUCTURAL DISCOVERY (deterministic, <5s):
    2A Build system: detects 20+ (Cargo, npm, Bun, pyproject, go.mod, CMake,
       Makefile, Gradle, Maven, Mix, Bundler, Composer, dotnet, deno, Zig,
       meson, just, Task). Priority: language-native > pkg manager > task runner
       > generic. Monorepo via workspace declarations. For package.json/
       pyproject.toml: READ scripts, don't guess "npm test".
    2B Language: extension census + tree-sitter parse success.
    2C Framework: dependency lookup table (~200 entries: Axum/Actix/Bevy/Tauri/
       FastAPI/Django/PyTorch/Next.js/Svelte/Express/Gin/Spring Boot/ASP.NET/
       Phoenix/Rails). Unknown = "custom" + Tier 3 attempt.
    2D Test runner: location pattern (same-file/adjacent/separate), naming,
       coverage tool.

11) reasoning-architecture-design.txt    (2026-04-14)
========================================================================
THESIS: "The model does not reason. The system reasons for it." Reasoning
decomposes into 6 discrete operations: classify error, localize root cause,
generate hypotheses, select fix, apply fix, verify. Frontier models do all 6
in one chain; small models can't (ARLCP: long reflection ACTIVELY HARMS sub-10B).
Evidence: ClawsBench (Apr 2026) — scaffolded models of ANY size cluster within
10pp band; scaffold dwarfs model variance.

6-LAYER EXTERNALIZED REASONING PIPELINE (each layer = next-cheaper failure mode):

  LAYER 1 DETERMINISTIC (no LLM, ~60-70% errors, sub-100ms, $0):
    FailureTaxonomy 9 categories (MISSING_IMPORT, TYPE_MISMATCH, SYNTAX_ERROR,
    UNDEFINED_SYMBOL, LIFETIME_ERROR, BORROW_ERROR, UNUSED_WARNING,
    TEST_ASSERTION, RUNTIME_PANIC). Localization: compiler diagnostic parse +
    DKG edge traversal (for UNDEFINED_SYMBOL: lookup → fix = import) +
    SVRepair CFG→SSG Mermaid serialization for logic errors + dependency
    analysis for TYPE_MISMATCH (expected vs actual). Fix instruction generation:
    per-category template (MISSING_IMPORT, TYPE_MISMATCH, etc.). Projected
    >95% pass rate for template-directed fixes.
    Types: DiagnosticResult, RootCause, RootCauseKind, DiagnosticConfidence.

  LAYER 2 MICRO-REFLECTION (~20-25%, 1 LLM call JSON, ~600 tok, 2-5s):
    Compressed context max 500 tok (spec goal + failed code + error + types).
    JSON-constrained output: {root_cause<30w, faulty_line, action<20w}.
    Temperature 0.3. Stored in MistakeBook. Injected as STRUCTURED constraint
    next attempt. Research: ARLCP — long reflection harms sub-10B; First Try
    Matters — overused checking overturns correct answers.

  LAYER 3 INTERROGATION TREE (~5-8%, 3-7 LLM calls multiple choice, 10-30s):
    System-guided Q&A. ~310 tok input + 10 tok output per question.
    Q1 ERROR LOCATION (5 choices); Q2 ROOT CAUSE CATEGORY (conditional);
    Q3 FIX APPROACH (conditional). Terminal nodes map to FixTemplates.
    Language-parameterized: Rust trees include lifetime/borrow; Python type
    hints; Go goroutines/channels. Trees stored as data in rules.db.
    Types: InterrogationTree, QuestionNode, Choice.

  LAYER 4 AB-MCTS TREE SEARCH (~3-5%, 3-15 LLM calls, ~3.6-18K tok, 30-90s):
    Branch at failure point. N=3 alternatives, temperatures [0.7, 1.0, 0.3]
    (diversity+exploration+focus). Forbidden diffs from MistakeBook.
    SCORE = compile*100 + tests_passed*50 + token_confidence_mean*20 +
            novelty_vs_previous*10 + code_length_penalty.
    GG INTRINSIC: mean_logprob + cosine(new, last_failed). Both FREE from
    sidecar metadata. Max depth 3, max 15 branches (Computational Arbitrage
    budget; 7B through 15 cycles beats single cloud zero-shot).
    Types: TreeSearchState, BranchCandidate, BranchScore.

  LAYER 5 CLOUD DIAGNOSTIC (~2-4%, $0.002-$0.05 per call):
    Diagnosis only — cloud never generates code. ~1000 tok package
    (spec+failed+error+mistake_book+context). Tiered:
      3A Haiku $0.002 (wrong algorithm, edge case, API misuse)
      3B Sonnet $0.01 (subtle logic, complex types, architectural)
      3C Opus $0.05 (max 1/task, CRITICAL only).
    Cloud diagnosis injected into local model as EXPERT DIAGNOSIS instruction;
    local model generates fix.
    Types: CloudDiagnosticRequest/Response, CloudTier.

  LAYER 6 CLOUD GENERATION (~0.5-1%, expensive last resort):
    Sonnet or Opus (CRITICAL only) writes actual code. Validated by same local
    pipeline T1/T2/T3+tests. BUDGET GUARD: monthly_budget tracked in SSB
    cloud_spend; daily_soft_limit = monthly/30; per_task_max default 3.
    Types: CloudGenerationRequest, CloudSpendTracker.

MISTAKE BOOK (research-grounded structured constraints, max 150 tok injection):
  Code-A1: externalized experience replay; safe with Qwen3B (no self-
  congratulatory collapse).
  CTIM-Rover WARNING: episodic NL memory degrades 42→31-40%; irrelevant
  variable names poison small-model attention. NEVER show variable names from
  failed attempts.
  Structure: MistakeEntry {attempt_number, diff_hash blake3, failure_category,
  faulty_line, root_cause_json, action_taken, timestamp}. Max 5/baby step,
  cleared on success. Prompt injection: forbidden diff hashes + diagnosis,
  zero narrative.

COMPRESSED CONTEXT REPLAY (Kimi-Dev, E-mem): wipe context every retry, never
show model its own failed CoT. Per-retry: system 50 + spec 200 + MistakeBook 150
+ code 500 + working example 300 + fix instruction 100 + reserve 100 = ~1400 tok.

GENERATION PARAMETERS (FixAudit empirical):
  FIRST_ATTEMPT 0.3/0.9 ; MICRO_REFLECTION 0.3/0.9; INTERROGATION 0.1/0.9;
  REPAIR_RETRY 1.0/1.0 (escape local minima); TREE_BRANCH 0.7/1.0/0.3.

VRAM-TIER LAYER AVAILABILITY:
  8GB: full pipeline but Layer 4 max 5 branches; Layer 5 more important.
  12GB-7B: full pipeline TQ8.
  12GB-3B: full pipeline more branches (low KV).
  16GB-7B: AB-MCTS max 20.
  24GB-14B: dual-model (14B gen + 7B verify).
  48GB-32B: 32B gen + 14B verify + 7B diagnose.
Offline mode: Layer 5 = model swap (10-15s on 8GB), Layer 6 = BubbleUp to human.

CLOUD BUDGET ($20/month): typical daily session (40 baby steps, 90% pass@1)
=~$0.01-0.05/day = ~$0.30-1.50/month. Cloud as scalpel.

GG INTRINSIC VERIFICATION (Guided by Gut, arXiv:2505.20325): sub-10B matches
32B-70B accuracy via token confidence + generation novelty. Sidecar response
extended: mean_logprob, min_logprob, entropy_mean, entropy_max — all ZERO extra
inference cost (logging what model already computes).

12 RESEARCH-GROUNDED DESIGN PRINCIPLES (Kimi-Dev stateless invocation,
ClawsBench micro-task decomposition, SVRepair deterministic localization first,
ARLCP single-sentence JSON reflection, CTIM-Rover forbidden-diffs-not-narrative,

agentic-trajectory pre-trained model preference).

offline swap UX, MistakeBook persistence scope, AB-MCTS auto-detect.

    hooks validate. Token savings: ~350/step vs structured; on 30-step task
    saves ~10,500 tok = 42% of 25K budget.
    Models: Qwen2.5-Coder native; StarCoder, DeepSeek-Coder, CodeLlama.
    Cloud models DO NOT support FIM (use structured).
    Limits: single region edits to existing files; must be in plan; max output
    length estimable.
  MODE 2 DIFF PATCH:
    For: edit_existing + multi-region.
    Model outputs unified diff directly. System parses, applies via tools
    crate 3-tier edit matching (exact → whitespace-norm → ellipsis-elision).
    Savings: ~30-50% smaller than full file for small changes. Multi-region
    support unlike FIM. Falls back to STRUCTURED on parse failure.
  MODE 3 STRUCTURED (existing): new files, complex multi-file, cloud mode,
    fallback. JSON wrapper with file path + content + action.

STREAMING VALIDATION (start before generation completes):
  Token-level: constrained decoder syntax; import validation against VERSION_GATE
  (block "use blake2::" tokens); lazy code detection (todo!/pass/unimplemented)
  via tree-sitter partial parse to distinguish code/comment/string.
  Chunk-level (~50 tokens): running tree-sitter parse attempt; abort if
  structural impossibility (unclosed brace growth); token budget tracking
  (>2x expected = degenerate).
  Early termination saves ~90% of generation time for bad attempts.

PIPELINE PARALLELISM (BSP supersteps support, depth=1):
  While step N validates → pre-assemble context for N+1 (plan, knowledge
  queries, FIM/diff prompt). Saves 100-500ms per step on ~88% pass-rate path.
  Adaptive: disable pre-assembly if pass rate <80%.
  NOT speculative execution of LLM. Only context assembly is pipelined.

SPECULATIVE FILE ROUTING: plan specifies target_file + edit_region; model never
specifies path. On mismatch (AST unresolved import suggests new module):
orchestrator creates micro-step "create {path} with {type}" in STRUCTURED, then
retries original step. Max 2 micro-steps per baby step.

DEPENDENCY MANAGEMENT (deterministic, model writes only code with imports):
  Detection per-language (parse Cargo.toml/pyproject/pkg.json vs imports).
  Resolution: identify name → check deprecated_patterns substitution → registry
  query → conflict check → add manifest → install. Model NEVER runs
  cargo add/pip install. Approval gate (existing rule); autonomous auto-approve
  if in allowlist or already transitive.

TOKEN BUDGET IMPACT: FIM ~350 tok/step + streaming early-term 50-200 + parallelism
free → ~6800 tok / 30-step MEDIUM = 27% of 25K freed for code context. Combined
with ShortCoder 18-38% reduction = ~45-65% effective context increase.
Difference between "3B struggles at 25 LOC" and "3B handles 40 LOC comfortably."

INTEGRATION: cloud mode → always STRUCTURED (overhead negligible at 200K);
token-efficiency = complementary; reasoning architecture = generation HOW changes
not diagnosis HOW; MistakeBook constraints injected into FIM prefix as comments;
code-completeness = streaming validation catches lazy code during generation.

7 NEW A-STEPS A-51..A-57 (FIM, diff parser, mode selection, streaming, parallelism,
dependency, file routing). 4-5 sessions.

4 RISKS: FIM quality on small models (benchmark vs structured, disable if -10pp);
diff parsing failures (3-tier matching fallback to STRUCTURED, track rate);
streaming false positives (AST-aware, only flag in code positions); pipeline
parallelism waste (adaptive depth).

16) compiled-pipeline-design.txt    (2026-04-16)
========================================================================
Stolen from Compiled AI (arXiv 2604.05150), Sema Code (arXiv 2604.11045),
Agent RuleZ. Four gaps in current spec, each solved by external proven design.

GAP 1: REPEATED PIPELINE EXECUTION COSTS TOKENS EVERY TIME.
GAP 2: LONG-RUNNING TOOL CALLS BLOCK PIPELINE.
GAP 3: TOKEN COUNTING USES ESTIMATES NOT ACTUALS.
GAP 4: ORACLE EXTRACTION LACKS STRUCTURAL GUARANTEES.

DESIGN 1 — COMPILED PIPELINE EXECUTION:
  When template validated N=3 times with 100% success: "compile" → deterministic
  script that replays exact file ops/edits/validations without LLM. Compiled AI:
  4.5ms P50 vs 2004ms; 57x token reduction; 100% reproducibility; break-even
  after ~17 executions.
  3 components in orchestrator/:
    TEMPLATE CRYSTALLIZER — monitors template outcomes; extracts deterministic
      skeleton (ordered list of CREATE_FILE/EDIT_REGION/RUN_COMMAND); identifies
      VARIABLE regions (per-invocation) and FIXED regions (boilerplate);
      produces CompiledPipeline.
    COMPILED PIPELINE struct {template_id, source_executions[], steps[],
      variables[], validation_commands[], confidence}.
    COMPILED EXECUTOR — resolves TemplateVariables (USER_INPUT, PROJECT_PROFILE,
      DKG_QUERY); substitutes + writes + validates; ANY fail → DECOMPILED, fall
      back to LLM, decrement confidence. Decompilation trigger: 2 consec fails
      OR confidence <0.7.
  Eligibility (computed): all_source_L1_only AND variable_region_ratio<0.3 AND
    no_replan AND template_rank.first_try_ratio==1.0.
  Not eligible: novel logic, codebase-state-dependent output, MEDIUM+ complexity,
    used reasoning L3+. Compiled execution: 0 LLM tokens, ~1-10s, $0.

DESIGN 2 — REACTIVE BACKGROUND TAKEOVER (Sema Code mechanism 8):
  When tool call exceeds soft timeout (30s build, 60s test): detach to
  BackgroundTaskManager, return BackgroundTaskId, orchestrator continues with
  next independent step, polls (5s→10s→30s), result injected at next superstep
  boundary as SSB entry (preserves BSP determinism).
  Constraints: max 3 concurrent; hard timeout = 5x soft; inherits BashSandbox
  Tier B/C; autonomous only (interactive shows progress instead).
  BackgroundTask {id, command, started_at, detached_at, pid, output_file,
  status}.

DESIGN 3 — CUMULATIVE TOKEN TRACKING:
  Sidecar already returns usage.prompt_tokens / completion_tokens. Cloud
  providers (Anthropic, OpenAI) return same. Currently parsed by providers but
  not fed to context budget. Add CumulativeTokenTracker {prompt/completion total,
  cache_read, cache_write, last_response_*}. If actual > estimated*1.1
  recalibrate estimate scaling. Sidecar HEALTH_SNAPSHOT carries actual count.
  Negligible per-turn savings; real value = accuracy (estimates drift 5-10%).

DESIGN 4 — SAFETY SANDWICH (Compiled AI healthcare prior-auth pattern):
  For Oracle Mode fact extraction:
  Phase 1 DETERMINISTIC: validate input, classify source tier, reject T4,
    rate limits. No LLM.
  Phase 2 CONSTRAINED AGENTIC: LLM extracts with JSON schema enforcement.
    Required: claim<200, exact_quote min 10, source_url uri, confidence enum.
    additionalProperties=false. Model CANNOT produce facts missing required.
  Phase 3 DETERMINISTIC: validate facts against source tier; verify exact_quote
    appears as substring in source text (normalize whitespace, fuzzy Levenshtein
    <5% fallback); FABRICATED facts excluded. No LLM.
  Plus source content cache (LRU 100 pages 50KB). Fabrication_rate metric per
  model; >20% escalate extraction to cloud.

Implementation: C-1..C-5 post-Phase-4 (5-6 sessions). Extends pipeline-factory
(4D), tools/BashSandbox (4B/4G), providers+context budget (3E/3J), Oracle (4D).
Risks: compiled output wrong on changed codebase (validation always runs,
auto-decompile); background tasks compete resources (deprioritize nice +10);
token tracking diverges (actual = ground truth, recalibrate estimate); quote
verification whitespace/encoding false negatives (normalize + fuzzy).

17) testing-trust-design.txt    (2026-04-19 rev 3, post-MVP)
========================================================================
PROBLEM: SCOPE-OF-TEST DRIFT — LLM test can compile, hit 100% coverage, pass
every run, and assert on the WRONG behavior. When same model writes test + impl,
both wrong in same direction still pass TESTING_FIRST gate.

9 PROBLEMS + 1 META-TRUST GAP:
  P1 COVERAGE LIES (Meta ACH: 32% cov vs 15% mutation; MutGen 100% cov / 4%
     mutation; AdverTest plateau ~95% cov / 52% mutation).
  P2 PLAUSIBILITY BIAS (LLMs optimize likelihood not correctness;
     arXiv:2512.16750 shows structural to next-token prediction). + BDG trap
     (same model two prompts agree on wrong answer — defeats naive differential).
  P3 CO-DRIFTING TESTS+CODE (same session, correlated failures).
  P4 DEAD WIRING — (a) placeholder-on-dispatch (None/Synthetic*/NoOp*/Empty* on
     production fields), (b) dual-entry divergence (CLI wires X, dashboard
     skips), (c) emitter-without-consumer. Oracle = callgraph, not output.
  P5 NON-DETERMINISTIC INFERENCE — temp=0 fallacy. Float non-associativity under
     dynamic batching + GPU-class divergence + provider routing patches.
     Without determinism, every other layer is noisy.
  P6 GROUNDING HALLUCINATION (GhostCite 2026: 14-95% hallucination over 375K
     instances) — fabricated arXiv IDs, paper titles, API refs, file paths,
     version numbers. Plausibility bias produces wrong CODE; this produces
     wrong EVIDENCE about code.
  P7 MULTI-AGENT STATE DRIFT (MLR-Bench: 80% chains emit invented experiments).
     Append-only SSB but no version anchor on reads.
  P8 REWARD HACKING UNDER SELF-MOD — Phase 4H drifts toward whatever metric the
     signal optimizes (gate-relaxation, trivial mutant killing).
  P9 CALIBRATION GAP (Rulebreakers) — LLM "I'm uncertain" / "high confidence"
     uncorrelated with error risk; "zero BLOCK findings" verdict = "auditor
     didn't recognize anything wrong" ≠ "code is correct."
  M1 UNVERIFIABLE PROVENANCE — meta-trust gap. Closed by Layer 5.5.
Cross-references P1..P25 sub-failure matrix in source file.

DESIGN PRINCIPLE: stack complementary oracles so an LLM error must survive every
filter. Oracle types: DETERMINISM, REACHABILITY, RUNTIME-OBSERVE, REFERENCE,
INVARIANT, TRANSFORM, DISCRIMINATION, SPECIFICATION, INTENT, CITATION,
PAIRED-ACCURACY, COVERAGE.

  LAYER -1 INFERENCE DETERMINISM (substrate, pre-everything):
    D-1 HARDWARE-CLASS LOCK ([inference.hardware] declares one SKU; sidecar
        refuses mismatch).
    D-2 BATCH-INVARIANT KERNELS (CRITICAL only; TBIK unified binary-tree
        reduction; accept up to 56% throughput penalty).
    D-3 LAYERCAST COMPUTE DTYPE (BF16 storage + FP32 compute; mitigates 9%
        accuracy / 9000-token swing on R1-7B).
    D-4 PREFIX-CACHE HYGIENE (blake3 not xxhash-128 for cache key; pinned
        caching manager; pre-hash whitespace normalize).
    D-5 TEMP=0 + SEED + FINGERPRINT PIN (top_k=1, project-pinned seed, verify
        provider system_fingerprint per request, DETERMINISM_DRIFT SSB log).
    D-6 LLM-42 SPECULATIVE VERIFIED DECODING (optional; <11% overhead vs fully
        deterministic).
    D-7 FACET R-DAG tool-call determinism (compiled AST contract per tool arg
        schema; reject mismatched emissions; no silent retry; replaces try/
        catch+JSON-retry).
    Framework selection: vLLM (batch-invariant kernels) primary; llama.cpp
    PR#16016 CPU fallback; SGLang second choice; TGI BLOCKED (maintenance).
    DIGITAL SIBLING (CRITICAL): parallel sidecar same config on dedicated GPU;
    primary vs sibling divergence on same prompt = BLOCK.
    Driver: EU AI Act Art. 13. Cost: near-zero standard; +30-56% latency
    CRITICAL + 1 GPU for sibling.

  LAYER 0 WIRING CONTRACT (PLANNING + ACCEPTANCE):
    Two complementary sub-mechanisms:
    APPROACH A STRUCTURAL: BabyStepSpec 9th block WIRING_CONTRACT
