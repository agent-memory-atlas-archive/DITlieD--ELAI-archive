6. REASONING ARCHITECTURE (reasoning-architecture-design.txt)
   No new phase. Integrates into 4B/4D/4E/4G. Extensions to 3E/3F/3J.
========================================================================

  FULL SPEC: docs/specs/guide/reasoning-architecture-design.txt
  READ before implementing any change below. Key sections:
    LAYER 1: Deterministic Error Reasoning (FailureTaxonomy expansion, DKG
      localization, fix template generation, DiagnosticResult types)
    LAYER 2: Micro-Reflection (500-token context, JSON-constrained output,
      MicroReflectionRequest/Response types)
    LAYER 3: Interrogation Tree (language-parameterized Q&A, QuestionNode,
      InterrogationTree types, rules.db storage)
    LAYER 4: AB-MCTS Tree Search (branching at failure, GG intrinsic scoring,
      TreeSearchState, BranchCandidate, BranchScore types)
    LAYER 5-6: Cloud Diagnostic/Generation (tiered escalation, CloudTier,
      CloudSpendTracker, budget economics)
    MISTAKE BOOK: structured constraint store in SSB, MistakeEntry type
    COMPRESSED CONTEXT REPLAY: fresh 1400-token assembly per retry
    GG INTRINSIC VERIFICATION: token confidence + generation novelty signals
    GENERATION PARAMETERS: per-profile temperature/top-p settings
    VRAM-TIER CONFIGURATIONS: layer availability per hardware tier
    INTEGRATION section: per-phase change list

  EXISTING PHASE FILES TO UPDATE:

  steps/phase-3E.txt (Context Budget Allocator)
    Add: REPAIR_CONTEXT SlotWeights profile for reasoning pipeline retries
    Add: Different slot allocation for retry context vs first-attempt context
    Scope: new SlotWeights variant, profile selection logic. ~100 LOC.

  steps/phase-3F.txt (Rules Engine)
    Add: InterrogationTree data storage in rules.db (language-parameterized)
    Add: Self-discovery extension for new FailureTaxonomy categories
    Add: When auditor finds recurring error pattern 3+ times, auto-propose
      new FailureTaxonomy category + fix template (Layer 1 expansion)
    Scope: new table schema, new seed data format. ~150-200 LOC.

  steps/phase-3J.txt (Sidecar + Providers)
    Add: mean_logprob and entropy_mean fields in sidecar response JSON
    Add: GG intrinsic signals computed during generation at zero extra cost
    Scope: sidecar response extension. ~30 LOC (Python + Rust client).

  steps/phase-4B.txt (Tools — future, not yet built)
    Add: FailureTaxonomy expansion with structured RootCause output per category
    Add: SVRepair-style CFG analysis as optional deep localization step
    Add: DiagnosticResult, RootCause, RootCauseKind types
    Add: 3 new FailureTaxonomy categories: LAZY_CODE, EMPTY_BODY, FILE_SIZE_EXCEEDED
    Scope: ~300-400 LOC.

  steps/phase-4D.txt (Pipeline Factory L1 — future)
    Add: Designer marks COMPLEXITY_HIGH baby steps (>3 files, core types, public API)
    Add: High-complexity steps get larger AB-MCTS budget (10 vs 5 branches)
    Add: Automatic few-shot injection for high-complexity steps
    Add: Lower escalation threshold (2 retries vs 3 before Layer 5)
    Scope: ~100-150 LOC.

  steps/phase-4E.txt (Pipeline Factory L2 — future)
    Add: BubbleUpAction::DiagnoseAndRetry (invoke reasoning pipeline before Redecompose)
    Add: BubbleUp integrates with reasoning layers:
      baby step fails after Layer 4 -> BubbleUp to Step (redecompose)
      baby step fails after Layer 6 -> BubbleUp to Phase (replan)
      phase fails -> BubbleUp to Concept (research alternative)
    Scope: new BubbleUpAction variant, integration logic. ~200 LOC.

  steps/phase-4G.txt (Autonomous Mode — future)
    Add: AutoAdvanceEvaluator checks reasoning pipeline exhaustion
    Add: Layers 1-4 exhausted -> auto-escalate to Layer 5 (if cloud enabled)
    Add: Layers 1-6 exhausted -> escalate to human (INTERACTIVE gate)
    Add: CloudSpendTracker in escalation policy:
      budget >50%: auto-escalate freely
      budget 20-50%: escalate only CRITICAL baby steps
      budget <20%: WARN, prefer offline fallback
    Scope: new escalation logic, spend tracking. ~200-300 LOC.

  NO NEW STEP FILES NEEDED:
    The reasoning pipeline is NOT a separate phase. It integrates into
    the existing error recovery path across 4B/4D/4E/4G. The MistakeBook
    is an SSB table, not a new crate. The compressed context replay is a
    new profile in the existing context budget allocator.
