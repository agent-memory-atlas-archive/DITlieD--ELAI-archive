PHASE 4K: DASHBOARD (Tauri MVP — desktop app with embedded webview)
Prerequisites: Phase 3A (FSM), Phase 3B (SSB), Phase 3J (CLI wired)
  Phase 4A-4J recommended but not strictly required (dashboard reads SSB,
  which exists from 3B. Phase 4 features populate SSB with richer data.)

SCOPE: see docs/specs/guide/implementation-guide.txt

GOAL
Build a native desktop UI for ELAI using Tauri v2. One interaction pattern
for MVP: interactive mode (user drives, ELAI executes with approval gates).
The UI is NOT a chatbot — it is a structured control surface where every
input routes through FSM classification.

Tech stack: Tauri v2 (tauri = "2.10", tauri-build = "2.5") desktop app.
  Rust backend: SsbViewer queries called directly via #[tauri::command].
  Frontend: Svelte in Tauri webview (small, reactive, good Tauri fit).
  No HTTP server. No REST API. No WebSocket. No CORS. No port management.
  Data flow: frontend polls SsbViewer via Tauri invoke() every 500ms.
  Distribution: single .exe via cargo tauri build (bundles WebView2 on Windows).

GROUNDING:
  tauri crate verified on crates.io: v2.10.3 (2026-04-16).
  tauri-build: v2.5.6. tauri-cli: v2.10.1.
  Tauri v2 uses #[tauri::command] for Rust-to-JS IPC (no HTTP layer).
  Svelte is a first-class Tauri frontend (create-tauri-app supports it).
  Source: https://crates.io/crates/tauri, https://v2.tauri.app/

Visual identity: teal primary (#1B7A6E) on dark charcoal (#0f1318).
Monospace typography (JetBrains Mono). Information density over whitespace.
Full spec in dashboard-design.txt VISUAL IDENTITY section.
These apply identically to Tauri webview (it renders HTML/CSS/JS).

RISKS TO WATCH
  Risk 1: SSB schema drift. Dashboard queries SSB directly. If SSB action_types
    or payload schemas change in a later phase, dashboard breaks silently.
    Mitigation: typed query functions in SSB viewer library (4K.1) with compile-time
    checked deserialization. Schema change = compile error, not runtime failure.
  Risk 2: WebView2 runtime on Windows. Tauri v2 requires WebView2 (Edge-based),
    pre-installed on Windows 10 1803+ and all Windows 11. Older Windows or
    locked-down enterprise machines may not have it.
    Mitigation: Tauri bundler includes WebView2 bootstrapper in .exe installer.
    Document requirement in README. Test on clean Windows 11 VM.
  Risk 3: Bundle size. Tauri .exe includes Rust binary + WebView2 bootstrapper.
    Typical Tauri v2 app: 3-8MB installer on Windows. Acceptable for MVP.
    Mitigation: strip debug symbols in release. Frontend budget: <100KB JS.
  Risk 4: Tauri CLI build dependency. cargo tauri build requires @tauri-apps/cli
    (npm) or cargo-tauri (cargo install). Dev setup has two package managers.
    Mitigation: document setup in 3 lines. CI can use cargo-tauri directly.
  Risk 5: 500ms polling instead of push. During heavy execution (100+ SSB
    writes/sec), UI updates at 2 Hz max. Acceptable for MVP — user sees
    activity feed update every half second, which feels live enough.
    Upgrade path: Tauri v2 supports event emission from Rust to frontend
    via app.emit("event", payload). Add SSB write hook later for true push.


STEPS

  4K.1 SSB READ-ONLY VIEWER LIBRARY (Rust, data extraction)
    PRE_GATE:
      - Phase 3B SSB exists: cargo test -p orchestrator --lib -- ssb (exit 0)
      - SSB database has data: grep -r "SsbAction" .elai_cc/crates/orchestrator/src/ returns matches
      - cargo build --workspace succeeds
    TASK:
      - SsbViewer struct: opens read-only WAL connection to SSB SQLite database.
        Separate connection pool from orchestrator's write connection.
        Read-only enforced at SQLite level (SQLITE_OPEN_READONLY).
      - Typed query functions (all return Result<T, SsbViewerError>):
          latest_fsm_state() -> FsmState
          active_session() -> Option<SessionInfo>
          phase_progress() -> Vec<PhaseStatus>  (phase_id, status, step_count, completed_count)
          recent_actions(limit: usize) -> Vec<SsbActionSummary>  (timestamp, action_type, agent_id, summary)
          agent_actions(agent_id: AgentId) -> Vec<SsbActionSummary>
          pending_interventions() -> Vec<InterventionRequest>  (from INTERVENTION_REQUEST)
          file_changes(session_id: SessionId) -> Vec<FileChange>  (path, action, diff_summary)
          reasoning_chain(step_id: StepId) -> Vec<ThinkStepSummary>  (step_type, content, grounding)
      - New SSB action types (add to existing 17, MVP subset only):
          INTERVENTION_REQUEST: { step_id: StepId, intervention_type: InterventionType,
            description: String, diff_summary: Option<DiffSummary>, options: Vec<InterventionOption> }.
            InterventionType enum { ApproveChange, ReplanApproval, ErrorRecovery }.
            InterventionOption enum { Accept, Decline, Retry(String), Skip }.
          INTERVENTION_RESPONSE: { request_id: SsbSeq, chosen: InterventionOption,
            user_note: Option<String> }.
      - Deferred to post-MVP: HEALTH_SNAPSHOT (needs MONITOR window), WINDOW_STATE
        (needs session recovery), health_snapshot() query, window_state() query,
        cost_summary() query. These belong to post-MVP dashboard completion (Group C).
      - SsbActionSummary: lightweight projection (no full payload deserialization
        unless client requests detail). Summary is first 100 chars of payload.
      - Pagination: all list queries support offset + limit.
      - Performance target: any single query < 10ms on 100K SSB rows.
    DETERMINISTIC_CHECK:
      - cargo check -p orchestrator (exit 0, new types compile)
      - grep -r "SsbViewer" .elai_cc/crates/orchestrator/src/ | wc -l  >= 1
      - grep -r "INTERVENTION_REQUEST" .elai_cc/crates/orchestrator/src/ | wc -l  >= 1
      - grep -r "INTERVENTION_RESPONSE" .elai_cc/crates/orchestrator/src/ | wc -l  >= 1
    ADVERSARIAL:
      - If SsbViewer opens a read-write connection, it could corrupt orchestrator's
        WAL state. Test: attempt INSERT via SsbViewer connection -> SQLite error.
      - If SsbActionSummary deserializes full payload for every row in recent_actions(),
        large histories will be slow. Test: 10K rows query < 50ms.
    ACCEPTANCE:
      - SsbViewer opens read-only connection, all 8 query functions return typed data.
      - 2 new SSB action types compile with typed payload structs.
      - Round-trip test: write INTERVENTION_REQUEST via orchestrator, read via SsbViewer.
