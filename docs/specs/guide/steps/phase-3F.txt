Prerequisites: Phase 3D complete (parallel with 3E).
  Implicit: Phase 1A complete (tree-sitter available in knowledge/ crate for AST_PATTERN).

GOAL
Deterministic rule enforcement replacing probabilistic prompt-based rules.
Predicate DSL with 5 types. Self-discovery from auditor violation patterns.
Rules are DATA in SQLite, evaluated by Rust interpreter.
Three-tier enforcement: Tier 1 (deterministic code), Tier 2 (constrained decoding),
Tier 3 (prompt guidance + auditor backup).

ARCHITECTURE DECISION: TREE-SITTER DEPENDENCY
  AST_PATTERN predicates require tree-sitter query evaluation.
  Phase 1A adds tree-sitter to knowledge/ crate (DKG uses it for code graph).
  Rules/ crate MUST NOT add a separate tree-sitter dependency.
  Instead: knowledge/ exposes a tree-sitter-facade module (query compilation + evaluation).
  Rules/ depends on knowledge/ for AST evaluation only.
  Crate map already shows: rules/ depends on core/ only.
  This means either: (a) rules/ adds knowledge/ as dependency, or
  (b) AST evaluation is delegated to knowledge/ via a trait (AstEvaluator).
  Option (b) preserves the current dependency graph. Recommended.
  Trait: knowledge::AstEvaluator { fn evaluate_query(lang, source, query) -> Vec<Match> }
  Rules/ takes Box<dyn AstEvaluator> at construction time. Testable with mock.

PREDICATE EVALUATION ORDER
  When multiple rules are active, evaluate in this order (cheapest first, short-circuit on BLOCK):
    1. METRIC_GATE  -- O(1) numeric comparison, no parsing
    2. GREP_PATTERN -- O(n) regex on raw text, no AST
    3. AST_PATTERN  -- requires tree-sitter parse (amortized if cached per-file)
    4. COMPOSITE    -- recursive, depends on children
  Within same type: sort by severity DESC (BLOCK rules before WARN).
  Short-circuit: first BLOCK verdict stops evaluation, returns immediately.
  WARN collection: accumulated WARN verdicts before a BLOCK are preserved in the
    response alongside the BLOCK. The BLOCK verdict carries all prior WARNs as context.
  Rationale: METRIC_GATE and GREP are 10-100x cheaper than AST parse.
    Evaluating cheap rules first means most BLOCK verdicts resolve without AST cost.

3F.4 RULE LIFECYCLE STATE MACHINE
  PRE_GATE:

  TASK:
    - Implement lifecycle: PROPOSED -> CANDIDATE -> SHADOW -> ACTIVE -> RETIRED
    - Transition guards (all deterministic arithmetic, no LLM):
      PROPOSED -> CANDIDATE: >= 3 contract tests AND all pass
      CANDIDATE -> SHADOW: contract tests pass AND human approves predicate logic
        (OR independent second-auditor verifies — finding-source auditor CANNOT approve)
      SHADOW -> ACTIVE: false_positive_rate < 5% AND true_positive_rate > 80%
        AND counterfactual_causal_rate > 50% AND no safety regressions
      ACTIVE -> RETIRED: false_positive_rate > 30% over 10 pipelines,
        OR superseded, OR human request
    - Safety invariant: mutable=0 rules reject auto-retirement
    - Safety invariant: mutable=0 rules exempt from causal rate gate (human-promotable only)
    - Every transition logged with timestamp, metrics snapshot, and reason
  DETERMINISTIC_CHECK:
    - cargo test -p rules --lib -- lifecycle 2>&1 | grep "test result: ok"
    - PROPOSED -> CANDIDATE with 2 tests returns Err (need >= 3)
    - PROPOSED -> CANDIDATE with 3 passing tests returns Ok
    - SHADOW -> ACTIVE with false_positive_rate=6% returns Err (gate: fpr < 5%)
    - SHADOW -> ACTIVE with true_positive_rate=79% returns Err (gate: tpr > 80%)
    - SHADOW -> ACTIVE with counterfactual_causal_rate=49% returns Err (gate: ccr > 50%)
    - SHADOW -> ACTIVE with safety_regression=true returns Err (gate: no regressions)
    - SHADOW -> ACTIVE with all thresholds met returns Ok
    - CANDIDATE -> SHADOW with source=AUDITOR approval by same auditor returns Err (circular trust)
    - CANDIDATE -> SHADOW with human approval returns Ok
    - mutable=0 rule + auto-retire attempt returns Err
    - Transition log entry written to DB for each successful transition
  ADVERSARIAL:

    - If RETIRED rules are deleted instead of kept, historical audit trail is lost.
      Test: retire a rule, verify it still exists in DB with status=RETIRED.
    - If PROPOSED rules from source=AUDITOR auto-promote, circular trust (auditor validates own rules).
