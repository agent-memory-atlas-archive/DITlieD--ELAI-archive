PHASE 3B: SSB (SHARED STATE BOARD)
Prerequisites: Phase 3A complete (full FSM with all 9 states, evidence gates, INTERACTIVE gating)

SCOPE: see docs/specs/guide/implementation-guide.txt

GOAL
Inter-agent communication via SQLite WAL with single-writer guarantee.
All agent writes go through SSB. Append-only within session.
SSB is the backbone for inter-agent state: every tool result, finding, claim,
checkpoint, and phase transition is recorded here. Downstream phases (1C vector
cache invalidation, 3C agent system, 3D BSP supersteps, 3E context budget) all
depend on the interface defined here.

A single Ssb instance is permanently bound to one (project_id, session_id) pair.
Multi-session scenarios (e.g., Phase 3D superstep replay from a different session)
require a new Ssb instance. This is by design: prevents agent forgery of these fields.

RISKS TO WATCH
  R10: SSB write throughput ceiling.
    Claim: 50K inserts/sec. Verified: 80K achievable with optimized pragmas
    (WAL + synchronous=NORMAL + mmap). Agent rate ~1-10/sec. 50x+ headroom.
    Fallback: batch writes in single transaction (risk-register.txt R10).
  R-3B-1: WAL checkpoint interference.
    SQLite auto-checkpoints WAL at 1000 pages by default. During checkpoint,
    readers may briefly block. Mitigation: wal_autocheckpoint=1000 (default),
    manual checkpoint only between supersteps (Phase 3D boundary).
  R-3B-2: r2d2 connection pool WAL file cleanup.
    r2d2 default idle_timeout closes connections. When the last connection closes,
    SQLite removes the WAL file, causing errors for other connections.
    Source: r2d2-sqlite GitHub discussions.
    Mitigation: disable idle_timeout and max_lifetime on the read pool.
  R-3B-3: Schema migration on CHECK constraint change.
    Adding action_types to CHECK constraint on existing ssb.db requires table rebuild
    (SQLite has no ALTER TABLE MODIFY CONSTRAINT). CREATE TABLE IF NOT EXISTS silently
    no-ops on existing DB with stale schema. Mitigation: PRAGMA user_version tracking
    with migration codepath (drop + recreate is acceptable since SSB is session-scoped).

SCHEMA (from orchestrator.txt Section 3, inline for implementer reference)
  PRAGMA user_version = 1;  -- increment on schema changes, migration codepath checks this

  CREATE TABLE ssb (
    seq         INTEGER PRIMARY KEY AUTOINCREMENT,
    project_id  TEXT NOT NULL,
    session_id  TEXT NOT NULL,
    agent_id    TEXT NOT NULL,
    superstep   INTEGER NOT NULL DEFAULT 0,
    action_type TEXT NOT NULL CHECK(action_type IN (
      'file_write', 'file_read', 'tool_result', 'test_outcome', 'finding',
      'claim', 'checkpoint', 'model_swap', 'phase_transition',
      'knowledge_degradation', 'isolation_metric', 'plan_update',
      'replan_request', 'stub_reference', 'reasoning_trace',
      'phase_complete', 'memory_monitoring'
    )),
    payload     BLOB NOT NULL,
    created_at  INTEGER NOT NULL
  );
  CREATE INDEX idx_ssb_project   ON ssb(project_id);
  CREATE INDEX idx_ssb_session   ON ssb(session_id);
  CREATE INDEX idx_ssb_superstep ON ssb(superstep);
  CREATE INDEX idx_ssb_conflict  ON ssb(project_id, superstep);

  CREATE TABLE ssb_files (
    seq       INTEGER NOT NULL REFERENCES ssb(seq),
    file_path TEXT NOT NULL
  );
  CREATE INDEX idx_ssb_files_path ON ssb_files(file_path);
  CREATE INDEX idx_ssb_files_seq  ON ssb_files(seq);

  Note: orchestrator.txt Section 3 lists 9 action_types in its synopsis (line 57-58).
  The full set of 17 is derived from cross-referencing all spec sections that define
  action_types: Section 7A (reasoning_trace), Section 7 (isolation_metric),
  Section 8 (plan_update, replan_request), Section 9 (stub_reference),
  knowledge.txt (knowledge_degradation), technical-analysis-v3.txt Concern 2
  (phase_complete — atomic durability marker at phase boundary),
  orchestrator.txt Section 11 (memory_monitoring).
  Orchestrator.txt Section 3 synopsis is incomplete — treat THIS schema as canonical.

ACTION_TYPE ENUM (Rust side)
  Implement as a Rust enum with serde Serialize/Deserialize. 17 variants matching
  the CHECK constraint above. Use #[serde(rename_all = "snake_case")].
  Typed payload per action_type: define SsbPayload enum with per-type structs
  validated at write time (BLOCK 8 fix: no opaque BLOBs without schema).

CONFLICT DETECTION QUERY (corrected — requires JOIN)
  ssb_files has only (seq, file_path). Columns agent_id, session_id, superstep
  are in ssb table. The query from orchestrator.txt Section 3 is shorthand.
  Correct SQL:
    SELECT DISTINCT ssb.agent_id
    FROM ssb_files
    JOIN ssb ON ssb_files.seq = ssb.seq
    WHERE ssb_files.file_path IN (rarray(?1))
      AND ssb.project_id = ?2
      AND ssb.session_id != ?3
      AND ssb.superstep = ?4
  Uses rusqlite array feature (rarray) for IN clause to preserve statement caching.
  Filters by project_id to prevent cross-project false positives (BLOCK 5 fix).
  idx_ssb_conflict compound index supports this query at scale.

WAL CONFIGURATION (required pragmas, order matters)
  PRAGMA journal_mode = WAL;
  PRAGMA synchronous = NORMAL;
  PRAGMA wal_autocheckpoint = 1000;
  PRAGMA busy_timeout = 5000;
  PRAGMA cache_size = -64000;    -- 64MB cache
  PRAGMA foreign_keys = ON;
  PRAGMA temp_store = MEMORY;
  Source: sqlite.org/wal.html, powersync.com benchmarks (80K inserts/sec with these).
  busy_timeout handles SQLITE_BUSY without manual retry for most cases.
  synchronous=NORMAL is safe with WAL (data survives app crash, not OS crash).

  IMPORTANT: foreign_keys is a per-connection pragma, not database-level.
  Must be applied to EVERY connection via r2d2 CustomizeConnection trait.
  Both the single writer connection and all read pool connections need this.
  Source: sqlite.org/pragma.html (foreign_keys section).

  3B.2 SINGLE-WRITER CHANNEL + WRITE PATH
    PRE_GATE:
      - Step 3B.1 skeleton compiles:
        cargo check -p orchestrator 2>&1 | grep "Finished"
    TASK:
      - Implement the write loop: tokio::spawn a task that receives SsbWriteRequest
        from mpsc channel and executes INSERT within a transaction.
      - SsbWriteRequest: { action_type, agent_id, superstep, payload, files: Vec<String> }
        Session_id and project_id injected by the writer (set at Ssb construction).
        created_at: use ClockProvider trait from core/ (core.txt L68-82).
        Inject via RuntimeContext.clock, never SystemTime::now().
      - Write path:
        1. BEGIN IMMEDIATE (acquire write lock early to avoid SQLITE_BUSY mid-transaction)
        2. INSERT INTO ssb (...) VALUES (...)
        3. For each file in files: INSERT INTO ssb_files (seq, file_path) VALUES (last_insert_rowid(), ?)
        4. COMMIT
        5. Broadcast SsbEntry on the broadcast channel (after commit, never before)
      - Return seq to caller via oneshot channel.
      - IPC sync requirement (WARN-6): SSB write MUST complete before ToolResult
        is dispatched to the agent. The write method is async but the caller must
        .await the seq confirmation before proceeding. Document this contract.
      - Implement Ssb::write(request) -> Result<i64> that sends to channel and
        awaits the oneshot response. After shutdown(), returns Err (channel closed).
      - Shutdown protocol: Ssb::shutdown() drops the mpsc::Sender, write loop drains
        remaining messages, then exits. Any write() call that has already sent to the
        channel but not received the oneshot response gets Err(SsbShutdown).
        Shutdown is idempotent (second call is no-op).
    DETERMINISTIC_CHECK:
      - cargo test -p orchestrator --lib ssb::tests::test_single_writer 2>&1 | grep "ok"
      - cargo test -p orchestrator --lib ssb::tests::test_write_after_shutdown 2>&1 | grep "ok"
      - Unit test: spawn 10 concurrent write tasks, assert all seqs are sequential
        and no SQLITE_BUSY errors occur.
    ADVERSARIAL:
      - If BEGIN IMMEDIATE is not used and two write requests arrive simultaneously,
        the second may get SQLITE_BUSY at COMMIT time (wasted work).
        Test: remove BEGIN IMMEDIATE, send 100 concurrent writes, count SQLITE_BUSY errors > 0.
      - If the mpsc channel is bounded and full, writes block. Use unbounded_channel
        for the write path (backpressure handled by agent rate << throughput ceiling).
        Test: send 10K writes rapidly, assert none are dropped.
      - If created_at uses wall clock instead of ClockProvider, deterministic replay breaks.
        Test: inject mock ClockProvider, assert created_at matches mock value.
      - If broadcast happens before COMMIT and transaction rolls back, subscribers see
        phantom entries. Test: simulate transaction failure, assert no broadcast emitted.
      - If write loop panics (e.g., SQLite corruption), oneshot receivers hang.
        Test: drop write loop handle, assert write() returns Err within 1 second.
    ACCEPTANCE:
      - 10K sequential writes complete without error
      - All seqs monotonically increasing with no gaps
      - created_at uses ClockProvider (core.txt L68), not SystemTime::now()
      - Broadcast emitted only after successful COMMIT
      - write() after shutdown() returns Err
      - No oneshot receivers hang on write loop termination
