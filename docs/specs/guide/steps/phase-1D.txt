PHASE 1D: PAGERANK REPO MAP
Prerequisites: Phase 1C complete (cargo check --package knowledge exits 0 with ort integrated)

SCOPE: see docs/specs/guide/implementation-guide.txt

GOAL
Rank code symbols by importance using PageRank on DKG graph.
Produce token-budget-fitted repo maps for context loading.

RISKS TO WATCH
  R20 (risk-register.txt:L88): PageRank density degradation. Density guard at 0.3 threshold.
    NOTE: R20 is also used in phase-0.txt:L22 for "entropy quarantine scope" — ID collision.
    This phase refers to the risk-register.txt definition (PageRank density degradation).
    ACTION NEEDED: renumber one of the two R20s in a cross-file cleanup (out of scope for this phase).
  R-NEW: Dangling nodes (leaf symbols with no outgoing edges) get zero rank in naive power iteration.
    Code graphs have many leaves (constants, utility functions, config structs). Without dangling node
    redistribution, these vanish from repo maps entirely. Source: aider uses dangling=personalization
    to redistribute. NetworkX docs confirm: "dangling nodes are given outedges according to the
    personalization vector." Mitigation: pass dangling vector = personalization vector in power iteration.
  R-NEW: Orphan symbols (defined but never referenced) get zero rank and vanish from results.
    Source: aider adds self-edges (weight=0.1) for defined-but-unreferenced symbols. Without this,
    a newly-added function that nothing calls yet is invisible to the repo map.
    Mitigation: add self-edges in adjacency matrix construction.

      - Implement DkgSnapshot::from_engine: query dkg_nodes and dkg_edges tables, build in-memory vectors.
      - Implement compute_repo_map:
        1. Build adjacency matrix from DkgSnapshot.edges
           - Self-edges (weight=0.1) already present from DkgSnapshot::from_engine for orphan nodes.
           - Apply sqrt(ref_count) scaling to edge weights. Source: aider uses sqrt(num_refs) to prevent
             high-reference symbols (Result, Error, String) from dominating rankings. Proof: test T17
             verifies that a 100-ref symbol does not rank disproportionately higher than a 4-ref symbol
             (ratio should be ~sqrt(100)/sqrt(4) = 5x, not 25x linear).
        2. Apply edge-weight boost (* 50) to edges touching active_files BEFORE PageRank
        3. Build personalization vector: 10x weight for nodes mentioned in task, normalize to sum=1.0
           If all nodes mentioned (uniform): still valid, personalization = 1/N for each.
        4. Compute density: edges.len() as f64 / (nodes.len() * (nodes.len()-1)) as f64.
           If density > config.density_threshold (0.3): skip PageRank, return nodes in insertion order, set used_pagerank=false.
           DESIGN NOTE: density guard is our addition. Aider does NOT use a density guard (uses try/except
           ZeroDivisionError fallback). We add it because: near-uniform PageRank on dense graphs wastes
           compute for no ranking signal. Proof: test A1 verifies dense graph produces near-uniform ranks
           (max_rank/min_rank < 1.1) — confirming the guard's value.
           If nodes.len() <= 1: density=0, skip PageRank (trivial graph), used_pagerank=false.
        5. Run power iteration PageRank: damping=config.damping_factor, max_iter=config.max_iterations, tolerance=config.tolerance
           Dangling node handling: nodes with zero out-edges redistribute rank according to personalization vector.
           Source: aider passes dangling=personalization to NetworkX. NetworkX docs: "dangling nodes are given
           outedges according to the personalization vector." Without this, leaf nodes (constants, config structs)
           accumulate rank but never distribute it — distorting the entire ranking. Proof: test T15 constructs
           a graph with a leaf node and verifies its rank > 0 (fails without dangling redistribution).
        6. Collect special files: hardcoded initial list for Rust projects:
           Cargo.toml, Cargo.lock, README.md, README, LICENSE, .gitignore, Dockerfile, docker-compose.yml, build.rs, rust-toolchain.toml, clippy.toml, rustfmt.toml, .cargo/config.toml
           (13 items for Rust. Config-driven extensibility deferred to future phase.)
        7. Binary search to fit ranked nodes + special files to max_map_tokens using token_estimator.
           If max_map_tokens == 0: return empty ranked_symbols with special files omitted, fit_iterations=0.
           Tolerance: +-15%. Max 10 iterations.
           Initial guess: min(max_map_tokens / 25, num_ranked_nodes) instead of all nodes.
           Source: aider starts at max_map_tokens/25 (estimated avg tokens per tag). This reduces iterations
           because the initial guess is closer to the answer. Proof: test T10 verifies fit_iterations <= 10.
           With initial guess = all nodes on a 1000-node graph, worst case is ceil(log2(1000)) = 10.
           With initial guess = max_tokens/25, starting closer means fewer iterations in practice.
        7b. Line truncation: before token estimation, truncate each signature line to 100 characters.
           Source: aider truncates all output lines to 100 chars to prevent minified/generated code from
           consuming the entire token budget. Proof: test T18 constructs a symbol with a 500-char signature,
           verifies token count is based on truncated (100-char) version, not the full 500-char line.
        8. Return RepoMap with ranked symbols, actual token count, density, used_pagerank flag, fit_iterations count

          Applies sqrt(ref_count) scaling. Includes self-edges from snapshot.
        - build_personalization(node_count, task_mentioned_indices) -> Vec<f64>  (sums to 1.0)

        - binary_search_fit(ranked_nodes, special_nodes, max_tokens, tolerance, estimator) -> (Vec<RankedSymbol>, usize)
          Returns (fitted symbols, iteration count). Initial guess: min(max_tokens/25, num_nodes).

AIDER SOURCE ANALYSIS (github.com/Aider-AI/aider/blob/main/aider/repomap.py, fetched 2026-04-06)
  Our spec is based on design 31.7 which derives from aider's repo map. Source analysis found:

  ADOPTED from aider (5 improvements, each with deterministic test proving benefit):
    1. Dangling node redistribution via personalization vector.
       Aider: dangling=personalization in nx.pagerank(). Without: leaf nodes accumulate rank forever.
       Test: T15 (leaf node C in A->B->C chain, verify rank > 0).
    2. Self-edges (weight=0.1) for defined-but-unreferenced symbols.
       Aider: G.add_edge(definer, definer, weight=0.1) for orphans. Without: orphans rank = 0.
       Test: T16 (orphan node 4, verify rank > 0 with self-edge vs rank = 0 without).
    3. sqrt(num_refs) edge weight scaling.
       Aider: math.sqrt(num_refs). Without: generic symbols (Result, Error) with 100+ refs dominate.
       Test: T17 (100-ref vs 4-ref node, verify rank ratio < 8x not 25x).
    4. Binary search initial guess = max_map_tokens / 25.
       Aider: middle = min(max_map_tokens // 25, num_tags). Starts closer to answer, fewer iterations.
       Test: T10 (fit_iterations <= 10).
    5. Line truncation to 100 chars before token estimation.
       Aider: line[:100] for all output lines. Prevents minified code from blowing token budget.
       Test: T18 (500-char signature, verify token count uses 100-char version).

  DIVERGENCES from aider (3 deliberate design decisions):
    1. Symbol-level nodes vs aider's file-level nodes.
       Rationale: finer granularity for symbol-level context loading. Our DKG already provides symbol graph.
       Trade-off: larger graph (more nodes) but more precise repo maps.
    2. Density guard at 0.3 threshold (aider has none, uses try/except fallback).
       Rationale: dense graphs produce near-uniform PageRank (no signal). Guard avoids wasted compute.
       Proof: test A1 verifies max_rank/min_rank < 1.1 on dense graph (confirming no useful signal).
    3. Insertion-order fallback (aider falls back to empty list on ZeroDivisionError).
       Rationale: returning nothing is worse than returning symbols in DKG insertion order.

  NOT ADOPTED from aider (justification for each):
    - Identifier specificity boost (10x for long snake/camel names, 100x cumulative): adds complexity
      with marginal benefit for symbol-level graphs (aider needs it because file-level is coarser).
      Defer to future phase if ranking quality tests show need.
    - Private symbol penalty (0.1x for underscore prefix): Rust uses pub/pub(crate) visibility, not
      underscore convention. Not applicable to our primary language.
    - Generic name penalty (0.1x for >5 definitions): sqrt(num_refs) already dampens high-ref symbols.
      Adding another penalty factor risks over-penalizing legitimately important shared types.
