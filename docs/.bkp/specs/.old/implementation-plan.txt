ELAI_CC IMPLEMENTATION PLAN — WALKING SKELETON
Version: 1.0
Date: 2026-04-05
Status: READY TO START

Principle: build the thinnest end-to-end slice first. Measure everything.
Elaborate only what the data says needs elaboration.

Every phase follows the same cycle:
  1. SKELETON  — minimal structure, stubs, types
  2. VERIFY    — does it compile? does existing test suite still pass?
  3. TEST      — write contract/integration tests for this phase (they fail)
  4. IMPLEMENT — make tests pass
  5. MEASURE   — collect metrics (compile time, test count, LOC, coverage)
  6. DECIDE    — fix issues found then proceed

No phase starts until the previous phase's tests pass.
Specs referenced below are in docs/specs/crates/ and docs/specs/integration/.

PHASE 4: WORKFLOW INTEGRATION + AGENT PROCESS ISOLATION + AUTONOMOUS MODE
================================================================================

Goal: complete development workflow with pipeline design capability.
  Enable AUTONOMOUS auto-advance on top of the validated INTERACTIVE pipeline.
  Agents run as isolated OS processes. Orchestrator communicates via IPC.
  No agent has visibility into enforcement logic, other agents, or harness internals.

Spec: crates/tools.txt, crates/plugins.txt, integration/pipeline-factory.txt,
  orchestrator.txt section 12 (agent isolation model).

Ordering rationale: 4A (process isolation) is foundational. All subsequent sub-phases
  run agents through the isolation boundary. This proves isolation under real workload,
  not as a bolt-on after the fact.


  4A: Agent process isolation (Tier C)
    SKELETON:
      - AgentProcess struct: wraps std::process::Command for agent binary
      - IPC channel: unix domain socket (Linux) / named pipe (Windows)
      - Wire protocol: 1-byte version + 4-byte length prefix + postcard payload
      - Message types: full enum (AgentRequest, AgentResponse, InferRequest,
          InferResponse, ToolRequest, ToolResult, BashRequest, BashResult,
          GroundingRequest, GroundingResult, ThinkStep, CheckpointSync,
          AgentHeartbeat, AgentKill, ReplanRequest)
      - AgentBinary: separate Rust binary (elai_cc_agent) compiled from agent/ crate.
          Contains: GRC reasoning loop, IPC client, structured output parser.
          Does NOT contain: LLM client, reqwest, network code, tool implementations,
            FSM, SSB, rules engine, knowledge engine.
          LLM calls: agent emits InferRequest over IPC. Orchestrator calls
            providers::LlmProvider::complete() and returns InferResponse.
            Agent never touches network for LLM inference.
      - ProcessConfig per role: allowed_paths, seccomp_profile, resource_limits
      - IPC socket directory: 0700 permissions, created before agent spawn
    VERIFY:   compiles as workspace with two binaries (elai_cc, elai_cc_agent)
    TEST:
      Functional isolation:
      - spawn agent process -> send AgentRequest -> receive AgentResponse -> kill
      - agent process cannot read .elai_cc/ (returns ENOENT from OS, not filtered)
      - agent process cannot see other agent processes (PID namespace)
      - agent process cannot access network (socket(AF_INET) returns EPERM via seccomp)
      - agent process CAN use IPC socket (socket(AF_UNIX) allowed in seccomp)
      - researcher agent CAN access allowlisted HTTPS endpoints via veth
      - orchestrator kills agent on timeout (SIGKILL, no negotiation)
      - agent crash does not crash orchestrator (process boundary)
      - agent cannot write outside its scratch directory
      - two agents running concurrently cannot see each other's scratch dirs
      - auditor agent can read executor's output files (orchestrator copies to auditor view)
      - executor agent cannot read auditor findings (separate filesystem view)
      - agent environment sanitized: no API keys, no HOME, no ELAI_CC_* vars
      - SO_PEERCRED verification: orchestrator rejects connection from wrong PID

      LLM proxy:
      - agent emits InferRequest -> orchestrator calls LLM -> InferResponse returned
      - agent binary has no reqwest dependency (cargo tree check)
      - agent cannot reach localhost:11434 (ollama) from its network namespace

      GRC budget (orchestrator-enforced):
      - orchestrator counts ThinkStep messages per topic externally
      - after max_calls ThinkSteps for a topic, orchestrator injects convergence
      - agent binary budget count is advisory only (verified by sending extra ThinkSteps)

      Adversarial IPC:
      - oversized frame (>10MB) -> orchestrator rejects, does not allocate
      - malformed postcard payload -> orchestrator returns IPC error, does not crash
      - agent sends AgentResponse without receiving AgentRequest -> rejected
      - agent sends ToolResult for a ToolId it never requested -> rejected
      - agent sends 10,000 ThinkStep messages in burst -> budget enforced, excess dropped
      - second process connects to same agent socket -> rejected (SO_PEERCRED mismatch)
      - agent socket survives agent SIGKILL: orchestrator closes fd, unlinks, respawns
      - agent sends message with mismatched agent_id -> rejected
      - protocol version mismatch at handshake -> agent killed

      ReplanRequest:
      - executor sends ReplanRequest(MINOR) with evidence -> auditor reviews -> fast-track replan
      - executor sends ReplanRequest(MAJOR) -> requires human approval
      - executor sends 2 ReplanRequests in same phase -> second rejected (max 1 per phase)
      - ReplanRequest without evidence string -> rejected
      - ReplanRequest logged to SSB as action_type='replan_request'

      Self-modification locks:
      - self-mod agent WriteFile to locked path -> rejected (generic error)
      - self-mod agent WriteFile("./metrics/../metrics.rs") -> rejected (canonical path)
      - self-mod agent BashRequest writing locked file -> blocked (read-only mount)
      - self-mod agent GitCommit touching locked file -> rejected (diff path filter)

    IMPLEMENT:
      Agent binary (elai_cc_agent):
        - Minimal binary. No network code. No tool code. No LLM client.
        - Receives AgentRequest via IPC. Runs GRC reasoning loop.
        - Emits InferRequest for LLM calls. Orchestrator proxies to providers crate.
        - Emits ToolRequest/BashRequest/GroundingRequest for all external actions.
        - Returns AgentResponse with structured output.

      Orchestrator IPC gateway:
        - Creates 0700 directory /tmp/elai_cc_{session}/ before any agent spawn.
        - Creates per-agent socket: /tmp/elai_cc_{session}/{agent_uuid}.sock
        - Verifies socket path does not pre-exist before bind() (symlink attack prevention).
        - On accept(): SO_PEERCRED check (Linux), named pipe impersonation check (Windows).
        - Reads frames with MAX_FRAME_SIZE=10MB hard cap.
        - Validates postcard deserialization before processing.
        - Routes: InferRequest -> providers, ToolRequest -> tools (through visibility
          filter + rules engine), BashRequest -> sandbox, GroundingRequest -> knowledge
          engine or web search (orchestrator has network access).
        - GRC budget: counts ThinkStep per topic per agent. Enforces cap externally.
        - SSB write synchronous with IPC ToolResult dispatch (crash safety).
        - Heartbeat: 5s interval. 15s timeout -> SIGKILL + unlink socket + respawn.
        - On agent death: close fd, unlink socket file, checkpoint to SSB.

      Linux process setup (in spawn order):
        1. Create 0700 socket directory if not exists.
        2. Create + bind socket. Listen.
        3. clone(CLONE_NEWNS | CLONE_NEWPID | CLONE_NEWNET).
        4. In child: prctl(PR_SET_NO_NEW_PRIVS, 1). Drop ALL capabilities.
        5. Setup mount namespace: bind-mount project (RO), scratch (RW).
           Self-mod agent: additionally mount locked dirs as RO.
        6. Setup PID namespace (child is PID 1).
        7. Setup network namespace: lo only. Researcher: add veth + iptables.
        8. Install seccomp-bpf (IPC_BASELINE or IPC_BASELINE + NETWORK_EXTRA).
        9. Sanitize environment (keep only LANG, TERM, PATH, TMPDIR).
        10. exec(elai_cc_agent, socket_path).

      Windows process setup:
        1. CreateAppContainerProfile() for agent.
        2. Grant AppContainer access to: project source (read), scratch dir (read-write).
        3. Create named pipe.
        4. CreateProcessAsUser with AppContainer token.
        5. Assign to Job object (process limit=1, memory limit=512MB).
        6. Researcher: add network capability to AppContainer profile.
        7. Fallback (no AppContainer): restricted token + ACL deny on .elai_cc/.
           Documented as weaker. Linux recommended for production security.
