RISKS TO WATCH

  R1: IPC serialization schema drift. Phase 4A defines ToolRequest/ToolResult message types.
      If Phase 4B adds new fields without updating the shared postcard schema, deserialization
      fails silently (postcard skips unknown fields in some configs). Mitigation: contract test
      that round-trips every ToolRequest variant through serialize+deserialize.
  R2: Incremental compilation false positives. cargo check may report errors in valid code
      that depends on unwritten modules (during EXECUTING, not all files exist yet).
      Mitigation: compilation check only runs on the specific file written, not workspace-wide.
      If the error references an unresolved import from a file not yet written, classify as
      DEFERRED (not COMPILATION_ERROR) and skip retry.
  R3: ShortCoder AST transform correctness. tree-sitter grammar version mismatch between
      knowledge/ crate (used for DKG) and tools/ crate (used for ShortCoder) could produce
      different ASTs for the same code. Mitigation: both crates pin identical grammar versions
      in Cargo.toml (workspace-level dependency).
  R4: Concurrent tool access. Multiple agents may issue ToolRequests simultaneously during
      BSP supersteps. ToolRegistry must check SSB file locks before executing write tools
      (orchestrator.txt L619: "No two agents write to same file simultaneously").

4B.4 IMPLEMENT — make tests pass
  PRE_GATE:
    - Step 4B.3 tests compile (cargo test -p tools --no-run exits 0)
    - All tests currently fail (confirmed by step 4B.3)
  TASK:
    - git2 native operations:
      Auto-commit with deterministic message from phase outcome (not LLM prose).
      Branch per plan: plan-{pipeline_id}. WIP commits for large phases (>5 edits).
      Session-owned commit tracking with safe undo protocol (tools.txt section 4).
    - 5-tier validation pipeline:
      Tier 1 (determinism), Tier 2 (quality/AST), Tier 3 (unit), Tier 4 (integration),
      Tier 5 (stress/adversarial). All run by auditor, executor never runs own tests
      (tools.txt section 5).
    - DAIRA trace with structured markers:
      Tracing crate for Rust, sys.settrace for Python. Markers: [CALL], [RETURN],
      [MUTATION], [BRANCH], [ERROR], [PANIC], [TIMEOUT], [FINDING], [PATTERN],
      [ANOMALY], [STAT:name], [DURATION:name], [MEMORY:name], [CHECKPOINT], [STEP:n].
      AdaptiveTool<T> wrapper with budget-based scope reduction (max 3 reductions).
      (tools.txt section 6)
    - 3-tier edit matching:
      Tier 1 exact -> Tier 2 whitespace-normalized (preserve original indentation) ->
      Tier 3 ellipsis-elision ("..." matches any line sequence).
      On failure: SequenceMatcher similarity hint. Never silently apply wrong match.
      (tools.txt section 3)
    - ShortCoder AST-preserving simplification:
      10 tree-sitter transform rules (R1-R10, tools.txt section 7). R4/R6 configurable.
      Applied as post-processing on executor output before auditor review.
    - Failure taxonomy (deterministic regex classification):
      9 categories: SYNTAX_ERROR, TYPE_ERROR, IMPORT_ERROR, ASSERTION_ERROR, TIMEOUT,
      EMPTY_OUTPUT, RUNTIME_PANIC, PERMISSION_DENIED, RESOURCE_EXHAUSTED.
      Each with deterministic suggested_action. Auditor reads classification BEFORE raw
      output. 3+ same-category failures in one phase -> anti-spiral trigger.
      (tools.txt section 11)
    - File read enhancement:
      Outline mode for files >300 lines (tree-sitter parsed sections). force_full flag.
      Budget guard: warns if file > 50% remaining context budget. INTERACTIVE: user decides.
      AUTONOMOUS: auto-downgrade to outline. (tools.txt section 2)
    - Incremental compilation feedback (ASYNC):
      After each file write during EXECUTING: run cargo check / ruff / tsc / go vet
      on the written file. Runs in background (async, per risk-register R51) — executor
      proceeds to next file immediately. Results delivered via IPC when ready.
      On failure: sanitized error + COMPILATION_ERROR category to executor.
      Retry semantics: round 1 = initial check, round 2 = retry after executor fix,
      round 3 = final retry. Max 3 rounds total (2 retry opportunities).
      After round 3 failure: NEEDS_AUDIT flag, auditor gets compilation context.
      NOT applied during TESTING_FIRST (test files expected to fail until EXECUTING).
      DEFERRED classification for errors referencing unwritten modules (Risk R2).
      (tools.txt section 10, risk-register R51)
    - IPC ToolRequest/ToolResult serialization:
      All tools dispatch through orchestrator IPC handler. Error messages sanitized before
      reaching agent (strip rule_id, predicate types, hook names — tools.txt section 8).
      ToolRegistry checks SSB file locks before executing write tools
      (orchestrator.txt L619).

BABY STEP INTEGRATION TEST RUNNER EXTENSION

  The base 4B tools operate per-file. This extension adds an IntegrationTestRunner
  that operates per-baby-step and per-level in the DecompositionTree (Phase 4E extension).

  NEW TOOL: IntegrationTestRunner
    Runs integration checks at 4 granularity levels:
      BABY_STEP: cargo check on affected files after each baby step completion.
        Target: <5s. Catches import errors, type mismatches immediately.
      STEP: cargo test on step's module after all baby steps in step complete.
        Target: <30s. Verifies baby steps compose correctly within a step.
      PHASE: cargo test -p crate after all steps in phase complete.
        Target: <60s. Verifies phase integrates with rest of crate.
      CONCEPT: cargo test --workspace -- concept_tag after all phases in concept complete.
        Target: <120s. End-to-end verification of concept.

    struct IntegrationTestRunner {
        level: IntegrationLevel,
    }

    enum IntegrationLevel { BabyStep, Step, Phase, Concept }

    fn run_integration(
        level: IntegrationLevel,
        target: &IntegrationSpec,            // from DecompositionTree
        project_root: &Path,
    ) -> IntegrationResult

    struct IntegrationResult {
        level: IntegrationLevel,
        passed: bool,
        test_count: u32,
        failures: Vec<String>,               // test names that failed
        stdout_hash: [u8; 32],               // deterministic replay
        elapsed_ms: u64,
    }

    Integration with existing tools:
      - Uses existing BashSandbox for test execution (tools.txt S9)
      - Uses existing FailureTaxonomy for error classification (tools.txt S11)
      - Results returned via IPC ToolResult (Phase 4A wire protocol)
      - BABY_STEP level uses incremental compilation infrastructure (4B S10)

    Added to ToolRegistry: tool_id="integration_test", available in AUDITING state.
    IntegrationTestRunner is NOT available during EXECUTING (executor writes code, not tests).
    Integration tests are triggered by orchestrator after baby step acceptance, not by agent.
