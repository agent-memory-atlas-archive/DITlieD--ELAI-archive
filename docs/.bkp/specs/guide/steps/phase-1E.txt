PHASE 1E: CatRAG + A-RAG (query pipeline assembly)
Prerequisites: Phase 1D complete (PageRank operational, DKG graph available)
Dependencies: Phase 1B (BM25), Phase 1C (vectors), Phase 1D (PageRank)

SCOPE: see docs/specs/guide/implementation-guide.txt

GOAL
Assemble the full retrieval pipeline: query -> BM25 -> vector -> PageRank -> CatRAG -> A-RAG.
CatRAG provides query-aware graph traversal over the DKG to expand evidence chains.
A-RAG provides hierarchical retrieval orchestration with snippet-based progressive disclosure.
Target: 55-87% token savings vs naive full-chunk retrieval, sub-second query latency.

GROUNDING SOURCES
  Paper: CatRAG (arXiv 2602.01965) — Context-Aware Traversal for Robust RAG
    Interface map: workflow/papers/catrag-interface.md
    Key algorithms: Symbolic Anchoring, Query-Aware Dynamic Edge Weighting, Key-Fact Enhancement
    All applied as query-time overlays on PPR (Phase 1D), modifying reset vector and transition matrix.

  Paper: A-RAG (arXiv 2602.03442) — Scaling Agentic RAG via Hierarchical Retrieval Interfaces
    Interface map: workflow/papers/arag-interface.md
    Key algorithms: three-tool hierarchy (keyword/semantic/chunk_read), ReAct agent loop,
    snippet-based progressive disclosure, context tracker deduplication.

  Spec: docs/specs/crates/knowledge.txt — Layers 4-5 (CatRAG, A-RAG), Section 3 (Query Pipeline)

ADAPTATION NOTES (paper -> ELAI)
  CatRAG paper uses HippoRAG 2 knowledge graph (OpenIE triples, entity nodes, passage nodes).
  ELAI uses DKG (tree-sitter AST graph). Mapping:
    Paper entity nodes (V_E) -> DkgNode (functions, structs, traits, modules)
    Paper passage nodes (V_P) -> source file chunks (from BM25 chunking)
    Paper relation edges (E_rel) -> DKG edges (calls, references, imports, implements)
    Paper synonym edges (E_syn) -> DKG nodes with high embedding similarity (>0.8 cosine)
    Paper context edges (E_ctx) -> DKG node-to-file mapping (which file contains which symbol)
    Paper OpenIE triple extraction -> NOT NEEDED (tree-sitter already extracts structured relations)
    Paper NER -> symbol name extraction from query (regex + fuzzy match against DKG node names)

  A-RAG paper uses no graph, no BM25 index for keyword search.
  ELAI adaptation:
    keyword_search -> BM25 (Phase 1B) + snippet extraction from matched chunks
    semantic_search -> dual-vector search (Phase 1C) + snippet extraction
    chunk_read -> read full file content or specific line ranges from disk
    Agent loop -> ReAct loop using local LLM (ollama) or external LLM
    No parallel tool calling (one tool per step, per paper design)

  Pipeline order (knowledge.txt L104-105):
    query -> BM25+SPLADE(RRF) -> dual-vector rerank -> PageRank importance filter
      -> CatRAG expand -> A-RAG filter -> cross-encoder rerank -> token-budget fit -> context
  Cross-encoder reranker is Phase 1G. Token-budget fit is Phase 3E.
  This phase implements CatRAG + A-RAG + pipeline wiring. Stubs for 1G and 3E interfaces.

RISKS TO WATCH
  R30: CatRAG LLM calls at query time add latency. Mitigate: limit to N_seed=5 seeds,
       K_edge=15 neighbors. Cache LLM scores for repeated query patterns.
  R31: DKG graph may be too sparse for CatRAG (code graphs are sparser than NLP knowledge graphs).
       Mitigate: add synonym edges between semantically similar symbols (embedding similarity > 0.8).
       If graph density < 0.01, skip CatRAG and pass PageRank output directly to A-RAG.
  R32: A-RAG agent loop may not converge (infinite retrieval cycles).
       Mitigate: max_loops=15, max_token_budget from context allocator, context tracker prevents re-reads.
  R33: Snippet extraction from BM25/vector results may lose critical context.
       Mitigate: snippets include surrounding lines (context window of +/- 2 lines for code).
  R34: Pipeline latency budget. All layers must fit within 2 seconds total for interactive use.
       Measure per-layer latency independently, identify bottleneck.

  1E.4 IMPLEMENT CatRAG — QUERY-AWARE GRAPH TRAVERSAL
    PRE_GATE:
      - Step 1E.3 complete: new tests exist and fail
      - CatRAG paper ingested: test -f workflow/papers/catrag-interface.md
    TASK:
      Implement CatRag::compute_overlay following the paper algorithm (catrag-interface.md Section 8):

      a. Symbolic Anchoring:
         - Extract symbol names from query (split on whitespace, camelCase, snake_case)
         - Fuzzy-match against DKG node names (case-insensitive, substring match)
         - For each matched node e_i: reset_weight = epsilon * |files_containing(e_i)|^(-1)
         - Combine with PageRank seed nodes (PageRank seeds get higher base weight)
         - Normalize combined distribution to sum=1.0
         NOTE: no LLM call needed here (unlike paper's NER). Symbol extraction is deterministic.

      b. Query-Aware Dynamic Edge Weighting (simplified for code graphs):
         - Select top-N_seed nodes by reset probability
         - For each seed u, get outgoing DKG edges
         - If |neighbors| > K_edge: coarse prune by embedding similarity between
           query and edge label/target node name. Keep top-K_edge.
         - Fine-grained scoring: for code, use heuristic scoring instead of LLM:
           Score based on: (1) edge type weight (calls=8, implements=7, references=5, imports=3),
           (2) target node type relevance to query, (3) file proximity to query-mentioned files.
           Map combined score to phi() tiers (0-10 scale).
           NOTE: LLM scoring (paper approach) available as optional upgrade path via circuit breaker.
                 Start with deterministic heuristic scoring. No LLM dependency in hot path.
         - Apply score_to_weight mapping (phi function, paper Table 7)
         - Store as edge_weight_deltas in overlay (sparse, not full matrix)

      c. Key-Fact Passage Weight Enhancement:
         - For each DKG edge from symbol to file: if the symbol was referenced in the query
           context (T_seed equivalent = symbols mentioned in query + their direct callees),
           boost context edge weight *= (1 + beta).
         - Pure algorithmic, zero LLM cost.

      d. Density Guard:
         - Compute graph density = |edges| / (|nodes| * (|nodes| - 1))
         - If density < min_graph_density (0.01): return empty overlay
         - Log warning: "CatRAG skipped: graph density {d} below threshold {t}"

      e. Apply overlay to PPR:
         - Modify PageRank's reset vector with symbolic anchoring distribution
         - Modify PageRank's transition matrix with edge weight deltas
         - Run PPR with modified inputs (reuse Phase 1D PageRank implementation)
         - Return ranked results

    DETERMINISTIC_CHECK:
      - CatRAG tests (a-e from 1E.3) pass: cargo test -p knowledge catrag
      - cargo clippy -p knowledge -- -D warnings exits 0
    ADVERSARIAL:
      - If edge_weight_deltas modifies base graph instead of overlay, concurrent queries corrupt state.
        Test: run compute_overlay twice with different queries, verify base graph unchanged.
      - If phi() mapping has off-by-one (e.g., score 3 maps to 0.2 instead of 0.0):
        Test: explicit assertion for every boundary value (3->0.0, 4->0.2, 6->0.3, 7->2.0, 10->5.0).
      - If symbolic anchoring matches too many nodes (common names like "new", "get", "set"):
        Test: cap matched nodes at 2*N_seed. Log warning if >50% of DKG nodes matched.
    ACCEPTANCE:

  1E.5 IMPLEMENT A-RAG — HIERARCHICAL RETRIEVAL ORCHESTRATOR
    PRE_GATE:
      - Step 1E.4 complete: cargo test -p knowledge catrag passes
    TASK:
      Implement AragOrchestrator following the paper algorithm (arag-interface.md Section 4):

      a. Keyword Search tool (wraps BM25):
         - Input: keywords Vec<String>, top_k usize
         - Call Bm25Index::query for each keyword, merge results
         - Score per chunk: sum(count(keyword, chunk_text) * keyword.len())
         - Extract snippets: sentences containing at least one keyword (+/- 2 lines for code context)
         - Return top_k RetrievalResults with snippets (NOT full chunks)

      b. Semantic Search tool (wraps vector index):
         - Input: query String, top_k usize
         - Call vector index (Phase 1C) for query embedding
         - Oversample 3x at sentence/chunk level, aggregate by max score per file
         - Extract snippets: matched sentences with surrounding context
         - Return top_k RetrievalResults with snippets

      c. Chunk Read tool:
         - Input: chunk_ids Vec<String>
         - For each chunk_id: if ContextTracker.is_read(id), return "(previously read)"
         - Otherwise: read full file content (or line range), mark as read in tracker
         - Return full content for new chunks, placeholder for already-read

      d. Context Tracker:
         - HashSet<String> of read chunk IDs
         - Per-query instance (not shared across queries)
         - is_read(&str) -> bool, mark_read(&str), token_count() -> usize

      e. Execute Tool dispatch:
         - Match on RetrievalTool enum variant, dispatch to a/b/c above
         - Track tokens consumed per tool call
         - Enforce max_token_budget: if exceeded, return partial results

      f. Query Pipeline orchestration (simplified, no LLM agent loop):
         - For Phase 1E: deterministic pipeline, not full ReAct agent loop
         - Pipeline: keyword_search(query_keywords) -> semantic_search(query) -> chunk_read(top hits)
         - The full ReAct agent loop (LLM decides which tool) is Phase 2+ (requires reasoning crate)
         - This phase implements the TOOLS and PIPELINE WIRING, not the agent decision-making

  1E.6 IMPLEMENT PIPELINE — FULL QUERY PIPELINE ASSEMBLY
    PRE_GATE:
      - Step 1E.5 complete: cargo test -p knowledge arag passes
      - CatRAG operational: cargo test -p knowledge catrag passes
    TASK:
      Wire all layers into QueryPipeline::query():

      a. Stage 1 — BM25 retrieval:
         - Extract keywords from query (split, dedup, filter stopwords)
         - Call Bm25Index::query(query, top_k=20)
         - Record as PipelineStage { stage: "bm25", results, latency_ms }

      b. Stage 2 — Vector retrieval:
         - Call vector index with query embedding (Phase 1C)
         - Merge with BM25 results via RRF (reciprocal rank fusion):
           RRF_score(d) = sum over r in rankings of: 1 / (k + rank_r(d)), k=60
         - Record as PipelineStage { stage: "vector", results, latency_ms }
         - If vector index unavailable (circuit breaker): skip, use BM25 only

      c. Stage 3 — PageRank importance filter:
         - Build DkgSnapshot, run PageRank (Phase 1D)
         - Filter/rerank results by PageRank score (boost files containing high-PageRank symbols)
         - Record as PipelineStage { stage: "pagerank", results, latency_ms }

      d. Stage 4 — CatRAG expansion:
         - Compute CatRagOverlay for the query
         - Apply overlay to PageRank, re-run PPR with modified inputs
         - Expand result set: add files reachable via high-weight overlay edges
         - Record as PipelineStage { stage: "catrag", results, latency_ms }
         - If density guard triggers: passthrough (no expansion)

      e. Stage 5 — A-RAG filtering:
         - Use AragOrchestrator to filter and refine results
         - Snippet-based progressive disclosure: return snippets, not full files
         - Context tracker prevents redundant reads
         - Record as PipelineStage { stage: "arag", results, latency_ms }

      f. Stage 6-7 — Stubs for future phases:
         - PipelineStage { stage: "rerank", .. } — stub, passthrough (Phase 1G implements)
         - PipelineStage { stage: "token_fit", .. } — stub, passthrough (Phase 3E implements)

      g. Return Vec<PipelineStage> with full trace of all stages
