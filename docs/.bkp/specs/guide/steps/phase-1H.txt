PHASE 1H: SPLADE KEYWORD EXPANSION (conditional)
Prerequisites: Phase 1G complete

SCOPE: see docs/specs/guide/implementation-guide.txt

GOAL
Evaluate SPLADE sparse keyword expansion. Feature-gated behind cfg(feature="splade").
Compare two model candidates: prithivida/Splade_PP_en_v1 (established, ONNX-ready) and naver/splade-v3 (newer, ensemble distillation, outperforms PP_en_v1 on TREC/BEIR — arxiv 2403.06789).
Pick the better-performing candidate on our code corpus, then apply the keep/drop gate.
DROP if <5% recall improvement over BM25-only on our test corpus.

CRITICAL RISK — BERT vocabulary mismatch on code:
  SPLADE operates in the BERT WordPiece vocabulary space (30522 tokens). Code tokens like
  "fn", "impl", "async", "Vec<T>", "unwrap()", "println!" may be aggressively subword-split,
  degrading expansion quality. HuggingFace research confirms "vocabulary mismatch can destroy
  the representation entirely" for specialized domains (huggingface.co/blog/yjoonjang/vocabulary-is-the-most-important-element-in-splade).
  This phase MUST measure vocabulary coverage before concluding SPLADE helps on code.

RISKS TO WATCH
  R24: SPLADE ONNX dependency weight (~532MB for main model) vs marginal recall gain on code search.
  R25: SPLADE benchmarks (29% nDCG@10 on ESCI) are for natural language — code search recall may differ significantly.
  R26: ort crate ONNX Runtime download strategy (default: downloads prebuilt from Microsoft) may fail in air-gapped environments.
  R27: SPLADE requires BERT tokenization (input_ids, attention_mask, token_type_ids). The ort crate does NOT include tokenization — requires separate tokenizers crate (may already be present from Phase 1G cross-encoder).
  R28: ort is an unconditional dependency for GraphCodeBERT/Granite (added in Phase 1G). Feature-gating SPLADE does NOT gate ort itself — only the SPLADE-specific ort::Session initialization.
  R29: BERT WordPiece tokenizer has ~30522 subword tokens trained on Wikipedia/BookCorpus. Programming-specific tokens (fn, impl, async, mut, Vec, HashMap, unwrap) are NOT in the vocabulary and will be split into character n-grams, reducing SPLADE expansion quality for code-specific queries. Evidence: HuggingFace blog "Vocabulary is the most important element of Sparse Retrieval" demonstrates vocab mismatch destroys SPLADE representations in specialized domains.
  R30: 10-query evaluation is statistically underpowered. TREC standard is 50 topics minimum for reliable IR evaluation (Sakai 2016, SIGIR/TOIS systematic review of statistical power). With 10 queries, effect sizes below ~15% are undetectable with any confidence.

EXIT CRITERIA
  Three possible outcomes:
  1. EARLY DROP (vocab coverage < 0.3): phase complete without recall measurement. SPLADE fundamentally mismatched for code corpus.
  2. DROP (delta < 5% OR p >= 0.05): improvement absent or statistically insignificant.
  3. KEEP (delta >= 5% AND p < 0.05): statistically significant improvement confirmed.
  All outcomes: feature flag works, module code preserved behind cfg(feature="splade") gate.
  If KEEP: circuit breaker integrated, RRF fusion operational, winning model candidate documented.
  If any DROP: feature flag disabled by default, decision rationale + all measurements logged.
  Verify SPARSE_ONLY cascade: with splade feature disabled, SPARSE_ONLY mode must degrade to BM25_ONLY (no dead code path). Confirm grep for SPARSE_ONLY in knowledge engine shows BM25-only fallback when splade is absent.

MEASUREMENTS
  vocab_coverage_code: fraction of code-specific identifiers that map to single WordPiece tokens (0.0-1.0). Threshold: 0.3.
  model_comparison: table of (candidate, p50_latency_ms, top50_term_jaccard) for each model variant.
  recall_delta_percent: per-query (BM25+SPLADE recall@10 - BM25 recall@10) / BM25 recall@10 * 100, excluding queries where BM25 recall@10 = 0 (logged as warnings). Report mean + std across 50 queries.
  wilcoxon_p_value: paired Wilcoxon signed-rank test on (bm25_recall, splade_recall) per query. Threshold: p < 0.05.
  splade_query_latency_ms: p50 and p95 for single expand_query call (N=10, excluding warm-up)
  model_load_time_s: time to load ONNX model into ort::Session
  binary_size_delta_mb: increase in release binary with --features splade vs without
