DESIGN DECISIONS

  STRIP BEFORE RESTRUCTURE:
    Stripping first removes ~4K+ LOC of known-bad code (compact, summary_compression,
    telemetry, usage, lsp_client, compat-harness) before splitting runtime into 5 crates.
    Fewer files = fewer move operations = fewer dependency breaks during restructure.
    Proof: runtime has 38 source files. Stripping removes 6+ files before the split begins.

  WORKSPACE PATH MIGRATION:
    Steps 0.1-0.3: work in .elai_cc/rust/ (the existing claw-code structure).
    Step 0.4: creates new structure at .elai_cc/crates/ with .elai_cc/Cargo.toml as workspace root.
    Steps 0.5+: all paths use .elai_cc/ as workspace root.
    The old .elai_cc/rust/ is archived (not deleted) after 0.5 verifies the new structure.

  ONNX MODEL CANONICAL PATH:
    ONNX embedding models stored at .elai_cc/models/onnx/ (canonical, pre-staged via setup
    script outside session, not auto-downloaded). Setup: download + blake2 hash verify +
    write index_version.toml. Missing models at startup -> DEGRADED mode (BM25_ONLY), not crash.
    Visibility: .elai_cc/models/** hidden from agents via visibility filter (hidden_paths default).
    Source: core.txt S4, technical-analysis-v3.txt Concern 1.

  TOKENUSAGE HANDLING (addresses R23):
    usage.rs (313 LOC) is STRIPPED, but TokenUsage is structural (embedded in Session).
    Strategy: define a minimal elai_cc_core::TokenUsage struct (input_tokens, output_tokens,
    total_tokens, estimated_cost_usd). Rewrite Session to use this instead of the claw-code
    TokenUsage. Strip UsageTracker, CompactionConfig, format_usd, pricing_for_model, ModelPricing.
    These are claw-code billing concepts; elai_cc tracks tokens for context budget, not billing.
    This happens in step 0.2c as an explicit sub-task.

  PROVIDER TRAIT MIGRATION (addresses WARN-7):
    claw-code has an existing Provider trait (in api/src/providers/mod.rs) implemented by
    AnthropicClient and OpenAiCompatClient. elai_cc defines LlmProvider (complete, embed,
    token_count, token_count_estimate). Strategy: keep old Provider trait during Phase 0
    as an internal implementation detail. New OllamaProvider implements LlmProvider directly.
    Phase 1+ migrates Anthropic/OpenAI to LlmProvider. Mark with #[deprecated] during Phase 0.
