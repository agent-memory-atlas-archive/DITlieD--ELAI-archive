TYPES (new, not yet in any spec — added here, to be propagated to orchestrator.txt)

  struct SystemProbeResult {
      gpu_count: u32,
      gpu_info: Vec<GpuInfo>,             // per GPU: name, total_bytes, free_bytes, driver_version
      ram_total_bytes: u64,
      ram_free_bytes: u64,
      disk_free_bytes: u64,               // on project partition
      os: String,                         // from sysinfo
      is_supported: bool,                 // sysinfo::IS_SUPPORTED_SYSTEM
  }

  struct GpuInfo {
      index: u32,
      name: String,
      total_bytes: u64,
      free_bytes: u64,
      driver_version: String,
      uuid: String,                       // stable cross-reboot identity (nvml device.uuid())
  }

  struct SystemConstraints {
      min_vram_bytes: u64,                // from PipelineSpec resource requirements
      min_ram_bytes: u64,
      min_disk_bytes: u64,
      required_gpu_count: u32,
  }

  struct StubResult {
      step_id: String,
      alternative_index: u32,             // 0-2
      outcome: FeasibilityOutcome,        // Pass | Fail | Blocked (from reasoning crate)
      elapsed_ms: u64,
      stdout_hash: [u8; 32],             // blake3 of stdout for deterministic replay
      stderr_summary: String,             // first 512 bytes
      resource_delta: ResourceDelta,      // VRAM/RAM change during stub execution
  }

  struct ResourceDelta {
      vram_before_bytes: u64,
      vram_after_bytes: u64,
      ram_before_bytes: u64,
      ram_after_bytes: u64,
  }

  struct FeasibilityReport {
      probe: SystemProbeResult,
      constraints: SystemConstraints,
      constraint_results: Vec<ConstraintResult>, // per-resource pass/fail with margin
      stubs: Vec<StubResult>,             // one per passing novel step (escalated steps in escalations)
      skipped_steps: Vec<String>,         // non-novel steps (not probed)
      escalations: Vec<FeasibilityEscalation>,
  }

  struct ConstraintResult {
      resource: String,                   // "vram_gpu0", "vram_gpu1", "ram", "disk"
      required: u64,
      available: u64,
      margin: f64,                        // (available - required) / required
      passed: bool,                       // margin >= 0.0 (met), margin >= 0.20 (skip threshold)
  }

  struct FeasibilityEscalation {
      step_id: String,
      reason: String,
      stubs_tried: Vec<StubResult>,       // all 3 failed attempts
  }

  enum FeasibilityDecision {
      Proceed,                            // all probes pass, all stubs pass
      ProceedWithConstraints(Vec<String>), // probes show limits, stubs adapted
      Escalate(Vec<FeasibilityEscalation>), // human decision needed (INTERACTIVE)
      Replan(Vec<FeasibilityEscalation>),   // auto-replan (AUTONOMOUS)
  }

  Serialization: msgpack (disk), postcard (IPC wire) — consistent with project convention.
  FeasibilityOutcome reused from reasoning crate (Phase 2D). No new enum.


SKIP CRITERIA (deterministic)

  FEASIBILITY_PROBE is skipped (PLANNING -> TESTING_FIRST directly) when ALL of:
    1. PipelineSpec.novel_steps.is_empty() == true
       (L2 structural validator marks steps as novel when tool/approach not in capability registry)
    2. ALL resource constraints met with >= 20% margin. Formula per resource:
       resource_free >= resource_required * 1.20
       Applied independently to: VRAM (per-GPU), RAM, disk.
       All three must pass. If any single resource fails the margin check, probe runs.
       (avoids probe for well-known workloads on capable hardware)
  If either condition fails, FEASIBILITY_PROBE runs.
  Skip decision logged to SSB as action_type='phase_transition' with skip_reason field.
  Grounding: architecture-overview.txt L139 confirms PLANNING->TESTING_FIRST skip exists.


RISKS TO WATCH

  R-4F-1: nvml-wrapper requires NVIDIA driver installed. On systems without NVIDIA GPU,
    Nvml::init() returns Err. Must handle gracefully: gpu_count=0, gpu_info=vec![].
    Grounding: nvml-wrapper docs — wraps libloading, fails if driver absent.

  R-4F-2: sysinfo refresh overhead. Creating System::new_all() is expensive.
    Keep one System instance, call refresh_specifics() with only needed categories.
    Grounding: sysinfo docs recommend reuse over recreation.

  R-4F-3: VRAM readings are point-in-time. Another process (ollama, ONNX) may allocate
    between probe and stub execution. Mitigation: re-check VRAM immediately before
    stub launch via ModelPool.available_vram(). Uses nvml device.memory_info().free.
    Grounding: vLLM pre-flight pattern — checks at load time, not just at startup.

  R-4F-4: Windows named pipe IPC latency may differ from Unix socket.
    Stub timeout must account for IPC overhead. Use same IPC as Phase 4A (Tier C).
    Grounding: Phase 4A already handles cross-platform IPC.

  R-4F-5: Stub sandbox escape. Stubs execute in Tier C isolated process with
    FEASIBILITY tool restrictions (stub write + bash + web search only, NO edit/git).
    Grounding: orchestrator.txt L38 — phase-aware tool loading.

BABY STEP FEASIBILITY EXTENSION

  The base 4F probes top-level novel steps from ExecutablePipeline.
  This extension probes at the baby step level within the DecompositionTree.

  DESIGN
    After the DecompositionTree is built (4E), before execution starts, the system
    identifies baby steps that use novel packages/frameworks/APIs. Each novel baby step
    gets a feasibility stub (<50 lines) to verify the approach works on current hardware.

    Novel baby step detection:
      - Baby step references a PackageRef with verified=false -> novel
      - Baby step uses a framework not previously used in this project -> novel
      - Baby step requires a system capability not yet tested (e.g. GPU, FFI) -> novel

    Feasibility runs PER CONCEPT (not all at once):
      Before executing concept N, probe all novel baby steps in concept N.
      This is more efficient than probing everything upfront: concept 2's approach
      may change based on concept 1's results.

    Skip criteria (per concept):
      No novel baby steps in this concept -> skip feasibility for this concept.
