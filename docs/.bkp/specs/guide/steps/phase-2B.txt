PHASE 2B: GROUNDING VERIFICATION
Prerequisites: Phase 2A complete (all 9+ GRC tests pass, cargo test -p reasoning 0 failures)

SCOPE: see docs/specs/guide/implementation-guide.txt

GOAL
Implement verification methods that check claims against real sources before execution.
Phase 2A validates grounding format (string parsing). Phase 2B resolves grounding claims
by actually checking files, source code, tests, web, and APIs. Ungrounded claims in a
plan block the PLANNING -> EXECUTING FSM transition.

Six verification methods: FILE_CHECK, SOURCE_CHECK, TEST_CHECK, WEB_CHECK, API_CHECK,
API_REGISTRY_CHECK. Each returns a binary pass/fail with evidence string. No confidence
scores — these checks are deterministic (file exists or it does not).

Plan grounding sweep: before EXECUTING, GRC scans all claims in a plan, classifies each
as GROUNDED / VERIFY_NEEDED / UNGROUNDED, runs verification on VERIFY_NEEDED, and blocks
execution if any remain UNGROUNDED after resolution.

Phase 2B also resolves UNCERTAIN grounding levels from phase 2A. Steps with
GroundingLevel::Uncertain that can be resolved via FILE_CHECK or SOURCE_CHECK are
auto-promoted to Verified or High. Those that cannot be resolved remain UNCERTAIN
and are flagged (but not auto-rejected — that policy is per-agent config in 2C).

Forward dependency: Phase 4A changes verification execution model — agents proxy
verification via IPC GroundingRequest messages through the orchestrator. Phase 2B
implements verification as direct function calls; 4A wraps them behind IPC.

DESIGN DECISIONS (grounded)

  D1. Binary verification, not scalar confidence.
      All 6 methods return VerificationResult { passes: bool, evidence: String }.
      FILE_CHECK is inherently binary (file exists or not). SOURCE_CHECK is binary
      (function signature matches or not). TEST_CHECK is binary (test passes or not).
      WEB_CHECK and API_CHECK could theoretically return confidence scores, but we keep
      binary for uniformity — the evidence string carries the detail.
      Grounding: MiniCheck (Tang et al., EMNLP 2024, arxiv:2404.10774) shows claim-level
      fact-checking works well with binary labels. Google Vertex AI grounding API also
      uses binary grounded/ungrounded classification for its fast mode.
      Deterministic benefit: binary results compose cleanly — a plan is GROUNDED iff
      ALL claims pass. No threshold tuning needed.

  D2. Claim decomposition for plan sweep only.
      Individual verify_claim() calls check one claim at a time. Plan sweep (ground_plan)
      must decompose a plan text into individual claims before verifying each.
      Our decomposition is structural (extract file paths, function names, API references),
      not semantic (no NLI model needed). This is simpler and deterministic.
      Grounding: RARR (arxiv:2210.08726) and SAFE (Wei et al., 2024) use LLM-based
      decomposition for semantic claims. Our claims are structural references
      (file:src/main.rs, api:ollama/generate) — regex extraction suffices.
      Phase 2A already validates grounding format as "type:reference" pairs (2A.4 I2),
      so plan sweep reuses that parsed structure.

  D3. VerificationMethod enum for dispatch.
      New enum: VerificationMethod { FileCheck, SourceCheck, TestCheck, WebCheck,
      ApiCheck, ApiRegistryCheck }. verify_claim() takes method + claim + context,
      dispatches to the correct checker. This allows per-method availability filtering
      (Phase 4A restricts which methods agents can use via IPC proxy).
      Grounding: reasoning.txt section 9 (L140-147) defines per-method availability
      by agent role. An enum enables this routing at the type level.

  D4. verified_at via entropy-quarantined timestamp.
      GroundingResult includes verified_at: Timestamp. All time access goes through
      core::entropy::TimeSource trait (Phase 0 entropy quarantine). This ensures
      deterministic testing — test fixtures inject fixed timestamps.
      Grounding: implementation-guide.txt L46 ("all time/randomness via injectable traits").
      reasoning.txt L184: GroundingResult { claim, method, level, source, verified_at }.

  D5. tools/ crate dependency for FILE_CHECK and SOURCE_CHECK.
      Phase 2B adds tools/ as a dependency of reasoning/. FILE_CHECK uses tools::read_file
      to check file existence. SOURCE_CHECK uses tools::read_file + parsing to verify
      function/struct presence. This is the first reasoning/ -> tools/ coupling.
      Grounding: crate map (implementation-guide.txt L64) lists reasoning/ deps as
      (core, providers, tools). The tools/ dep was always planned.
      Risk: tools/ depends on knowledge/ (implementation-guide.txt L65). Circular dep
      risk: reasoning -> tools -> knowledge -> (no reasoning dep, safe).
      Verification: knowledge/ does NOT depend on reasoning/ — confirmed by crate map.
      Note: tools/ also transitively pulls knowledge/ -> providers/. reasoning/ will
      eventually depend on providers/ directly (crate map L64). Not circular, but
      providers/ changes can break reasoning/ through two paths. Acceptable — both
      deps are planned and the crate map reflects this.

  D6. GrcEngine trait signature update (breaking change from 2A stubs).
      Phase 2A defines: fn ground_plan(&self, plan: &str) -> Vec<GroundingResult>
      Phase 2B changes to: fn ground_plan(&self, plan: &str) -> PlanGroundingResult
      This is a breaking change to the trait. PlanGroundingResult wraps Vec<GroundingResult>
      with additional metadata (all_grounded, ungrounded, verify_needed).
      Rationale: Vec<GroundingResult> loses the sweep summary — callers must recompute
      all_grounded by iterating. PlanGroundingResult provides the answer directly.
      Impact: 2A stubs return unimplemented!() so no existing code constructs Vec<GroundingResult>
      from ground_plan. The type change is safe at this point.
      Architecture-overview.txt and reasoning.txt must be updated to reflect new return type.
      PRE_CHECK: grep phase-2A tests for "ground_plan" — if any test calls ground_plan
      and checks the return type, that test must be updated.

  D7. verify_claim gets a context parameter.
      Phase 2A defines: fn verify_claim(&self, claim: &str, source: &str) -> Result<...>
      Phase 2B changes to: fn verify_claim(&self, claim: &str, source: &str, context: &str) -> Result<...>
      The context parameter is needed for SOURCE_CHECK (claim="symbol_name", context="file_path")
      and TEST_CHECK (claim="test_name", context="crate_name"). FILE_CHECK uses claim as
      the file path and ignores context. WEB_CHECK/API_CHECK may use context for search scope.
      This is a breaking change to the trait but the 2A stub is unimplemented!(), so no
      existing code calls verify_claim with 2 args. Safe at this point.
      Architecture-overview.txt must be updated.

  D8. TestRunner trait abstraction for TEST_CHECK.
      TEST_CHECK must run a specific test by name. In production, this calls
      BashSandbox::execute("cargo test --exact {name} -p {crate}", sandbox_config).
      In unit tests, this must be mocked — spawning cargo in every test is too slow
      and non-deterministic.
      Solution: trait TestRunner: Send + Sync { fn run_test(&self, name: &str, crate_name: &str) -> TestRunResult; }
      LocalVerifier takes Box<dyn TestRunner> at construction (dependency injection).
      Production: CargoTestRunner (calls BashSandbox::execute with 30s timeout).
      Test: MockTestRunner (returns configured pass/fail per test name).
      Grounding: tools.txt section 9 (L184-186) defines BashSandbox::execute(command, sandbox_config) -> BashResult.
      This is the correct API — not "bash_exec" or Command::new("cargo").


RISKS TO WATCH
  R-2B-1: tools/ dependency introduces coupling earlier than other phases may expect.
    Mitigation: reasoning/ uses only tools::read_file (leaf function, no graph/index).
    Verify: check tools/Cargo.toml does not depend on reasoning/.
  R-2B-2: WEB_CHECK and API_CHECK require network access. Phase 2B tests must not
    require network. Mitigation: all tests use mock/stub implementations of the checker
    trait. Real network checks only in integration tests (gated by #[cfg(feature="network")]).
  R-2B-3: Plan sweep must handle plans with zero claims (empty plan). Must not panic
    or return UNGROUNDED for an empty plan — empty plan = trivially GROUNDED.
  R-2B-4: Phase 4A will wrap verification behind IPC. Phase 2B's direct-call interface
    must be structured so 4A can wrap it without changing the trait signature.
    Mitigation: verify_claim takes &self (not &mut self), is stateless per call.
