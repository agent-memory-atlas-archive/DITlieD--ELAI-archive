PHASE 1C: VECTOR SEARCH (dual-model ONNX)
Prerequisites: Phase 1B complete

SCOPE: see docs/specs/guide/implementation-guide.txt

GOAL
Semantic code search via dual embedding models (GraphCodeBERT for code, Granite for text)
using ONNX Runtime. Vector cache in SQLite keyed by content hash. Circuit breakers per
model with graceful degradation cascade. Startup readiness gate with canary query.

RISKS TO WATCH
  R22 (MEDIUM): ONNX Runtime GPU contention with main model.
    Embedding on GPU1 only when executor/auditor on GPU0.
    Fallback: all ONNX models CPU-only (slower, zero contention).
    Mitigation in code: ModelPool.can_fit_onnx(model_size) before GPU allocation.

  R26 (MEDIUM): Single ONNX model failure cascading to total knowledge engine outage.
    Mitigation: per-model circuit breaker (knowledge.txt section 6).
    Degradation: HYBRID -> SPARSE_ONLY -> BM25_ONLY. Never total failure.

  R27 (LOW): ONNX startup delay blocking FSM.
    Mitigation: startup readiness gate with canary query embed("fn main()") within 5s.

  R29 (LOW): Cross-encoder concurrency under parallel agents.
    Mitigation: tokio::Semaphore(1) + max queue depth 4.

SCOPE DECISIONS

  SPLADE: DEFERRED to Phase 1G measurement cycle.
    knowledge.txt Section 3 defines pipeline as "BM25 + SPLADE (RRF fused) -> dual-vector rerank".
    knowledge.txt Section 3.25 marks SPLADE as "EVALUATE: measure retrieval improvement vs ONNX dep cost.
    Drop if <5% gain." Phase 1C implements the core dual-vector pipeline without SPLADE.
    Rationale: SPLADE adds a third ONNX model (additional GPU/CPU contention, R22 risk amplified).
    The EVALUATE decision requires measurement data that Phase 1C Step 5 will begin to produce.
    Phase 1G will have throughput baselines to measure SPLADE's incremental gain.
    Impact on Phase 1C: RRF fusion in Step 4 merges BM25 + code_vec + text_vec (3 rankers).
    If SPLADE is added later (Phase 1G), it becomes a 4th RRF ranker — additive, not breaking.
    Circuit breaker scope: Phase 1C implements per-model circuit breakers for GraphCodeBERT and
    Granite only. SPLADE circuit breaker (knowledge.txt Section 6) deferred with SPLADE itself.

  Claims now GROUNDED (originally ungrounded, resolved during improvement):
  [GROUNDED-PAPER] TurboQuant (arXiv:2504.19874, ICLR 2026). Paper ingested 2026-04-06.
    Interface map: workflow/papers/turboquant-interface.md. RAG topic: paper-turboquant.
    Verified distortion (unit-norm): b=2 MSE=0.117, b=3 MSE=0.030, b=4 MSE=0.009.
    Inner product distortion: b=2 0.56/d, b=3 0.18/d, b=4 0.047/d.
    For 768d vectors at b=3: ~3 bits/dim, ~10.7x compression vs f32, InProd error ~0.00023.
    For 384d vectors at b=3: ~3 bits/dim, ~10.7x compression vs f32, InProd error ~0.00047.
    Indexing: ~0.001s vs PQ ~494s at 100k vectors (Table 2, 4-bit).
    Requirements: unit-norm input (store norms externally), QR rotation (NOT Hadamard),
    codebook precomputed per (b,d) via Lloyd-Max. O(d^2) space for rotation matrix.
    Implementation pitfalls: no Hadamard shortcut, no codebook reuse across dimensions,
    no MSE variant for NN search (biased), d must be >=64 for Beta-Gaussian approximation.
    Status: GROUNDED but implementation still deferred to after Phase 1C.
    Phase 1C stores raw f32 vectors. Quantization target: Phase 1G or dedicated phase.
