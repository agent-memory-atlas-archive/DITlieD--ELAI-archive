GOAL
Agent spawning, lifecycle management, checkpointing, crash recovery, supervision tree,
and anti-spiral escalation. Agents run in-process in Phase 3 (Tier A isolation only).
Process separation (Tier C) deferred to Phase 4A.

This phase transforms the claw-code WorkerRegistry (worker_boot.rs, ~1069 LOC) and
recovery_recipes.rs (~630 LOC) into the AgentPool trait defined in architecture-overview.txt
section 4, with full checkpoint/recovery/supervision semantics from orchestrator.txt section 7.

INPUT CONTRACTS (from prerequisite phases)
  From 3B (SSB): ssb::write(action_type, payload) for checkpoint/reasoning_trace writes.
    Invariant: single-writer guarantee, append-only within session, seq monotonic.
  From 3A (FSM): Fsm::get_state() for phase-aware behavior, Fsm::transition() for escalation.
    Invariant: phase-aware tool loading restricts agent tool access per FSM state.
  From 2C (GRC): AgentGrcConfig { budget, required_steps, grounding_level, csq_required }.
    Invariant: per-role config loaded at spawn time, applied to agent GrcEngine instance.
  From 2A (GRC): GrcEngine::think() for structured reasoning within agents.
    Invariant: each ThinkStep produces ReasoningTraceEntry written to SSB.

OUTPUT CONTRACTS (consumed by dependent phases)
  To 3D (BSP): AgentPool::spawn() returns AgentHandle. BSP loop calls prepare_next_tasks
    using agent handles. spawn_parallel STUBBED here (returns Vec<AgentHandle> but runs
    sequentially), implemented with true parallelism in 3D.
  To 3E (Context Budget): AgentHandle exposes agent_id, role, active_files for context
    budget allocator file-overlap scoring (orchestrator.txt section 6).
  To 3F (Rules): Agent tool calls pass through RuleEngine::evaluate() — 3C wires this
    by routing all tool requests through the orchestrator dispatch (not direct tool calls).
  To 4A (Tier C): AgentHandle abstraction is IPC-ready. In 3C it wraps in-process agent.
    In 4A it wraps IPC socket. Same interface, different transport.
  To 3A/4G (ReplanRequest): Agent can emit ReplanRequest(evidence, severity) to orchestrator.
    In 3C this is an in-process method call on orchestrator dispatch. In 4A it becomes IPC message.
    Invariant: max 1 ReplanRequest per agent per phase (orchestrator.txt L425).
    Orchestrator logs to SSB as action_type='replan_request'. Auditor validates evidence
    before any replan. MINOR: fast-track to PLANNING. MAJOR: human gate required.

RISKS TO WATCH
  R6 (MEDIUM): Agent parallelism resource contention. In Phase 3 (single GPU), all agents
    share one model. VRAM check before spawn: if model loaded + embedding model > available
    VRAM, serialize agents (never parallel on 12GB). Mitigation built into spawn().
  R31 (HIGH): Agent learns enforcement patterns. Relevant because 3C defines what agents
    CAN see. Tier A invisible walls (orchestrator.txt section 12) must be wired into
    agent tool dispatch: hidden paths return "not found", not "denied".

  3C.6 ANTI-SPIRAL DETECTION AND ESCALATION
    PRE_GATE:
      - 3C.5 tests pass (supervision tree operational)
      - GRC step tracking available (step_type and topic recorded per agent)
    TASK:
      - Implement anti-spiral detection (orchestrator.txt L135, L142-143):
        Track per-agent: last N GRC steps (step_type + topic + content_hash).
        If same_step_count > 3 (same step_type + same topic + similar content for 3
        consecutive steps), classify as SPIRAL.
        "Similar content" = content_hash matches (not string equality — allows minor
        rephrasing but catches substantive repetition). Hash = blake2s of normalized
        content (lowercase, whitespace-collapsed).
      - On SPIRAL detection:
        1. Checkpoint current state (safety net).
        2. Inject escalation signal: GRC convergence with step_type="status",
           content="Anti-spiral: 3x repeated step detected. Converge or request help."
        3. If agent produces ANOTHER identical step after escalation signal: supervisor
           stops the agent (not restart — permanent stop for this task).
