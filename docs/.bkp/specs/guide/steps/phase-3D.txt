PHASE 3D: BSP SUPERSTEPS + CHANNELS
Prerequisites: Phase 3B (SSB) complete, Phase 3C (Agent system) complete.

SCOPE: see docs/specs/guide/implementation-guide.txt

GOAL
Deterministic macro-level orchestration via BSP superstep model (Valiant 1990).
4 channel types for inter-agent state sharing. BinaryOp intentionally dropped
(non-deterministic with concurrent writes; see audit BLOCK 4).
Determinism guarantee: all channel combiners are either total-ordered (LastValue via
SSB seq) or append-only with deterministic ordering (Topic via SSB seq). This satisfies
Blelloch et al. (CMU 2012) requirement that parallel combiners must be commutative+
associative or linearizable for internal determinism.
IMPORTANT: the determinism guarantee applies in deterministic simulation mode (mocked
agents with fixed seed). With real LLM agents, straggler timeouts may remove different
agents across runs, producing different superstep participation sets. Channel combiners
are well-defined on partial inputs (LastValue: last surviving writer; Topic: subset of
appends), but byte-identical checkpoint reproduction requires identical agent sets.

RISKS TO WATCH
  R19: UntrackedValue memory accumulation. Monitor per superstep.
    Threshold: configurable in elai_cc.toml [orchestrator.bsp.untracked_memory_limit_bytes].
    Default: 10MB per UntrackedValue channel. Force-clear when usage exceeds 2x limit.
    Measurement: custom DeepSizeOf trait (NOT std::mem::size_of_val which only measures
    stack representation — a Vec<u8> with 15MB data returns 24 bytes via size_of_val).
    Require T: DeepSizeOf bound on UntrackedValue<T>. Use deepsize crate or hand-roll.
  R-NEW-1: Straggler agents blocking barrier. LLM calls have variable latency (seconds
    to minutes). Mitigation: per-agent superstep timeout, reusing Phase 3C heartbeat
    timeout (15s default). Agent exceeding timeout classified as AgentDeath::TIMEOUT,
    removed from barrier wait set. Remaining agents proceed.
    Source: CMU HotOS'13 "Solving the Straggler Problem with Bounded Staleness".
  R-NEW-2: Barrier deadlock if agent crashes mid-superstep without triggering timeout.
    Mitigation: Phase 3C supervision tree detects crash (CLEAN_EXIT/CRASH/TIMEOUT
    classification). Crashed agent removed from current superstep barrier. Orchestrator
    does not wait for dead agents.

    - Define channel enum and 4 channel type structs in orchestrator/src/bsp/channels.rs:
      - LastValue<T>: single value, last writer wins. Writer ordering = SSB seq (monotonic).
        Read returns Option<T> (None if never written).
      - Topic<T>(accumulate: bool):
        accumulate=true: append-only Vec<T>, persists across supersteps.
        accumulate=false: Vec<T> cleared to empty at superstep boundary. Two-phase reset:
          (1) snapshot current state for prepare_next_tasks scheduling reads,
          (2) clear to empty Vec before execute_tasks writes new values.
          This prevents stale data from influencing task selection (WARN-7 fix).
        Append ordering follows SSB seq within a superstep.
      - EphemeralValue<T>: fire-and-forget signal. Cleared to MISSING on any superstep
        where write_count == 0. Detection: u32 write counter per channel per superstep,
        incremented on write (saturating_add to prevent overflow), checked at barrier.
        Clearing decision recorded in SSB as action_type='checkpoint' with subtype
        'ephemeral_clear' so crash recovery can replay clearing deterministically from
        SSB data alone (WARN-8 fix: count writes per channel per superstep in SSB,
        if count==0 for a superstep, set MISSING during replay).
      - UntrackedValue<T: DeepSizeOf>: in-memory only, never serialized to checkpoint.
        guard=false allows multi-writer. Persists until overwritten or force-cleared.
        Lost on crash. T must implement DeepSizeOf trait for R19 memory monitoring.

    - Define ChannelState enum for checkpoint serialization (excludes UntrackedValue).

3D.2 BSP SUPERSTEP LOOP
  PRE_GATE:
    - Step 3D.1 ACCEPTANCE criteria met (all channel types defined and tested)
    - SSB single-writer channel operational (Phase 3B): cargo test -p contracts --test ssb_write
    - Spec amendment 4 applied to orchestrator.txt (save_checkpoint placement fix)
  TASK:
    - Implement superstep loop in orchestrator/src/bsp/engine.rs.
      NOTE: loop structure differs from orchestrator.txt section 4 pseudocode.
      save_checkpoint moved AFTER evidence_gate_passes to prevent checkpoint filename
      collision on gate retry (auditor BLOCK-4). The spec must be amended (amendment 4).
      Corrected loop:
        loop {
            channel_snapshot = channels.snapshot_for_scheduling();
            tasks = prepare_next_tasks(checkpoint, channel_snapshot, nodes);
            if tasks.empty() { break; }
            // clear Topic(accumulate=false) AFTER snapshot, BEFORE execute
            channels.clear_non_accumulating_topics();
            writes = execute_tasks_parallel(tasks, model_pool, ssb);
            apply_writes(checkpoint, channels, writes);
            // deferred phase in step 3D.3
            // EphemeralValue clearing: check write_count, record in SSB
            channels.clear_ephemeral();  // logs clearing to SSB for replay
            if !evidence_gate_passes(checkpoint, channels) {
                attempt += 1;
                if attempt >= max_superstep_attempts { break; }  // safety valve
                continue;
            }
            save_checkpoint(checkpoint, channels);  // AFTER gate passes
            superstep += 1;
            attempt = 0;
        }
    - prepare_next_tasks: reads channel_snapshot (frozen, pre-clear), determines ready nodes.
    - execute_tasks_parallel: dispatches to agent pool via spawn_parallel (Phase 3C).
      Collects ChannelWrite results. Each write recorded in SSB.
    - apply_writes: applies ChannelWrites to channels in SSB seq order (deterministic).
    - save_checkpoint: serializes HashMap<ChannelId, ChannelState> for LastValue+Topic+
      Ephemeral. UntrackedValue excluded. Format: msgpack. Location:
      .elai_cc/sessions/{sid}/checkpoints/superstep_{N}.msgpack
      Only written after gate passes — no collision, no overwrite on retry.
    - evidence_gate_passes: checks whether phase transition evidence is sufficient.
      Returns false to retry superstep. Max attempts: configurable (default 3 per
      superstep, distinct from max_supersteps which limits total supersteps to 100).
    - superstep counter: u64, persisted in checkpoint. Monotonically increasing.
    - Straggler handling: per-agent timeout at barrier (default: Phase 3C heartbeat
      timeout, 15s). On timeout: remove agent from barrier wait set, classify as
      AgentDeath::TIMEOUT, trigger supervision restart policy. Remaining agents proceed.
  DETERMINISTIC_CHECK:
    - cargo test -p orchestrator --test bsp_loop -- superstep counter increments correctly
    - Determinism proof (simulation mode): run same superstep sequence with fixed seed
      and mocked agents twice, compare checkpoint files byte-for-byte (must be identical)
    - Superstep counter persists in checkpoint: load checkpoint, assert superstep == expected
    - No checkpoint file written on failed gate: trigger gate failure, verify no superstep_{N}.msgpack created
  ADVERSARIAL:
    - If apply_writes does not use SSB seq order, non-deterministic channel state results.
      Test: inject 10 writes with shuffled timestamps, verify apply_writes sorts by seq before applying.
    - If evidence_gate_passes is never false, infinite loop if tests never pass.
      Test: inject always-false gate, verify loop terminates after max_superstep_attempts.
    - If straggler timeout is too short, legitimate long LLM calls get killed.
      Test: set timeout=1ms, verify agent receives TIMEOUT classification (not CRASH).
    - If save_checkpoint still runs before gate, retry overwrites checkpoint.

  ACCEPTANCE:

      - At each superstep boundary, call deep_size_untracked(id) for each UntrackedValue channel.
      - Log to SSB as action_type='memory_monitoring' (NEW action type, not isolation_metric).
        Payload: {channel_id, size_bytes, threshold_bytes, action: "measure"|"force_clear"}.
        isolation_metric remains exclusively for cognitive token savings (orchestrator.txt 7A).
      - If size > 2x configured limit (default 10MB): log warning with action="force_clear",
        clear channel, record event in SSB.
    - EphemeralValue zero-write detection:
      - Per-channel write_count: u32, reset to 0 at superstep start.
      - Incremented on each write() call via saturating_add.
      - At barrier (in clear_ephemeral): if write_count == 0, set value to MISSING.
      - Record clearing decision in SSB for crash recovery replayability:
        action_type='checkpoint', payload includes ephemeral_clears: Vec<ChannelId>.
        On recovery replay: for each superstep, count writes to each EphemeralValue in
        SSB entries. If count == 0, set MISSING. This makes clearing deterministic from
        SSB data alone, without requiring runtime write_count state.
    - Topic(accumulate=false) superstep reset:

        (2) clear_non_accumulating_topics() clears to empty Vec AFTER snapshot but BEFORE
        execute_tasks writes new values.
      - Checkpoint contains the post-execute state (new writes), not the pre-clear snapshot.
    - Crash recovery: on restart, load latest checkpoint, replay SSB entries since
      checkpoint superstep to reconstruct channel state. For each replayed superstep:
        1. Apply writes in SSB seq order (same as live apply_writes).
        2. For EphemeralValue: count writes per channel in that superstep. If 0, set MISSING.
        3. For Topic(accumulate=false): clear at superstep boundary start before applying writes.
