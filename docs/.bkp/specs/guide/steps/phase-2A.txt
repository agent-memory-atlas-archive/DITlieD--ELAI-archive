PHASE 2A: GRC STATE MACHINE (basic)
Prerequisites: Phase 0 complete (all contract tests pass, cargo check clean)

SCOPE: see docs/specs/guide/implementation-guide.txt

GOAL
Implement the Grounded Reasoning Chain engine core. All reasoning must cite grounding
sources. Budget system enforces per-topic call and character limits. State machine
validates transition order. Rejected steps produce typed errors.

This phase covers the GRC state machine, budget system, and grounding validation only.
Grounding verification methods (FILE_CHECK, WEB_CHECK, etc.) are phase 2B.
Per-agent configuration is phase 2C. CSQ is phase 2D.

DESIGN DECISIONS (grounded)

  D1. State transition validation via allowed_transitions map.
      The GRC state machine (observe -> hypothesize -> plan_action -> act -> verify) must
      reject invalid transitions (e.g., hypothesize -> verify skipping plan_action).
      Implementation: GrcState enum with fn allowed_next(&self) -> &[GrcState].
      Grounding: standard FSM practice. Guidance-ai uses similar FSM-from-schema
      token masking (github.com/guidance-ai/guidance). Our version validates at the
      step level, not token level.

  D2. Typed error enum for all rejection modes.
      GrcError { UngroundedStep, BudgetExhausted, InvalidTransition, MalformedGrounding }.
      Each variant carries context (which step, what was missing, what was expected).
      Grounding: standard Rust error handling (thiserror pattern).

  D3. Budget tracking with forced convergence.
      GrcBudget tracks remaining_calls and remaining_chars, decremented atomically per step.
      When remaining_calls <= 1, the engine forces a convergence step (must produce conclusion).
      Grounding: BudgetThinker (OpenReview 2025, openreview.net/forum?id=ahatk5qrmB) inserts
      budget-remaining signals; Token-Budget-Aware LLM Reasoning (ACL 2025) adjusts tokens
      by complexity. Our version enforces hard limits at the engine level.

  D4. Grounding field validation decomposes content into claims.
      Instead of just checking "grounding field present," validation parses the grounding
      string into individual source citations and verifies each is well-formed
      (format: "source_type:reference", e.g., "file:src/foo.rs:L42").
      Phase 2B adds actual source verification; phase 2A validates format only.
      Grounding: RARR (arxiv:2210.08726) decomposes LLM output into claims for per-claim
      verification. SAFE (arxiv:2403.18802) does similar decomposition.

  D5. GroundingLevel enum matching spec hierarchy.
      VERIFIED > HIGH > UNCERTAIN. Steps with UNCERTAIN grounding are flagged (warn log)
      but not rejected in phase 2A. Phase 2B adds resolution of UNCERTAIN claims.
      Grounding: reasoning.txt section 4 defines these three levels.

  2A.4 IMPLEMENT: GRC state machine logic
    PRE_GATE:
      - Step 2A.3 complete (tests written, all currently fail)
      - No other session owns reasoning/ files
        (checked by mcp_session_claim at EXECUTING entry)
    TASK:
      Implement BasicGrcEngine in reasoning/src/engine.rs:

      I1. State transition validation:
          Maintain last_state per topic. On think(), check step.step_type is in
          last_state.allowed_next(). If not, return Err(InvalidTransition).
          Special cases:
            - First step in a topic: must be Observe (no last_state).
            - Status step: allowed from any state, does not update last_state.
            - Converge step: allowed from any state (forced convergence path).

      I2. Grounding validation:
          For steps requiring grounding (Observe, Hypothesize, Verify):
            - If grounding is None: return Err(UngroundedStep).
            - If grounding is Some(s): parse s as comma-separated "type:reference" pairs.
              Valid types: "file", "grep", "test", "search", "tool", "training".
              Malformed -> Err(MalformedGrounding).
            - Classify each citation's GroundingLevel:
              "test"/"search" -> Verified, "file"/"grep"/"tool" -> High, "training" -> Uncertain.
              Rationale: "search" = web-verified (reasoning.txt s4: "searched" = VERIFIED).
              "tool" = tool output read this session (equivalent to file/grep = HIGH).
            - Log warning for Uncertain citations (do not reject in phase 2A).
          For PlanAction, Act: grounding optional (these are action steps).
          For Status: no grounding required, no budget consumed.

      I3. Budget enforcement (check-then-increment pattern):
          On each think() call (except Status):
            - CHECK FIRST: if calls_used >= max_calls, return Err(BudgetExhausted) immediately.
            - CHECK FIRST: if chars_used + step.content.len() > max_chars,
              return Err(BudgetExhausted) immediately.
            - CHECK FIRST: if must_converge() (remaining_calls <= 1) and step_type != Converge,
              return Err(BudgetExhausted) with message indicating forced convergence needed.
            - THEN INCREMENT: calls_used += 1, chars_used += step.content.len()
              (use saturating_add to prevent u32 overflow).
          Rationale: increment-before-check corrupts budget state on the error path.
          After returning BudgetExhausted, calls_used would be max_calls+1, making
          subsequent budget queries return incorrect remaining values.

      I4. Topic isolation:
          Each topic has independent TopicState { budget, last_state, steps, grounding_log }.
          Default budget from global config (configurable via set_budget).
          reset_topic() clears all state for a topic.

      I5. ThinkResult construction:
          Return ThinkResult { step: ThinkStep, budget_remaining: GrcBudget,
            grounding_level: Option<GroundingLevel>, warnings: Vec<String> }.

EXIT CRITERIA
  GRC enforces grounding on every step that requires it (Observe, Hypothesize, Verify).
  Budget overflow triggers convergence or returns BudgetExhausted error.
  Invalid state transitions are rejected with InvalidTransition error.
  Malformed grounding strings are rejected with MalformedGrounding error.
  Status steps are free (no budget consumed, no grounding required).
  Per-topic budgets are independent.
  Scope enumeration validated when require_scope_enumeration=true (WARN on unaddressed items).
  All 12+ tests pass. Zero todo!/unimplemented!/unwrap() in engine code.
