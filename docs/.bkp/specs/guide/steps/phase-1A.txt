PHASE 1A: DKG (tree-sitter -> SQLite graph)
Prerequisites: Phase 0 complete (9-crate layout exists, cargo check passes)
Canonical path: determined by Phase 0. Expected: .elai_cc/crates/knowledge/
  PRE_GATE resolves dynamically: KNOW_PATH=$(find .elai_cc -path "*/knowledge/Cargo.toml" | head -1 | xargs dirname)

  Phase 0 references .elai_cc/rust/crates/ correctly (pre-restructure layout).

SCOPE: see docs/specs/guide/implementation-guide.txt

GOAL
Parse source code into a dependency knowledge graph stored in SQLite.
First layer of the knowledge pipeline (see knowledge.txt Layer 1).
Downstream consumers: Phase 1D (PageRank) reads DKG edges for adjacency matrix.
  Phase 1E (CatRAG) traverses DKG graph for evidence chains.
  Phase 1B (BM25) runs independently but shares the readiness gate.

NOTE: knowledge.txt header said "FIVE LAYERS" — corrected to "5 major + 2 sub-layers".
  Architecture-overview.txt says "7 layers" (L100) counting sub-layers 3.25 and 3.5.
  Both now consistent. DKG is Layer 1.

COMPLIANCE SCOPE (what this phase does and does NOT implement)
  knowledge.txt Sec 8 "TREE-SITTER PARSE FAILURE FALLBACK" has 5 items:
    1. File excluded from DKG graph (no AST nodes)         -> IMPLEMENTED in Phase 1A
    2. File STILL indexed by BM25                          -> DEFERRED to Phase 1B (BM25 layer)
    3. File STILL embedded by vector models                -> DEFERRED to Phase 1C (vector layer)
    4. PageRank treats file as leaf node                   -> DEFERRED to Phase 1D (PageRank)
    5. Parse failure logged. Retried on next file change.  -> IMPLEMENTED in Phase 1A
  Invariant "every file in project appears in at least BM25 index" (L177) is NOT achievable
  until Phase 1B. Phase 1A tracks parse-failed files so Phase 1B can index them.

      - Design SQLite schema for DKG graph:
        Table: dkg_nodes (
          id INTEGER PK,
          file_path TEXT NOT NULL,
          name TEXT NOT NULL,
          kind TEXT NOT NULL,          -- maps to SymbolKind enum
          signature TEXT NOT NULL DEFAULT '',  -- reconstructed from AST for Phase 1D
          start_line INTEGER NOT NULL,
          end_line INTEGER NOT NULL,
          parent_id INTEGER REFERENCES dkg_nodes(id),
          concept TEXT DEFAULT NULL,   -- populated by context-compiler in MEMORIZING (knowledge.txt L25)
          concept_stale INTEGER NOT NULL DEFAULT 1,  -- 1=stale/unset, 0=current (knowledge.txt L31-32)
          file_hash BLOB NOT NULL      -- blake2s of file content, for incremental staleness (knowledge.txt L31)
        )
        Table: dkg_edges (
          source_id INTEGER REFERENCES dkg_nodes(id) ON DELETE CASCADE,
          target_id INTEGER REFERENCES dkg_nodes(id) ON DELETE CASCADE,
          edge_type TEXT NOT NULL,     -- one of: "imports", "contains", "implements"
          PRIMARY KEY (source_id, target_id, edge_type)
        )
        Edge type semantics (directed graph — edge direction matters):
          "imports"    — source module/file -[imports]-> target symbol (use_declaration resolution)
          "contains"   — parent -[contains]-> child (module->fn, impl->method, struct->field)
          "implements" — impl block -[implements]-> trait (when trait is in the same codebase)
        Reason: Phase 1D (PageRank) needs typed directed edges for weight boosting (knowledge.txt L67).
          Phase 1E (CatRAG) traverses directed edges for evidence chains (knowledge.txt L79).
        Table: dkg_files (
          file_path TEXT PK,
          file_hash BLOB NOT NULL,     -- for quick per-file staleness check without scanning dkg_nodes
          parse_status TEXT NOT NULL DEFAULT 'pending',  -- 'ok', 'failed', 'pending'
          parse_error TEXT DEFAULT NULL,
          last_indexed INTEGER NOT NULL  -- unix timestamp
        )
        Reason: tracks parse failures for Phase 1B (BM25 must index parse-failed files).
          Also enables O(1) file-level staleness check without scanning dkg_nodes.
        Table: dkg_meta (key TEXT PK, value TEXT)
          Initial rows: ('schema_version', '1'), ('created_at', unix_timestamp)
        Index: idx_nodes_name ON dkg_nodes(name)
        Index: idx_nodes_file ON dkg_nodes(file_path)
        Index: idx_nodes_kind ON dkg_nodes(kind)
        Index: idx_files_status ON dkg_files(parse_status)  -- for Phase 1B to query failed files
        ON DELETE CASCADE on dkg_edges ensures node deletion cascades correctly during incremental update.
      - Create index_version.toml at project-scoped path (provided by caller):
