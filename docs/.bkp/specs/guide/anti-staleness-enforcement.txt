PROBLEM STATEMENT

LLMs default to frequency-based retrieval from training distribution. If blake2
appeared 10,000 times in training data and blake3 appeared 50 times near cutoff,
the model mathematically favors blake2. This is not a bug — it is an architectural
inevitability of static training (Doc 1, "parametric memory is structurally hostile
to temporal accuracy").

Measured impact (from ICSE 2025 "LLMs Meet Library Evolution"):
  - Java: 72% AI failure rate on deprecated APIs
  - Python: 38% failure rate on deprecated APIs
  - ~40% increase in failure rate for post-cutoff library versions (VersiCode)
  - 2.74x more security vulnerabilities in AI-generated PRs vs human-written

ELAI-specific audit (2026-04-13, outdated-tech-audit.md):
  - 9 critical findings (blake2, wrong torch kwarg, fake streaming, etc.)
  - 14 high findings (outdated rand, dual logging, unwrap violations)
  - Root cause: every finding traces to the model picking the training-era default
    over the current best practice

Small models (3B-7B, e.g. Qwen2.5-Coder) are especially vulnerable due to
limited parametric capacity (Doc 2: "parameter-efficient models are especially
vulnerable to library version hallucination"). Measured: 7B API hallucination
rate 40% baseline, 100% with DoLa (baseline_findings_and_actions.md Part 7).
External orchestration, not internal reasoning, is the solution (Doc 3 key theme 6).
Gemma 4 E2B: REJECTED (mixed head_dim blocks FA2, 18x larger KV cache).


ARCHITECTURE: FOUR-LAYER DEFENSE-IN-DEPTH

Research consensus (Doc 1-3): single-point mitigation fails. Defense-in-depth
across pre-generation, during-generation, post-generation, and maintenance is
mandatory. ELAI already has building blocks for all four layers.


LAYER 1: PRE-GENERATION (context assembly)
Integration: Phase 3E (context budget) + Phase 3F (rules engine) + Phase 1E (RAG pipeline)

  1.1 FRESHNESS SCORING IN RAG RETRIEVAL

    Current: RRF fusion (BM25 + code_vec + text_vec) in knowledge/src/pipeline.rs
    uses cosine similarity only. No temporal signal.

    Change: Add recency decay factor to RRF scoring.

    Formula (revised per BLOCK-2 and WARN-2):
      relevance = cosine_sim * recency_decay * access_boost
      recency_decay = exp(-t * ln2 / half_life_days)
        where t = (now - last_modified) in days
        half_life_days: configurable, default 180 (6 months = 50% weight)
        Floor: max(min_decay, recency_decay) where min_decay = 0.05
      access_boost = 1.0 + ln(1.0 + access_count / boost_normalization)
        boost_normalization: configurable, default 15
        Hard cap: min(access_boost, 2.0)

    Rationale for formula changes (from BLOCK-2, WARN-2):
      - Exponential decay replaces quadratic: at 30 days a document retains 89%
        (not 99.3%), at 180 days retains 50%, at 365 days retains 25%. Significantly
        more aggressive for the code indexing use case vs web crawl.
      - Logarithmic access_boost with hard cap at 2.0x: prevents frequently-used
        stale code (blake2, used hundreds of times) from dominating fresh code.
        At 100 accesses: boost = 1.0 + ln(1 + 100/15) = 1.0 + ln(7.67) = 3.04,
        capped to 2.0. Fresh code with 0 accesses: boost = 1.0. Max ratio = 2.0x
        (was unbounded, reaching 7.2x+ in original formula).

    Implementation (revised per BLOCK-6):
      - Freshness metadata stored in SIDECAR SQLite table (freshness_meta.db),
        NOT in tantivy BM25 schema or vector_cache schema. This avoids tantivy
        schema fingerprint breakage on upgrade. Tantivy and vector_cache schemas
        remain unchanged.
      - freshness_meta.db schema:
          CREATE TABLE file_freshness (
              file_path TEXT PRIMARY KEY,
              last_modified_epoch INTEGER NOT NULL,
              access_count INTEGER NOT NULL DEFAULT 0
          );
      - Populated from filesystem mtime during DKG build_graph and BM25 index_file.
      - pipeline.rs rerank stage: JOIN result chunk paths against freshness_meta.db,
        multiply freshness factor into RRF score. Missing entries default to
        recency_decay=1.0, access_boost=1.0 (no penalty for untracked files).
      - Docs/specs/changelogs: separate half_life (default 90 days, more aggressive)
        configurable via FreshnessConfig.doc_half_life_days.

    Phase touched: 1E (pipeline.rs), new file: knowledge/src/freshness.rs
    New types: FreshnessConfig { half_life_days, doc_half_life_days, boost_norm,
               min_decay, max_boost }
    No tantivy/vector_cache schema changes required.

      deprecated_patterns table:
        pattern_id TEXT PRIMARY KEY,
        ecosystem TEXT NOT NULL,        -- "cargo" | "pip" | "npm" | "go" | "maven"
                                        --   | "nuget" | "bundler" | "composer"
        deprecated_name TEXT NOT NULL,  -- "blake2" | "rand 0.8" | "http.server"
        replacement_name TEXT NOT NULL, -- "blake3" | "rand 0.9" | "fastapi+uvicorn"

        severity TEXT NOT NULL,         -- "BLOCK" | "WARN"

      Ecosystem coverage (language-parameterized):
        cargo:    Rust crates (crates.io)
        pip:      Python packages (PyPI)
        npm:      JavaScript/TypeScript packages (npmjs.com)
        go:       Go modules (proxy.golang.org)
        maven:    Java/Kotlin packages (Maven Central)
        nuget:    C#/.NET packages (nuget.org)
        bundler:  Ruby gems (rubygems.org)
        composer: PHP packages (packagist.org)

    VERSION_GATE predicate evaluation (revised per WARN-3, language-parameterized):
      1. Extract imports/dependencies from code action via language-specific regex sets:
         a. Source imports (per language):
            Rust:       r"use\s+(\w+)" / r"extern crate (\w+)"
            Python:     r"import\s+(\w+)" / r"from\s+(\w+)\s+import"
            Go:         r'"([\w./]+)"' inside import blocks
            TypeScript: r"from\s+['\"]([^'\"]+)['\"]" / r"require\(['\"]([^'\"]+)"
            Java:       r"import\s+([\w.]+)" (extract package root)
            C#:         r"using\s+([\w.]+)" (extract namespace root)
            Ruby:       r"require\s+['\"](\w+)" / r"gem\s+['\"](\w+)"
         b. Dependency declarations (per ecosystem):
            cargo:      '{name}\s*=' in TOML [dependencies] sections
            pip:        '{name}' in requirements.txt/pyproject.toml [project.dependencies]
            npm:        '"{name}"' in package.json dependencies/devDependencies
            go:         '{module}' in go.mod require block
            maven:      '<artifactId>{name}</artifactId>' in pom.xml
            nuget:      'Include="{name}"' in .csproj PackageReference
            bundler:    "gem '{name}'" in Gemfile
      2. Cross-reference against deprecated_patterns table (ecosystem-filtered)
      3. Return BLOCK (if severity=BLOCK) or WARN (if severity=WARN)
      This ensures both source imports AND dependency declarations are caught
      across all supported languages and ecosystems (addresses WARN-3).

    Seed data: populate from outdated-tech-audit.md findings (blake2, rand 0.8,
    http.server, log crate, async-trait, Box<dyn Error>, etc.)

    Self-discovery integration (revised per WARN-4):
      When auditor finds a deprecated usage 3+ times, auto-propose VERSION_GATE rule.
      Requires extending ViolationRecord with optional replacement_name: Option<String>

      The auditor must provide replacement_name in its finding for this pathway to fire.

    Phase touched: 3F (rules/src/predicate.rs, rules/src/self_discovery.rs)
    New types: DeprecatedPattern, VersionGatePredicate
    Changed types: ViolationRecord gains replacement_name: Option<String>

  2.1 ETC (ENTROPY-TREND CONSTRAINT) MONITORING

    REVISED ARCHITECTURE (per BLOCK-1 and BLOCK-7):

    The original design added ETC to the manual Python token loop (server.py:391-436).
    Audit finding C-04 mandates replacing that loop with model.generate() +
    LogitsProcessor for 10-50x speedup. These are mutually exclusive in the same
    code path.

    Resolution: implement ETC as a HuggingFace LogitsProcessor subclass.

    class ETCLogitsProcessor(LogitsProcessor):
        """Monitors entropy trends during model.generate() and flags
        high-uncertainty tokens for post-generation search."""

        def __init__(self, threshold, import_pattern):
            self.H_prev = 0.0
            self.dH_prev = 0.0
            self.triggered = False
            self.trigger_token_idx = -1
            self.threshold = threshold
            self.import_pattern = import_pattern  # compiled regex

        def __call__(self, input_ids, scores):
            probs = torch.softmax(scores, dim=-1)
            H = -(probs * probs.log()).sum(dim=-1).item()
            dH = H - self.H_prev
            d2H = dH - self.dH_prev
            self.H_prev = H
            self.dH_prev = dH

            if d2H > self.threshold:
                # Decode recent tokens to check if import-context
                recent = tokenizer.decode(input_ids[0, -20:])
                if self.import_pattern.search(recent):
                    self.triggered = True
                    self.trigger_token_idx = input_ids.shape[1]

            return scores  # never modify scores, only observe

    Usage in model.generate():
        etc = ETCLogitsProcessor(threshold=..., import_pattern=IMPORT_RE)
        output = model.generate(
            input_ids,
            max_new_tokens=max_tokens,
            logits_processor=[dola_processor, etc],
            ...
        )
        if etc.triggered:
            # Post-generation: extract partial output up to trigger point,
            # call orchestrator search API, regenerate from trigger point
            # with search results injected into context
            partial = output[0, :etc.trigger_token_idx]
            search_result = call_orchestrator_search(partial)
            regenerated = model.generate(
                torch.cat([input_ids, partial, encode(search_result)]),
                max_new_tokens=max_tokens - etc.trigger_token_idx,
                ...
            )

    This preserves model.generate() speed (C-04 fix) while still detecting
    high-entropy moments. The search happens BETWEEN generation calls, not
    mid-token.

    Threshold (revised per BLOCK-7):
      Default: UNCALIBRATED. Must run calibration before deployment.
      Calibration procedure:
        1. Generate 100 code completions with ETC logging enabled (threshold=0)
        2. Record all d2H values and their token contexts
        3. Compute percentile distribution of d2H at import-context tokens vs
           non-import tokens
        4. Set threshold at p95 of non-import d2H (meaning: only triggers when
           uncertainty is higher than 95% of normal generation tokens)
        5. Store calibrated threshold in elai_cc.toml [inference.etc_threshold]
      Until calibrated, ETC is DISABLED (threshold = f64::INFINITY).
      Calibration script: metrics/calibrate_etc_threshold.py

    Phase touched: 3J (server.py, after C-04 model.generate migration)
    New types (Python): ETCLogitsProcessor, ETCCalibrationResult
    New types (Rust): SearchTriggerPayload in providers/src/sidecar_client.rs
    Prerequisite: C-04 (replace manual token loop with model.generate) MUST be
    implemented first. ETC cannot coexist with the manual loop.

    IMPORTANT: ETC uses LogitsProcessor which is compatible with model.generate().
    DoLa also uses LogitsProcessor. However, DoLa is HARMFUL on 7B models
    (measured 2026-04-14: -15% code quality, -6% factuality, 4.7x slower,
    destroys stop-token distribution). ETC and DoLa LogitsProcessors must NOT
    be stacked on models < 32B. ETC should be the ONLY LogitsProcessor on
    7B/14B. DoLa is only viable on 32B+ (64 layers, untested but projected).
    Target model for ETC calibration: Qwen2.5-Coder-7B (not Gemma).

  2.2 FRESHNESS STEERING VECTOR

    Current: Phase 3J.5 implements ActAdd steering vectors with per-role
    contrast pairs and mid-layer injection. Existing vector: "skepticism.npz"
    (computed in metrics/compute_steering_vector.py).

    Change: Compute a "modern_api_preference" steering vector from contrast pairs.

    Contrast pairs (revised per WARN-1 — equal token length templates):
      All pairs use identical template structure to avoid positional encoding
      contamination. Template: "The recommended {domain} library is {name}"

      Positive examples (modern):
        "The recommended hashing library is blake3"
        "The recommended async mutex is tokio sync Mutex"
        "The recommended random library is rand zero point nine"
        "The recommended inference context is torch inference mode"
        "The recommended web framework is FastAPI with uvicorn"

      Negative examples (deprecated):
        "The recommended hashing library is blake2"
        "The recommended async mutex is standard sync Mutex"
        "The recommended random library is rand zero point eight"
        "The recommended inference context is torch no grad"
        "The recommended web framework is http server BaseHTTPRequestHandler"

      Token length difference between each pair: <= 2 tokens (due to name length
      variation). The template prefix is identical, so hidden state at the
      divergence point captures the semantic difference, not positional artifacts.

    Steering formula (from Doc 3, "TTSV"):
      v_fresh = (1/N) * sum(h_modern_i - h_deprecated_i)
      Hidden state extracted at the LAST shared token position (just before names
      diverge), not at sequence end. This further isolates the semantic direction.
      Inject at mid-layers: h'_pos = h_pos + alpha * v_fresh
      alpha: configurable, default 0.3 (conservative to avoid coherence loss)

    Compute script: metrics/compute_steering_vector.py must be extended to accept
    multiple pairs (current: single pair). Batch all pairs, average the difference
    vectors.

    Auto-update: when deprecated_patterns table changes, trigger recomputation.
    Store at: models/steering_vectors/modern_api.npz

    MEASURED STATUS (2026-04-14, baseline_findings_and_actions.md):
      Steering on Qwen2.5-Coder-7B: NEUTRAL. Infrastructure works (vectors
      compute, store, apply via forward hooks), but generic contrast pairs
      have zero measurable effect on output quality. Domain-specific pairs
      (the anti-staleness pairs above) have not been tested yet.
      Possible causes: coefficient=5.0 may need tuning for hidden_dim=3584,
      layer 9 (n_layers//3) may not be optimal, pairs too generic.
      Ship DISABLED by default. Enable after domain-specific pair testing.

    Phase touched: 3J.5 (steering vectors), metrics/compute_steering_vector.py
    Risk: if alpha too high, output quality degrades (Doc 3 warning). Must tune.

  2.3 CONSTRAINED DECODING FOR IMPORTS (vLLM only, feature-gated)

    Current: Phase 3J mentions vLLM integration with cfg(feature="vllm").
    vLLM supports XGrammar for constrained decoding.

    REVISED APPROACH (per BLOCK-4):
    Negative lookahead regex (e.g. "(?!blake2)") cannot compile to finite automata.
    XGrammar and Outlines use FSM-based engines that only support regular languages.
    Negative lookahead is PCRE-class and will fail at compile time.

    Resolution: use POSITIVE ALLOWLIST via JSON Schema, not negative regex.

    Implementation:
      - Generate JSON Schema from deprecated_patterns table:
        {
          "type": "object",
          "properties": {
            "imports": {
              "type": "array",
              "items": {
                "type": "string",
                "enum": ["blake3", "rand 0.9", "tokio::sync::Mutex", ...]
              }
            }
          }
        }
      - Use vLLM guided_json mode (not guided_regex) for import-context lines
      - Alternative: use EBNF grammar that enumerates allowed crate names:
          import_stmt ::= "use " allowed_crate "::" rest_of_path ";"
          allowed_crate ::= "blake3" | "tokio" | "tracing" | "thiserror" | ...
        XGrammar supports EBNF natively (verified: XGrammar docs, Nov 2024).
      - Only active during import-context (detected by preceding tokens)
      - Fallback: if vLLM not available (ollama), skip (Layer 1+3 still active)

    Phase touched: 3J (VllmProvider), providers/src/vllm_client.rs
    Dependency: vLLM >= 0.7.0 with XGrammar (verified: vLLM structured outputs docs)
    Risk: allowlist must be maintained. Auto-generate from non-deprecated crates in
    Cargo.toml + deprecated_patterns.replacement_name values.

    Schedule: once per 24 hours (or on-demand via CLI command).

    Actions (revised per BLOCK-5, WARN-6, now multi-ecosystem):
      Per-ecosystem registry queries:
      1. Rust (cargo): crates.io REST API
         GET https://crates.io/api/v1/crates/{name}

         Rate limit: 1 req/sec, requires User-Agent header.
      2. Python (pip): PyPI JSON API
         GET https://pypi.org/pypi/{name}/json
         Response: JSON with .info.version field (latest stable).
         No rate limit. Use PyPI API as primary, pip index as fallback.
      3. JavaScript/TypeScript (npm): npm registry API
         GET https://registry.npmjs.org/{name}/latest
         Response: JSON with .version field.
         No auth required for public packages.
      4. Go (go): Go module proxy
         GET https://proxy.golang.org/{module}/@latest
         Response: JSON with .Version field.
      5. Java (maven): Maven Central Search API
         GET https://search.maven.org/solrsearch/select?q=g:{group}+AND+a:{artifact}
         Response: JSON with .response.docs[0].latestVersion field.
      6. C#/.NET (nuget): NuGet API
         GET https://api.nuget.org/v3-flatcontainer/{name}/index.json
         Response: JSON with .versions array (last = latest).
      7. Ruby (bundler): RubyGems API
         GET https://rubygems.org/api/v1/gems/{name}.json
         Response: JSON with .version field.

      After all queries:
      8. Update deprecated_patterns table with new findings:
         - New entry if a dependency has a newer major version
         - Severity = WARN for minor updates, BLOCK for known-deprecated
         - Ecosystem field populated from the registry source

REASONING ARCHITECTURE INTEGRATION (reasoning-architecture-design.txt)
========================================================================

The anti-staleness layers integrate with the 6-layer externalized reasoning
pipeline at three points:

1. LAYER 1 (DETERMINISTIC) + VERSION_GATE:
   Reasoning Layer 1 FailureTaxonomy includes MISSING_IMPORT and UNDEFINED_SYMBOL.
   When Layer 1 localizes an import error, it queries deprecated_patterns before
   generating a fix template. If the attempted import matches a deprecated_name,
   the fix template uses the replacement_name instead:
     Model tried: "use blake2::..."
     Layer 1 detects: deprecated_patterns match (blake2 -> blake3)
     Fix instruction: "Use blake3 instead of blake2. Import: use blake3::..."
   This catches staleness errors BEFORE they reach hooks or auditor.
   Projected: resolves 30-40% of anti-staleness violations at zero LLM cost.

2. ETC (SECTION 2.1) + GG SIGNAL 3:
   ETC entropy monitoring (ETCLogitsProcessor) produces entropy trend data
   during generation. reasoning-architecture-design.txt Layer 4 (AB-MCTS) uses
   this as GG Signal 3: if entropy spikes mid-generation, the model is uncertain
   and likely hallucinating an API name. Early termination prevents wasting a
   retry on garbage output. ETC and GG share the same entropy data source.

3. STEERING VECTORS (SECTION 2.2) + REPAIR GENERATION:
   When the reasoning pipeline triggers repair retries (Layers 2-4),
   the freshness steering vector (modern_api_preference) is active during
   ALL repair generations. This biases the model toward modern APIs even
   when generating code under exploration (temperature 1.0 repair retries).
   The steering vector is a forward hook — it applies regardless of
   generation parameters, providing a persistent anti-staleness baseline.

4. CONSTRAINED DECODING (SECTION 2.3) + AB-MCTS:
   AB-MCTS branches (Layer 4) use the same constrained decoding for imports
   as first-attempt generation. The positive allowlist (JSON Schema or EBNF)
   prevents deprecated imports from appearing in ANY branch candidate.
   This is especially important because AB-MCTS uses temperature 1.0,
   which would otherwise increase the probability of deprecated tokens.
