USER FEEDBACK SYNTHESIS
================================================================================

What people PRAISE and CRITICIZE about AI-harness UIs, with sources.

1. "POLISH SIGNALS TRUST" -- a UI that visually ties its features together reads as
   trustworthy; one that looks like "a software engineer built the visual elements"
   reads as unpolished and lowers confidence in the tool.
   - "Windsurf does a really good job visually tying together all its features, while
     Cursor definitely feels like a software engineer built the visual elements with a
     noticeable lack of polish." / "Windsurf's IDE itself is clean and responsive, far
     superior to Cursor's interface."
   - Source: https://www.qodo.ai/blog/windsurf-vs-cursor/  (and the comparison set at
     https://www.allaboutai.com/comparison/windsurf-vs-cursor/)

2. "DESIGN SLOP" -- the single loudest current criticism. AI-tool UIs (and the UIs those
   tools generate) increasingly share one homogeneous generated aesthetic, and the
   community now reads that look as a signal of low effort / low quality underneath.
   Named tells: Inter font everywhere, "VibeCode Purple" / violet gradients, glassmorphism
   cards, identical feature-card grids with a big rounded icon on top of every heading,
   badge-above-hero layouts, everything wrapped/nested in cards, dated bounce/elastic
   easing, pure-black (#000) backgrounds, gray text on colored backgrounds.
   - "Design slop is described as a visual indicator for code slop -- if the UI looks like
     it was generated by the same model with the same defaults, the code underneath
     likely is too."
   - Sources: https://dev.to/_46ea277e677b888e0cd13/stop-your-ai-coding-tool-from-generating-generic-ui-impeccable-design-skill-4g1l
     and the HN "Design Slop" discussion via https://news.ycombinator.com/item?id=44322036

3. "SIMPLICITY vs CONTROL is a real split" -- users self-sort. One camp wants minimal
   configuration and automatic context handling (praised in Windsurf); the other wants
   visible knobs and control (Cursor). A project-picker / onboarding should not force the
   simplicity crowd through the control crowd's setup.
   - "The community reflects a clear split; Cursor for control, Windsurf for simplicity,
     and many bounce between the two depending on the task." /
     "Windsurf was praised ... by those who preferred a smoother UI with less configuration."
   - Source: https://www.qodo.ai/blog/windsurf-vs-cursor/

4. "FORCED LOGIN AT FIRST LAUNCH IS HATED" -- being blocked by an undismissable login form
   on first open, with no try-before-signin and no offline path, is a concrete onboarding
   complaint filed against Warp.
   - "users were immediately presented with a login form that could not be dismissed upon
     downloading ... for the first time" -- feature request: trial without sign-in +
     offline mode.
   - Source: https://github.com/warpdotdev/warp/issues/900

5. "FAMILIAR FOUNDATION REDUCES ONBOARDING FRICTION" -- the most-praised onboarding move is
   letting users import their existing environment (themes, keybindings, extensions) from
   VS Code / Cursor in the first wizard step, so the tool feels instantly familiar.
   - "Windsurf gives you the option to import your existing configurations ... directly
     from VS Code or Cursor, which is a huge time-saver. The entire setup took less than
     five minutes."
   - Source: https://docs.windsurf.com/windsurf/getting-started ; also
     https://medium.com/@proflead/windsurf-ai-tutorial-for-beginners-ai-code-editor-dcef7637117c

6. "CHAT-FIRST EMPTY STATE WITH EXAMPLES WORKS" -- the prompt-box-as-homepage pattern
   (v0's "What can I help you ship?" + community examples; Bolt's homepage prompt with an
   'enhance' helper; Lovable's single prompt box) is consistently described as inviting and
   low-friction for starting a new project.
   - v0: "an intuitive chat window ... a 'What can I help you ship?' screen with community
     examples that appears when starting a new project."  Bolt: "try clicking the 'enhance'
     icon to have the AI help you refine your prompt."
   - Sources: https://annjose.com/blog/v0-dev-firsthand/ , https://capacity.so/blog/what-is-bolt-new ,
     https://lovable.dev/

7. "SPLIT-SCREEN chat+preview is the expected work layout" -- once a project starts, users
   expect chat on the left and live preview/artifact on the right (Replit, OpenHands, Bolt).
   - Replit: "you move into a split-screen interface with chat on the left and live preview
     on the right." OpenHands: agent on the left, generated artifacts / VS Code on the right.
   - Sources: https://www.datacamp.com/tutorial/replit-agent-ai-code-editor ,
     https://www.amd.com/en/developer/resources/technical-articles/2025/OpenHands.html

8. "PROJECT DASHBOARD ergonomics matter" -- small touches in the project list are noticed:
   default sort by last-opened, and hover-to-preview a project's screenshot without opening.
   - "The dashboard now defaults to sorting projects by last opened ... You can hover over
     any icon to preview that artifact's screenshot without opening the project."
   - Source: https://releasebot.io/updates/replit

9. "TUI CAN BE PREMIUM" -- a terminal UI is not automatically low-polish; Factory's Droid
   and Aider are praised for a "concise and clean TUI" with a first-class in-prompt command
   palette (/skills, /model, /init, /review), which is its own onboarding affordance.
   - "Droid CLI provides a concise and clean TUI ... a first-class command palette in your
     terminal."
   - Source: https://www.siddharthbharath.com/factory-ai-guide/ , https://factory.ai/product/cli

================================================================================
DESIGN TAKEAWAYS  (for a project-selection screen specifically)
================================================================================

PATTERNS WORTH STEALING
- Lead with ACTION, not a form. The strongest new-project screens are a single prominent
  prompt box / "open or create" with example chips, not a multi-field wizard (v0, Bolt,
  Lovable, Replit prompt-entry).
- Offer THREE clear entry doors on the picker: (a) open existing / recent project,
  (b) start blank, (c) start from a prompt or import (zip/GitHub/screenshot). Don't make
  the user guess which path they're on (v0 + Lovable do this well).
- Make RECENTS first-class: sort by last-opened, and hover-preview each project's
  thumbnail so users navigate by sight, not filename (Replit dashboard).
- Reduce first-run friction by IMPORTING the user's world (theme/keybinds/recent dirs)
  as an optional first step, and let it be skipped (Windsurf onboarding).
- One locked accent + tinted neutrals + a real type hierarchy; a focal "primary action"
  beats an equal-weight grid of cards. Polish is read as trustworthiness.
- A clean TUI/CLI picker is legitimate and can feel premium IF it has a clear command
  palette and a calm status bar (Factory Droid, Aider) -- relevant since ELAI is CLI-shaped.

ANTI-PATTERNS TO AVOID
- DESIGN SLOP tells: Inter-only, violet/"VibeCode purple" gradients, glassmorphism cards,
  identical icon-on-top feature-card grids, badge-above-hero, everything nested in cards,
  bounce/elastic easing, pure #000 backgrounds. These now actively signal "AI-generated,
  low effort" to the target audience.
- Don't gate first launch behind an undismissable login with no try-first / offline path
  (Warp issue #900).
- Don't force the simplicity-seeking user through a control-seeker's setup wizard
  (API keys, indexing toggles, privacy modes) before they can pick a project -- defer the
  knobs, make them reachable but not mandatory.
- Don't make the project list an equal-weight wall of identical tiles with no focal point,
  no recency signal, and no preview -- it reads generic and slows navigation.
