DOCTRINE (the eight non-negotiables, every phase inherits them)

1. PROGRAMMATIC SEAM FIRST, GUI LAST. Unity via Unity MCP, Blender via blender --background --python recipes, CAD via python (CadQuery/FreeCAD console/Fusion MCP), web via Playwright/CDP. the GUI operator lane exists ONLY for the residue: GUI-only apps (Marvelous Designer, AssetHub-class sites), editor dialogs no MCP reaches, installers, and visual verification. a task that COULD go through a seam but was pixel-driven is a finding, not a success
2. PERCEPTION LADDER, ID-INDIRECTION. tier 1 UIA tree (uiautomation lib): role+name+bbox+interactable per element, model picks an ELEMENT ID integer, never coordinates, when an element exists. tier 2 pixels (OCR, later OmniParser-class SoM) only when UIA is empty/dead (game viewports, GPU canvases, Blender viewport). tier 3 VLM advisory only; counts NEVER from the VLM (visual-ui-loop law). every element carries a provenance tag (uia_exact | ocr_text | vlm_caption | pixel_som)
3. FRAME BINDING, FAIL-CLOSED. every actuation carries blake3(screenshot bytes it was computed from) + the UIA-snapshot revision. the actuator re-captures, and REFUSES on hash/geometry/foreground-window mismatch — re-observe, never retarget. a stale or replayed frame hash actuates nothing
4. EVIDENCE THE MODEL DID NOT AUTHOR. per-action journal row {ts, intent, element_or_coords, frame_hash_before, action, frame_hash_after, result} + before/after PNG + crosshair-annotated evidence crop; optional bounded per-action screen recording (hash on the row). a run emits a findings report (playtester discipline: exceptions/softlocks/dead-ends are findings, "looks fine" is not a verdict)
5. ARMED CAPABILITIES. destructive/irreversible action classes (delete, overwrite outside scratch, install, purchase, send/submit, registry/config mutation) are dark until ARMED: two-phase arm (journal the grant BEFORE exposing the class) + TTL lease checked both by sweep and inline at dispatch. unarmed attempts refuse loudly
6. EXPLORE THEN CRYSTALLIZE. an exploration run that succeeds can mint a deterministic replay script (UIA selectors preferred, coords+frame-hash fallback, assertion points from the journal) + manifest. replay is the execution mode: near-zero reasoning cost, drift detected by frame-binding refusals
7. HOST LANE vs SANDBOX LANE. host lane = owner-present/supervised sessions (this plan's default, the playtester posture). sandbox lane (Windows Sandbox, or vendored trycua-cua, MIT) for untrusted payloads/installers when wanted. UNATTENDED runs never hold armed destructive classes on the host
8. GATED INSTALLS. "download blender/ps on demand" happens only through a catalog: named rows {tool, winget/source id, license, hash-or-signature policy}; catalog row + armed install class, or it refuses. no ad-hoc "the model found an installer online"

ARCHITECTURE

two approaches considered (two-minimum):
approach 1, vendor an existing full agent (cua's agent loop, or agent-s): rejected as the CORE — cua's in-loop safety gating is a commented-out TODO (eval ENTRY 10), agent-s has no journal/replay/undo at all, and both are screenshot-first where our doctrine is UIA-first; we would spend the effort gutting their loop to insert our gates. cua remains the SANDBOX substrate vendor (its VM providers are the best of the six) and agent-s remains the grounding-model prior art — steal parts, not the loop
approach 2 (CHOSEN), thin owned toolkit on the proven pattern: stdlib+4-deps python tools under this root's .claude/tools/operator/, driven by a skill (the playtester shape: the session IS the agent loop, tools are deterministic primitives). the LLM never emits raw pyautogui strings (agent-s exec() anti-pattern); it calls typed tools whose actuator enforces frame binding + arming. this is also exactly what ports to TEIKOKU later: the tools become the daemon-side operator adapter, the skill logic becomes the conductor's operator TaskSpec stage

toolkit (all python, windows-native, one venv at .claude/tools/operator/.venv):
- op_snapshot.py: foreground/named-window UIA tree dump (elements with int IDs, role, name, bbox, interactable, provenance) + mss screenshot + blake3 frame hash + monitor/window geometry. outputs snapshot.json + frame.png to a run dir. --ocr flag adds tier-2 text boxes when UIA is sparse
- op_act.py: click <element_id>|--xy x,y / type <text> / keys <chord> / drag / scroll / focus-window <title>. REQUIRES --frame <hash> (+ element revision when targeting an ID); re-captures, verifies, refuses on mismatch; auto-captures the after-frame; appends the journal row; draws the crosshair evidence crop. destructive classes require --lease <id> from op_arm
- op_arm.py: arm <class> --ttl <s> (two-phase: grant row journaled, then class exposed) / disarm / status. sweep + inline expiry
- op_run.py: run lifecycle: new-run dir under workflow/operator-runs/{ts}-{slug}/ (journal.jsonl, frames/, crops/, report.md), optional ffmpeg region recording start/stop (bounded), finalize writes the findings report skeleton
- op_install.py: catalog-gated winget wrapper (catalog at .claude/tools/operator/catalog.toml), install class must be armed
- op_replay.py (OP-E): replays a crystallized script with per-step frame-binding + assertions
skill: .claude/skills/operator/SKILL.md — the loop (snapshot > decide ONE action > act > verify delta > repeat), the playtester findings discipline, anti-spiral bounds (same screen K actions = finding + move on), the seam-first rule (check unity-mcp-skill / blender headless / playwright BEFORE driving pixels), report format

DOCTRINE ADDENDUM (added 2026-07-11 from the OP-A3 real-smoke finding — the shared-desktop reality): ACTUATION IS UIA-PATTERN-FIRST, COORDINATE-CLICK LAST. Inside a GUI app the programmatic seam (doctrine #1) is the element's own UIA control pattern — InvokePattern.Invoke / ValuePattern.SetValue / TogglePattern / SelectionItemPattern / ExpandCollapsePattern — which needs NO foreground and NO physical mouse, so it is immune to the owner using the PC concurrently and to Windows' system-wide foreground-lock. The safety binding for a pattern action is ELEMENT RE-RESOLUTION by UIA identity (role/name/bbox vs snapshot_revision), not a pixel hash. A physical coordinate-click (auto.Click(x,y)) is the FALLBACK for pixel-only / no-usable-pattern targets (the OP-C tier); it alone needs foreground + carries the full frame-binding gate. Grounding: the plan's own exemplar lesson (line 15, "an in-process programmatic seam beats pixel driving every time one exists") + observed live (OP-A3: coord-click lost the foreground war on a busy owner-present desktop, frame-binding correctly refused rather than mis-clicking). HONEST LIMIT: Windows foreground is system-wide, one window per SESSION — a second monitor is spatial isolation, not a separate foreground; true focus-blip-free parallelism needs a separate session (sandbox lane, parked).

OP-B7 | content-safety / never-clobber verification gate (owner ask 2026-07-12; HIGHEST-PRIORITY open safety item, implement BEFORE any unattended/exclusive real use). BORN FROM A REAL NEAR-MISS: the operator's `type` action used ValuePattern.SetValue, which REPLACES the entire field — during a smoke it overwrote an entire Notepad page of the owner's real content; had it been saved the data was lost. SetValue-replace shipped as a BENIGN action with NO gate; the enumerated destructive taxonomy (delete/install/overwrite-FILE/...) missed "overwrite the CONTENT of a field/document the owner cares about". TWO LEGS: (a) ADDITIVE-BY-DEFAULT — `type` INSERTS/APPENDS and NEVER clobbers existing non-empty content; add a SEPARATE explicit `replace`/`set-value` action as the ONLY clobbering text path. Prefer a non-clobbering primitive (TextPattern insert-at-caret, or SetFocus+move-to-end+SendKeys append, or read-current+set current+appended) so a plain `type` preserves what was there. (b) DESTRUCTIVE-INTENT VERIFICATION GATE (the double-check) — op_act AUTO-DETECTS a mutating/destructive actuation from the TARGET + action semantics: a content-clobbering replace/clear on a non-empty editable, OR a click on a control whose Name/AutomationId matches a destructive lexicon (Delete/Remove/Discard/Don't Save/Do not save/Overwrite/Replace/Clear/Reset/Format/Uninstall/Erase/Trash), REGARDLESS of what --class the caller passed (FAIL-SAFE: the LLM cannot bypass by mislabeling; the TOOL re-derives intent; when uncertain, GATE). A detected mutating action MUST (i) capture a PRE-IMAGE — read + journal the current content/state BEFORE acting, so an approved overwrite is RECOVERABLE from the journal (reversibility leg, grounded in the H-plan CAS pre-image work + this plan's reversibility posture) — and (ii) require CONFIRMATION before it fires: in --mode shared a CONFIRM_REQUIRED refusal the owner explicitly approves (reuse the op_arm approve / sentinel spine, per-action or per-class), in --mode exclusive/unattended an armed owner-confirmed lease for the mutation class. NEVER silently overwrite/delete/replace. The destructive lexicon is a named extensible constant documented in DESTRUCTIVE-CLASSES.md. | dep OP-B1 (reuses the arming/confirm spine) + OP-B2 | NEGATIVE: a `type` onto a NON-EMPTY field preserves prior content + inserts the new text; a `replace`/clear on non-empty content and a click on a Delete/Don't-Save-class control BOTH refuse CONFIRM_REQUIRED in shared (need approval) or require a lease in exclusive; a pre-image row lands in the journal in every gated case
EXPECTED_OBSERVATION: type preserves prior field content; replace/destructive-labeled click refuses CONFIRM_REQUIRED (shared) or needs a lease (exclusive) + a pre-image row is journaled
ON_FAIL: a control exposes ONLY ValuePattern (no TextPattern/insert) so an additive `type` is impossible without a full SetValue replace (CAUSE: legacy edits) > then treat EVERY SetValue on a NON-EMPTY field as a gated `replace` (pre-image + confirm); only a SetValue on a genuinely EMPTY field (zero-length current value, whitespace counts as non-empty) is a benign additive write, never a silent clobber
