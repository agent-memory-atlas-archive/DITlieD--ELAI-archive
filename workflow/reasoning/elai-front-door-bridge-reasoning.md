DETERMINISM RESOLUTION (the load-bearing principle)
- ELAI determinism was never "the LLM is deterministic" (it never is, anywhere). It is "the GATES and the EVIDENCE are deterministic; the LLM is ADVISORY". Precedent: TD-3 (LLM T3-advisory never the gate), D-10 mode-routing predicate (deterministic, LLM has no input), F-4 AntiFabricationGate (auditor cannot emit passed=true without matching orchestrator-captured blake3 stdout hash).
- Therefore a non-deterministic intent rewrite is fine IF: (a) the ROUTER deciding research/ask/proceed/reframe is deterministic (J-32: T0 slash-bypass / T1 deterministic matchers / T2 local-3B constrained {lane,confidence,arg_spans} temp 0, fail-closed to asking), (b) the rewrite is a PROPOSAL verified against grounding before execution, (c) the decision + assumptions are journaled (RRA-reproducible).
- "Every presented option must be best/up-to-date" without researching live every fork: CACHE grounded recommendations (Cosmos artifact tier, outdated-tech-audit.md, posture-doc 90-day staleness check); the router decides when a rec is stale enough to re-research. Research-vs-ask-vs-proceed is a deterministic routing decision over (confidence, staleness, risk, mode).

AUTONOMOUS vs INTERACTIVE (same router, different action on a high-ambiguity node)
- Interactive: do NOT ask every step (tax + users-cannot-answer). Ask SELECTIVELY where router measures ambiguity/premise-risk high; verbalize-assumptions for the rest.
- Autonomous: calibrated defaults from grounded priors (Cosmos/cached research/code) + JOURNAL every assumption made (audit/override after); defer destructive/irreversible (matches feedback_autonomous_mode). Be CONSERVATIVE on reframing: proceed on literal intent + recorded assumptions by default; only escalate "wrong problem" on high-confidence GROUNDED contradiction (grill-style flat), and surface it as a recorded decision the user sees, never a silent goal-swap.

PERSONAS vs DETERMINISM
- A persona is non-deterministic steering (real but uneven effect). It is NOT against ELAI determinism IF: (1) it steers the PROPOSAL, never adjudicates (auditor hostile-skeptic is fine because its VERDICT is backed by deterministic checkers: wiring_contract_check.py, production_caller_check.py, test-output hash; persona shapes look, checker decides pass); (2) each persona is A/B measured. ELAI already decided this at plan level: I-32 / IC-17 STRUCTURAL ROLE SCOPING = drop narrative personas from executor/researcher, KEEP for auditor/critic/anti-spiral, per-role A/B measured. GAP: that measurement is PLANNED, not done. The danger is only a persona whose load-bearing output has no deterministic backstop.

CONTINUATION (invocation-determinism + aim-verifiability + improve-ELAI-not-the-model)
USER QUESTION: if every test is deterministic, why have the model invoke them at all? Depending on the model to invoke is probabilistic, not deterministic. Isn't model-chosen test selection stupid? Or is there a method to improve the deterministic tools automatically as ELAI goes (is that DGM)?
- Separate three layers: (1) test EXECUTION is deterministic (cargo test / the .py checkers / the blake3 stdout hash are scripts, zero model judgment). (2) test SELECTION + invocation TIMING is, TODAY, partly model-judgment (auditor consults advisory tools impact_radius.py / cross_lang_diff.py / failure_taxonomy.py and decides scope). (3) GROWTH of the check set.
- The user's critique is valid for the CURRENT advisory state, and ELAI already has the fix named: J-16 BLAST-RADIUS / ANTI-REGRESSION GATE [PLANNED, KEYSTONE, user #1] makes regression-test SELECTION a DETERMINISTIC function of the diff (reverse-dep cone + diff-scope + pass->fail BLOCK + silent-deletion flag), LLM never adjudicates. So selection moves from model-judgment to deterministic gate. That closes most of the "isn't it stupid to let the model choose" gap.
- The ceiling: you CAN run every gate on every change deterministically (no model), but it is slow/expensive, so you want selection. Deterministic selection (J-16) gives that for KNOWN check classes. The residual model role then shrinks to: novel changes no deterministic selector has a rule for yet, and PROPOSING new checks. The probabilistic share of LOAD-BEARING decisions trends toward zero as the deterministic floor grows; the model is never eliminated (open-ended input) but is pushed to the frontier.
- "Method to improve the deterministic tools automatically" = YES, and it is mostly the RULES ENGINE, not full DGM. Rules are DATA in SQLite, predicates AST/GREP/SCHEMA/METRIC/COMPOSITE, lifecycle PROPOSED->CANDIDATE->SHADOW->ACTIVE->RETIRED gated by fpr<5% + tpr>80% + causal>50%. A model PROPOSES a new check; it becomes LOAD-BEARING only after measured FPR/TPR clears the bar in SHADOW. Same pattern: model proposes, deterministic MEASUREMENT promotes. SELF-MODIFICATION CORE (L1 data-tables no-LLM / L2 config staged eval 10/50/200 / L3 structural human-only) is the config-param sibling.
- DGM proper (darwin_admit_loop) is the aggressive evolutionary variant, currently DARK with the two placeholder GAPs (fitness = blake3 of config bytes; traps = keyword grep) that H-43..H-48 Track 7 exist to replace with execution-grounded fitness + measured-recall trap detection. So: rules-engine SHADOW->ACTIVE = the shipped conservative self-improvement of the deterministic floor; DGM = the research-grade version, not yet trustworthy.
- SYNTHESIS: push the probabilistic boundary as far back as possible. Deterministic EXECUTION (have it) -> deterministic SELECTION (J-16, planned) -> deterministic GROWTH via measured promotion (rules-engine shipped; DGM research). This IS the "improve ELAI itself, not the model" direction the user is reaching for.

AIM vs FIDELITY (reasoning before the dispatched research returns)
- Fidelity (built what was planned) is deterministically checkable; it is what every ELAI gate measures. Aim (was the plan the RIGHT thing) is NOT obviously deterministically checkable because "right problem" depends on the user's true goal, which lives in the user's head, not in any artifact. This is the classic Validation (right product) vs Verification (product right) split. ELAI gates verify; they do not validate. Structural blind spot: a flawless implementation of the wrong thing passes every gate.
- Three candidate routes to address aim (likely a LADDER, not pick-one; mirrors IC-6 search-is-a-ladder + I-4 evidence-ranked ladder):
  (Surface-and-confirm, cheap) verbalize the assumed goal + any flat contradiction, let the user confirm/override. Evidence-backed (ask-don't-tell, verbalize-assumptions). Does not GATE aim, it SURFACES it. J-31 canvas-system-mode is a candidate vehicle: bind plan-unit nodes to wiring contracts with verdicts derived from checkers, so a mis-aimed DIRECTION is visible/inspectable rather than buried in baby-steps (surface aim via visualization).
  (Grounded-research, expensive) ELAI researches the problem space (prior art, the usual goal behind the task, known better solutions) and checks the stated idea against that evidence; flags known anti-patterns / standard better approach / goal-mismatch. Cost: per-idea research = expensive + slow + conversation/latency tax. Use only when router measures risk/ambiguity high.
  (Slow self-improvement, compounding) do NOT verify aim up-front; LEARN aim-patterns from OUTCOMES over time (the SSB journal already records which initial directions led to good vs bad outcomes) into a growing anti-pattern / aim-heuristic library (the skill.md-improves-over-time pattern the user named; cosmos accumulation; rejected-ledger). Cheaper per-idea, compounds, but slow to mature and only as good as the outcome signal.
- PRE-RESEARCH VERDICT (to test against the dispatched researcher): aim probably cannot be FULLY deterministically verified (depends on a private goal), but can be SURFACED cheaply (confirm), PARTIALLY GROUNDED against prior art (expensive, gated), and LEARNED as patterns (compounding). Best shape = the ladder: cheap surface-and-confirm by default; grounded-research only on high-risk nodes (J-32 router decides); self-improvement accumulates patterns so the expensive route is needed less over time.
- USER VALUE TO HOLD: improve ELAI itself (harness / skills / checkers / patterns / cosmos), NOT the model. Cost tension: grounded-research-per-idea increases cost; slow self-improvement is cheaper and compounds. Lean self-improvement, escalate to grounded-research only on measured high-risk.

TWO LOAD-BEARING NEW FINDINGS (beyond the ladder):
- MODEL-NATIVE SUPPRESSION: false-premise correction is SUPPRESSED 19-90% when the premise is embedded in a routine TASK context ("Knowing But Not Correcting" 2605.05957), and reasoning fine-tuning DEGRADES abstention 24% (AbstentionBench 2506.09038). ELAI is always a task context. So the model will NOT spontaneously catch mis-aim and gets WORSE at it as it gets more capable. Implication: aim-catching must be STRUCTURALLY FORCED (deterministic router fires the clarify/verbalize-assumptions step), never hoped for. Hard validation of the deterministic-router + verbalize-assumptions design.
- INTENT FORMALIZATION = the named grand challenge (Lahiri/Microsoft 2603.17150): neither tests nor proofs validate aim unless intent is first correctly formalized, and validating that formalization itself needs human judgment. So the front-door intent-rewrite (Mediator piece) IS "intent formalization", and it must be HUMAN-CONFIRMED, not silently trusted -> autonomous mode stays conservative (default + journaled assumption + user review).
- Ambig-DS line is the structural blind spot stated in the literature's own words: "Recognizing target and objective underspecification, not pipeline execution, is the bottleneck"; agents "produce clean executable artifacts that hide their incorrect assessment of the task." That is exactly plan_skeleton faithfully decomposing a misframed task.
DESIGN IMPLICATIONS (reconciled, this is the answer to "can aim be verified / is automating it worth the cost"):
1. DO NOT try to automate aim itself (Layer 5 impossible; literature unanimous). Aim is surfaced-and-confirmed, never gated.
2. Build the cheap SURFACE-AND-CONFIRM (verbalize the assumed goal + flat contradiction, human confirm), STRUCTURALLY FORCED by the deterministic router because the model suppresses self-correction under task framing. J-31 canvas-system-mode is a strong vehicle: make the direction/composition VISIBLE + evidence-bound so a human catches mis-aim cheaply (surface aim via visualization, not gate it).
3. Build the automatable AIM-ADJACENT FLOOR gates where cheap+sound: proxy-gaming detection (held-out composition tests — ELAI has held-out store D-6 + mutation/MR gates; the SpecBench held-out idea fits) and underspecification/false-premise detection (the J-32 ambiguity router + an ambiguity classifier). Treat as FLOOR, label honestly, never as aim itself.
4. AVOID the Layer-4 conflation (fidelity gate masquerading as aim = fail-open).
5. COST ANSWER: grounded-research-per-idea is expensive AND weak (44% ceiling at the hardest layer) -> reserve for measured high-risk nodes only. Self-improvement (accumulate aim-patterns/anti-patterns from the SSB OUTCOME journal over time) is cheap, compounding, and matches the "aim is often only knowable post-hoc" finding -> this is the right primary route, and it confirms the user's lean: improve ELAI itself (harness/skills/checkers/cosmos), not the model. Surface-and-confirm is the cheapest and handles the irreducible human residual.
NET: aim cannot be verified (human residual is real and principled), but ELAI can (a) STRUCTURALLY FORCE the cheap human-confirm the model won't do itself, (b) build weak automatable floor-gates around it, (c) COMPOUND aim-patterns via self-improvement. The expensive live-research route is the fallback for high-risk only.
