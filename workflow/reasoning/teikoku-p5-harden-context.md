TARGET 2 — events_wait "*" sentinel (P5-A, folds H-b)
================================================================================
ROOT CAUSE (CONFIRMED, latent): the wildcard contract is broken across a 3-hop chain.
- WAKE LAYER (the contract): conductor/wake.py:108 matches `(recipient is None or e.get("recipient") == recipient)`. So the TRUE wildcard is recipient=None (matches every event). A literal string "*" matches ONLY events whose top-level "recipient" key equals the string "*" (none are published with that), so "*" matches NOTHING.
- NATIVE LEG: signal/src-tauri/src/lib.rs:261 `let recipient_arg = if recipient.is_empty() { "*" } else { recipient.as_str() };` — substitutes empty -> the literal "*".
- CLI VERB (the actual bug seam): conductor/slice_api.py:575-579 `if sys.argv[1]=="events-wait": ... recipient = sys.argv[3] if len(sys.argv)>3 else None; print(json.dumps(events_wait(since, proj, recipient)))`. It passes "*" THROUGH UNCHANGED as the string "*". events_wait (slice_api.py:146) forwards it to `wake.wait_for_new(since, project, timeout, "*")` -> matches nothing.
- ASYMMETRY NOTE: the HTTP handler (slice_api.py:443) ALREADY normalizes correctly: `recipient = (qs.get("recipient",[None])[0]) or None` (empty->None). Only the CLI verb (which the native Tauri leg feeds) is broken.
- LATENCY: every shipped P4 surface passes a CONCRETE sessionId (never empty), so lib.rs:261 never produces "*" today. This is a ROBUSTNESS fix, not a live failure.
EXACT FIX LOCATION + RECOMMENDED APPROACH (the SAFER of the two): normalize "*"/empty -> None at the CLI verb, conductor/slice_api.py:577. Change `recipient = sys.argv[3] if len(sys.argv)>3 else None` to also map "" and "*" to None (e.g. `recipient = (sys.argv[3] if len(sys.argv)>3 else None) or None; if recipient == "*": recipient = None`). This makes the wake layer treat the sentinel as a TRUE wildcard, matches the HTTP handler's `or None` semantics, and keeps lib.rs:261's "*" as the documented wildcard TOKEN (no Rust rebuild needed). This is safer than the alternative (making the native leg reject empty), because it preserves the existing native behaviour and centralizes the normalization at the single Python seam both transports converge on.
  REJECTED ALTERNATIVE (reject-empty at native leg): editing lib.rs:261 to require a concrete recipient breaks the legitimate "subscribe to all events" use (the migrating-indicator feed wants every event for a chat; an all-events poll is valid). Don't reject; normalize.
