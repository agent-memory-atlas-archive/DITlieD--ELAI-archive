V1 grammar/JSON constrained output ("make invalid output structurally impossible") - ALREADY-SPECIFIED.
Corpus: E-26 constrained decoding + retry (DecodingMode + 3 EBNF grammars), E-35 structured-output substrate (XGrammar + CodeAct + SEARCH/REPLACE), E-18 tool-use reliability, J-13 LogitsProcessor seam; capability matrix already types supports_json_schema/cfg_grammar/logit_bias per backend (feature-map:3104). Nothing to steal; Bellard is independent confirmation the mechanism is the right one.

V2 DeterministicInferenceProfile - EXTENSION(G-2 / J-lacuna re-executable RRA). The strongest concrete improvement of this exercise.
What exists: RRA G-2 pins SSB stream + seed + HardwareClass + model pin + gate verdict hashes (master-summary:160); cloud lane is explicitly reproducible-ACTION-STREAM, not tokens (GD-5); sidecar threads sampling_seed; local-lane token determinism is mentioned (systems-overview:252); VLLM_BATCH_INVARIANT noted (feature-map:2006).
The gap ts_zip exposes: ELAI replay is hardware-CLASS-scoped. ts_zip demonstrates hardware-INDEPENDENT deterministic LLM evaluation is an engineering choice, not a law of nature. Two legs:
  (a) CHEAP LEG (recommend): journal a per-turn output-token-hash (blake3 of the emitted token-id sequence; optionally a top-k logit hash where the backend exposes logits) on the local lane. Cost: one hash per turn. Payoff: replay --verify localizes divergence to the FIRST divergent turn instead of a diverged end-state; a same-class replay becomes token-verifiable; a cross-class replay reports precisely where and how the exogenous model diverged (composes with G's model-drift canary). Also tightens the RRA claim wording: today "byte-recomputable" is true of the harness stream, not of local token streams across hardware; the hash makes the boundary of the claim explicit and honest (claims-policy KD-1 pressure).
  (b) EXPENSIVE LEG (evaluate-only, do not build): a deterministic-eval mode on the E-51 llama.cpp lane (pinned build + GGUF hash + fixed thread count + deterministic kernels) to upgrade gate-critical local inference to replay-anywhere. Ungrounded conjecture on cost: likely needs batch-invariant/fixed-reduction kernels; llama.cpp determinism across BACKENDS is not established (From training, unsearched) - would need its own recon before any plan unit.
Spine: strengthens the K re-executable-RRA differentiator; readiness-note class, no new number.

V3 LLM + arithmetic-coding lossless compression of journal/RRA/transcripts (ts_zip/NNCP shape) - REJECT on the trust path.
Reasons: (a) it puts a neural decompressor inside the evidence-reading path; M-plan's standalone OSS verifier and the versioned open evidence standard exist precisely so a third party can verify with a small, boring tool - requiring a 169M model + GPU to READ evidence contradicts the deeper Bellard lesson (V5 small-dep doctrine) more than it honors the compression trick; (b) throughput ~1 MB/s on a 4090 vs zstd at GB/s - operationally absurd for an append-only journal; (c) ts_zip itself ships no backward compatibility; an evidence format must outlive model versions. RRA is already msgpack+zstd - the boring right answer.
Salvage checked and mostly moot: "compression = prediction" as a novelty/familiarity SIGNAL is already covered - the D-plan tripwire stack carries a perplexity signal (feature-map:1469) and N-10 types NoveltyScore into budget wires (feature-map:3061). Bits-per-byte under the pinned local model would be one more mechanically-distinct novelty predictor; delta over existing signals is small. Park unless N-10 measurement shows the existing detectors are weak.

V4 single-binary, dependency-light doctrine - direction ALREADY-SPECIFIED; one small NEW.
E-51 (MLX + llama.cpp adapters) is the Bellard-adjacent single-binary local lane; 4M RuntimeAdapter makes the Python sidecar replaceable per role; TextSynth itself is REJECT as a dependency (binary-only, non-commercial license - verified) and stays a reference design.
NEW (small): a MEASURED trust-path dependency budget on the M-plan standalone verifier - a locked number in the K-4 gate-tax style: the verifier builds as a single static binary, zero network, zero Python, crate-count and binary-size recorded and ceiling-locked, lint-checked so a letter cannot silently bloat the thing that has to be smaller than what it audits. This converts "small, auditable verifier" from posture into an enforced property. Fits as an M-plan acceptance criterion, not a new unit. PROOF_SPINE if ever planned: none (discipline class) - needs user ack per PSR-2.

V5 SQLite/Hipp gate-testing doctrine - EXTENSION(H trading gate self-validation -> whole gate manifest).
What exists: 3I DST (madsim, proptest 10000 cases, IPC fault injection, 100-run identical checkpoints) proves FSM/SSB/BSP; H-trading has gate self-validation where "each gate kills its own frozen mutant corpus" (feature-map:1495); C-plan has mutation testing for code; N adds evaluator-refutation verdict-collapse.
The Hipp lesson ELAI has not fully applied: SQLite spends 590:1 test:code because the LIBRARY is the product; ELAI's product is the GATES, so the mutant/anomaly discipline currently scoped to the trading gate family belongs on the ENTIRE gate manifest. Concretely: every frozen checker gets a standard evidence-corruption corpus (truncated journal, corrupt msgpack, missing SSB db, flipped verdict hash, zero-row evidence, OOM/I-O-error injection in the checker process) and must BLOCK on every corpus item; report a per-gate KILL-RATE as a measured number, regression-tracked. This converts wiring-enforcement R1/R2 (missing evidence = FAIL, dead evidence path must scream) from doctrine into a tested, numbered property of every gate, not just the trading ones. Cheap: the corpus generator is deterministic, the gates already exist, the harness is offline. PROOF_SPINE if planned: indirectly hardens everything; strictly it is discipline class (PSR-2 user ack) unless framed as a gate-manifest coverage number feeding the K compliance/appsec brief.
