what: typed, hash-keyed, mutation-covered EARS requirement records (EarsRequirement /
EarsRequirementSet) with a deterministic Satisfied/Unverified/Regressed status, a
default-OFF blocking RequirementsGate (PLANNING -> TESTING_FIRST), and an additive
RequirementVerified SSB row emitted per requirement at the task_runner gate seam.

key decisions:
D1 (fork resolved B+emit, controller-authoritative): the plan's named C-50 ContractSpec
seam is a PHANTOM (0 hits). Added a new RequirementsGate impl EvidenceGate appended to
evidence::all_gates() (slot 12, order-stable, exactly as C-29's IntentPairsGate). The
RequirementVerified row is emitted at the existing PLANNING->TESTING_FIRST gate-loop seam
in task_runner::drive_task (alongside the EvidenceGateEvaluated emit idiom). Gate computes
status; the seam writes the row.

D2 (default-OFF blocking, additive emit): RequirementsGate can BLOCK a transition, so its
blocking behaviour is gated default-OFF behind ELAI_REQUIREMENTS_GATE_ENABLE (R9 experiment).
With the flag absent the gate degrades to pass AND None-degrades when ears_requirements is
unset — it changes no production gate behaviour. The RequirementVerified SSB emit is
INDEPENDENT of the flag (always lands when a set is present) so an Unverified requirement is
SHOWN in the cockpit, never silently dropped (R1).

D3 (EARS parsing, no new dep): five EARS stereotypes parsed by a hand-rolled line
state-machine (parse_ears_line) over the prefix templates (when/while/where/if-then/the).
NO new dependency added (verified: serde_yaml etc. not introduced). parse_speckit_str is
the in-memory form (production-wired); parse_speckit_file is the I/O wrapper.

D4 (composition, GD-1): IntentPair (IS-15) becomes the Ubiquitous base case via
EarsRequirement::from_intent_pair; metamorphic relations + I-20 mutation coverage are
foreign-key references, not re-implemented. blake3-only content_hash (anti-stale).

D5 (ID-5): DEFAULT_MUTATION_COVERAGE_FLOOR is a NAMED const used only as the
fixture/unconfigured default; verify_requirement takes coverage_floor as an argument so the
production path passes the I-20-measured floor. No paper constant baked into gate logic.

D6 (SSB Tier-B derived): +1 action_type RequirementVerified (Pattern-2 single-variant 3-arm
RequirementVerifiedKind: Satisfied/Unverified/Regressed = ONE action_type). Registry +1 ->
SSB_ACTION_TYPES.len()=566; SCHEMA_VERSION auto-derives -309+566=257. Golden regenerated by
mechanism (regen_golden_file target, 566 lines). No hand-bump, no exact-count assertion.
