## Artifact 1 — programasweights (PAW): compile a plain-English spec into a tiny deterministic offline "neural program"

WHAT IT IS. The Python client SDK + CLI (PyPI `programasweights` v0.4.2, MIT) for a hosted compile service: a user writes a fuzzy-text function spec ("classify sentiment", "fix malformed JSON"), the service compiles it into a ~23MB Q4_0 GGUF LoRA adapter bundled with a prompt template (`.paw` zip), and the SDK runs it locally forever on a shared small base (Qwen3-0.6B Q6_K ~594MB or GPT-2 ~134MB) via llama-cpp-python — greedy/temp-0 deterministic, offline, no GPU required. Compile mechanism (server-side, docs-only): untrained Qwen3-4B writes a pseudo-program from the spec; a trained 4B compiler model's hidden states (vLLM extract_hidden_states) are mapped by an MLP into LoRA weights; Q4_0 quantization is evidence-tabled as lossless (EM 0.6584 Q4_0 vs 0.6580 fp32, n=4096, their ADR-002). Positioning: the tier between regex and a full LLM. NOT related to artifact 2 — agent grep found zero arXiv/paper references in the repo.

CORE MECHANISMS (agent-verified in code):
1. Compiled-function artifact: base model + per-task LoRA + prompt template with `{INPUT_PLACEHOLDER}`; deterministic greedy decode.
2. Persisted prefix-KV cache: the fixed prefix is tokenized/evaluated ONCE, its KV state saved to `prefix_kv_cache.bin` via `llama_state_seq_save_file`/`_load_file` (runtime_llamacpp.py:134-175), reloaded every call, try/except fallback to recompute-and-resave — kills the 2-3s cold start ACROSS PROCESS RESTARTS.
3. Content-addressed identity + dual naming: same spec+compiler-version -> same program id; `slug@vN` immutable/cached-forever vs bare `slug` floating-but-offline-fallback; every artifact records the exact frozen snapshot even when requested via the floating alias (ADR-004).
4. Self-describing artifact with layered manifest resolution: embedded manifest > local cache > server fetch > hardcoded legacy table (cache.py:159-181) — the artifact stays executable/verifiable if the live registry dies.
5. Fail-loud zip-slip guard: every archive member checked for absolute path / `..` before extractall, RAISES rather than sanitizes (client.py:185-189).
6. ADR-with-evidence-table: one-page Status/Context/Decision/EVIDENCE-TABLE/Consequences docs settle load-bearing tradeoffs with measured numbers (ADR-002).

## Artifact 2 — arXiv 2607.02440 EvoPolicyGym: evaluating autonomous policy evolution under bounded feedback

WHAT IT IS. A benchmark + protocol ("Autonomous Policy Evolution") in which a harness+model coding agent repeatedly edits an executable policy system (policy.py + helpers + state files) under a FIXED interaction budget (128 episodes on Core16: Gym/Box2D, MuJoCo, MiniGrid, robotics/driving). Train submissions return rich visible feedback (summary.json, per-step trajectory.jsonl, stdout/stderr, optional frames); validation and held-out splits stay server-side; after budget exhaustion the server selects the best checkpoint on HIDDEN validation (ties -> later submit) and reports HIDDEN held-out return. Results: GPT-5.5/Codex 0.891 rank score, top-2 on all 16; Opus 4.7/Claude Code 0.750, best on MiniGrid; MiniMax-M3 0.531 and DeepSeek-V4-Pro 0.359 collapse on synthesis-dominant tasks (0.19 / 0.03 normalized vs 0.98 / 1.00 for the leaders).

CORE MECHANISMS:
1. The evaluated unit is the HARNESS+MODEL SYSTEM, explicitly not normalized ("we do not normalize token use, context management, or provider-specific defaults across harnesses; these are part of the evaluated system") — token stats are diagnostics only.
2. Visibility boundary as the anti-gaming spine: train visible / validation hidden (selection) / held-out hidden (report); budget charged per requested episode; request-format failures free, execution failures charged; server snapshots immutable checkpoints while the agent workspace has live no-rollback semantics.
3. Budget as measured capability: post-hoc best-so-far hidden-validation curves over the consumed budget expose WHEN improvements arrive (early jumps vs late; plateaus = burned budget).
4. Deterministic edit-type classifier: a SYNTHESIS edit introduces a previously-unseen policy-bundle AST TOPOLOGY after numeric constants are stripped; a PARAMETRIC edit changes the bundle while preserving the stripped topology; rollbacks/retests are candidate-management events, not edit types. Edit "hits" = raised validation best-so-far.
5. The headline diagnostic result: the capability gap opens on synthesis-dominant tasks; leaders convert synthesis edits at 41-48% hit rate, weak models churn structure at 3-10% while staying competitive on tuning (25-38%); "complex code is not necessarily a task-adapted mechanism"; same-topology edits rarely rescue a wrong mechanism.
6. Winning policies are small stateful programs: task abstraction + controller/planner + recovery logic for visible failure modes.

COMPARISON TO ELAI AS-SPECIFIED.
- Thesis-level: this is the strongest external validation in the four sources of ELAI's core bet. The paper's own framing — the harness is inseparable from the evaluated capability; iterative improvement quality is a property of the LOOP, not the model — is E-49's harness-vs-model attribution tuple and L-20's competitor-arm harness stated as a benchmark's first principle. ELAI's design goes one step further than the paper: E-49 plans to SPLIT the attribution the paper deliberately confounds.
- Eval architecture: ELAI's spec already contains, and in several places exceeds, the paper's protocol. Hidden held-out with temporal/contamination discipline = D-6 + E-54 (13-gram); adaptive-reuse defense = H-19 Thresholdout DP budget (the paper has NO defense against overfitting visible train feedback beyond hiding validation — ELAI's H-19/H-47 are strictly stronger on the axis the paper's own limitation section worries about); eval firewall for self-improvement = H-47 (date-gate + template regen + budget binding); measured score-vs-compute curves = I-27 ConvergenceCurveMeasured (the paper's Figure-3 best-so-far curve IS I-27's shape with budget on the x-axis); trajectory record = the SSB journal + G-2 RRA, which is the paper's "full execution-feedback-revise trajectory" made portable, sealed, and replayable — the paper records it, ELAI proves it.
- Where the paper has something ELAI's corpus does NOT: (a) the stripped-AST-topology synthesis-vs-parametric EDIT CLASSIFIER — deterministic, cheap, and finer than anything in ELAI's stagnation stack (anti-spiral C-10 detects Spinning/Oscillation/NoDrift/DiminishingReturns off content hashes and score plateaus; I-22 shapes rewards off deterministic observables; neither can say "you are churning STRUCTURE without traction" vs "you are tuning constants inside the WRONG structure" — the paper's two named failure modes); (b) checkpoint SELECTION on hidden data as the promotion rule (ELAI gates promotion on held-out EVALUATION (D-6, H-45 worst-case scoring) but the SELECT-then-report split — select on hidden validation, report on disjoint hidden held-out — is a cleaner two-stage discipline that prevents even the selection step from leaking into the reported number); (c) a public leaderboard whose measured object is exactly what ELAI sells.
