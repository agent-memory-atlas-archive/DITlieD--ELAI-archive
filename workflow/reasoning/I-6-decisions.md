I-6 decisions — anchor pane slot: immutable privileged-last context slot (lost-in-the-middle defense)

what: add ContextSlot::AnchorPane as a LAST slot (ordinal 10) appended after the final cache breakpoint (CodeContext=4, HD-2), carrying the frozen TaskSpec bytes, the unresolved-claim list, and the active constraint list. The model must open its reply with a short acknowledgement tag reflecting the highest-priority active constraint; the I-1 supervisor validates the tag's presence in the first reply token window. This is a mechanical recency-bias lever — not a persona, not a prompt instruction. Grounded in the U-shaped performance curve documented in Liu et al. "Lost in the Middle: How Language Models Use Long Contexts" (arXiv:2307.03172, TACL 2024): performance is highest at the beginning (primacy) or end (recency) of the context, and degrades in the middle. I-6 exploits recency bias constructively by placing the task spec + constraints LAST.

key decisions:
- APPEND-LAST only: AnchorPane is ordinal 10, after Evidence=9. NO rebalancing or displacing existing slots (stub_ban). The H-31 lazy-ALTER + slot-add pattern is mirrored exactly: add the variant, bump SLOT_COUNT 10->11, add the assembly branch. Existing ordinals 0-9 are stable.
- HD-2 safe: the final cache breakpoint is after CodeContext (index 4). AnchorPane (ordinal 10) is well past this breakpoint, so all volatile content lands after the byte-stable cache prefix. The bp.valid assert in update_breakpoints continues to hold. The prefix hash covers slots 0-4 only; slots 5-10 are volatile by design.
- NO new SSB action_type (GD-1 compose-not-restate): the anchor's presence in the assembled context is a prompt fact, not a journaled action_type. When a context reduction affects the AnchorPane slot, its ordinal (10) is recorded in the EXISTING ContextReductionPayload.slots_affected field (Vec<u8>) — the same field that records every other slot's reduction. SSB TOTAL_VARIANTS and SCHEMA_VERSION are unchanged.
- Serialization format: length-prefixed (u64 LE) sub-blocks — [u64 LE: task_spec_len][task_spec_bytes][u64 LE: claim_count](per claim: [u64 LE: len][bytes])[u64 LE: constraint_count](per constraint: [u64 LE: len][bytes]). This mirrors the update_breakpoints length-prefix convention (hasher.update(&(slot_bytes.len() as u64).to_le_bytes())). Deterministic: same inputs produce identical bytes (required for blake3 prefix-hash stability). Order-sensitive: the first constraint in active_constraints is the highest-priority one (the ack-tag target).
- Acknowledgement tag: a short deterministic slug derived from the highest-priority active constraint. The model emits it at the START of its reply. Missing tag -> retry prompt with explicit clarification (NOT a hard error, but logged). Bounded retries (no infinite loop). The tag is a prompt fact — no SSB action_type for it (stub_ban).
- Tier-2 deferrals (GD-4 gated): adaptive constraint prioritisation (rank constraints by recent miss-rate) deferred until >=3 measured constraint-adherence runs show the fixed-list is insufficient. Constraint-adherence cockpit tile deferred under the same gate.
