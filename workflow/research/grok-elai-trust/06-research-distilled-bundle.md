No existing benchmark satisfies all constraints; pieces across SUSVIBES/BaxBench/SeCodePLT/LiveBench/MMLU-CF/AgentDojo.
KEY: SUSVIBES (Feb2026) SWE-Agent+Claude4 Sonnet 61% correct but 10.5% secure on 200 tasks; prompt-side security strategies didn't fix it. RECS: build 300-400 task blind exploit-executing paired-ablation bench, fresh repo-level (SUSVIBES/SWE-bench-Live style) + small BaxBench greenfield slice, distributed git-free tarball + reproducible containers; 4 anti-gaming controls (strip .git/remotes/refs/reflogs; private held-out + open val; semantic-NN decontam; dynamic exploit exec primary, static supplementary); publish 1 primary + companions (reviewer-reaching rate, secure reviewer-reaching rate, block rate, latency/cost); lock thresholds on val, freeze, run private test ONCE; per-CWE breakdown (MITRE 2025 Top25); release benchmark card + harness code public, decisive test set private/rolling.

BOTTOM LINE: Verification (not generation) is the binding constraint. Human role shifts to trust auditor/risk governor/exception handler — durable medium-term but must change form (own intent/risk/irreversible decisions, not read every line). 2-5x faster verification achievable via structural triage + reviewer cockpit, but no single end-to-end production RCT proves the full multiplier.
KEY: METR Jul2025 19% slowdown (time lost to review/correct). Sonar Jan2026 (1,149 devs): 96% don't fully trust AI code, only 48% always check before commit, 38% say reviewing AI code takes MORE effort, top skill = "reviewing/validating AI code" 47% > prompting 42%. SO2025: 46% distrust vs 33% trust. Octoverse 2025: ~43M merged PRs/mo. Anthropic Jun2026: >80% merged code authored by Claude by May2026, engineer merging 8x as much/day. Anthropic Dec2025: only 0-20% work fully delegable, supervision norm. JetBrains 2026: 3-level review workflow, 7 constructs (chunk/risk-per-line/risk-per-file/Judge/walkthrough/zoom/security-cage), 63% expect less effort. Meta 2026 FSE: Diff Risk Score + risky-snippet highlight + auto-extra-reviewer + soft-block; top 5% riskiest: 9.56% more fell below high-risk threshold, only 0.45% more review time. MSR 2026: CRA-only PRs 45.2% merge vs 68.4% human; 60.2% of CRA PRs in 0-30% signal. Synergy 2026 (278,790 convos): human adoption 56.5% vs AI 16.6%, AI-reviewed code 11.8% more rounds, 85-87% AI convos end after 1 comment. c-CRAB: tools catch 20.1-32.1% of human issues, union of 4 = 41.5%, 84% comments useful. Circuit-breaker: 20% review budget on size/files/complexity captures 69% of effort. Auto-vuln-repair: >40% "looked correct" failed PoC+; OpenSSF 630 patches 20-40% semantically wrong despite passing automated val. Linux kernel 2026: only humans certify DCO, "Assisted-by" tag.
RECS: require spec+plan+task-breakdown before code; prohibit monolithic PRs (route large/many-file to high-friction path); attach machine verification RECEIPTS per hunk (which tests ran/checks passed/policy gate/stronger tests exist), generating agent never sole judge; build 3-level cockpit (overview + risk-ranked Judge traffic-light file list + hunk view) + Meta risky-diff routing; require human final response for auth/billing/privacy/data-deletion/migrations/public-APIs/CI; suppress style/formatting noise (inadmissible when deterministic tooling clean), reserve LLM comments for correctness/security/test-gaps + require evidence per comment.

## CROSS-REPORT TENSIONS / CONTRADICTIONS
- R1 "price premium above $24-30" vs R4 incumbents already at/above that with huge sales teams -> "premium" hard without a genuinely differentiated trust primitive.
- "Independent off-agent attestation is unoccupied" is an INFERENCE from public product surfaces; Endor Agent Governance + GitHub artifact attestation are close adjacencies that could close it fast.
- R2 leans on CaMeL/FIDES/RTBAS while citing NAACL "all 8 defenses bypassed >50% ASR" -> inline taint is valuable but NOT provably robust; calling them a "can't-lie spine" overstates robustness.
- R3 "dynamic exploit exec is the only real truth" vs R4 incumbents winning on static/SAST at scale -> higher commercial bar.
- R5 "2-5x" is a design target not proven; R1's case-study numbers are vendor-supplied/non-neutral — opposite of the independent-evidence posture ELAI sells.
- R3 wants 300-400 tasks for power; SUSVIBES is only 200 -> an SUSVIBES-derived number may not survive enterprise due diligence.
- R1 "target cleanup agencies as wedge+channel" vs R4 "CodeGate shows standalone trust tools get squeezed" — agencies already using Semgrep/Snyk have little reason to adopt unless the artifact is contractually portable.
- R2 Sigstore/Rekor v2 "usable but mid-migration" (witnessed checkpoints not live) = operational fragility for a product staking credibility on proof infra.
