Algorithm: Reflexion - Language Agents with Verbal Reinforcement Learning
ArXiv: 2303.11366
Paper: Reflexion: Language Agents with Verbal Reinforcement Learning
Authors: Shinn, Cassano, Berman, Gopinath, Narasimhan, Yao (NeurIPS 2023, v4 Oct 2023)

WHAT IT IS:
Reflexion replaces gradient-based weight updates with verbal reinforcement: after each failed attempt, the agent uses an LLM to convert the scalar failure signal into a natural-language critique stored in an episodic memory buffer. On the next trial, prior reflections are prepended to the prompt as context, steering the actor away from known failure modes. No weight updates occur; all learning is in-context. This makes it lightweight and compatible with any frozen LLM but creates a hard ceiling at the context window and requires that errors be detectable by an external evaluator.

IMPLEMENTATION DETAILS:

Three components:
  Actor (M_a): LLM generates actions/text conditioned on current state + stored reflections. Policy pi_theta samples from the base model.
  Evaluator (M_e): Scores trajectory tau_t. Implementations: exact match for reasoning tasks; heuristics for navigation; LLM-based binary classifier for complex feedback.
  Self-Reflection (M_sr): LLM converts {trajectory, reward} pair into verbal critique. Output: 1-3 sentences identifying the specific error and a corrective direction.

Memory buffer:
  Short-term: current trajectory history (fine-grained observations).
  Long-term: verbal reflection outputs. Max capacity Omega = 1-3 reflections (context limit). Newest appended; oldest dropped when full.
  Reflections are prepended to actor's next-episode prompt.

Episode budget:
  AlfWorld: up to 12 trials per task.
  HotpotQA: up to 3 consecutive failures before abort.
  HumanEval/programming: continue until all unit tests pass, 1 reflection per episode.

Evaluator for programming: LLM-generated unit tests used as the external oracle. Known failure mode: false positives in generated tests cause premature success.

TESTS/BENCHMARKS:
AlfWorld (134 environments, sequential decision-making): 130/134 task completions with ReAct+Reflexion. Baseline (ReAct alone) converges lower.
HotpotQA (100 questions, multi-hop QA): +20pp absolute over baseline. CoT+Reflexion reaches 80% vs 68% baseline. Note: HotpotQA EM is 80% for Reflexion vs 27% for ReAct alone (different eval setup than ReAct paper).
HumanEval Python: 91% pass@1. GPT-4 baseline: 80% pass@1 (the 11pp gap is the headline claim).
MBPP Python: 77.1% pass@1. HumanEval Rust: 68%. LeetcodeHard: 15%.
Models used: GPT-3.5-turbo and GPT-4 (2023 era). No smaller open models tested.

STALENESS VERDICT: PARTIALLY-STALE
What survives: The architectural pattern (external oracle -> verbal critique -> episodic buffer) is sound and widely adopted. The "verbal gradient" framing is used in SCoRe (2024), Meta-Reflection (Dec 2024), and production agent harnesses (LangGraph, CrewAI).
What is stale: The original 91% HumanEval result used GPT-4 as both actor AND reflector - this is the oracle smuggling problem. Huang et al. 2023 + Zhang et al. 2025 established that without an EXTERNAL oracle, intrinsic self-correction degrades performance: the "self-correction blind spot" (Tsui 2025) - LLMs fail to correct their own errors while successfully correcting identical errors presented as external input. Reflexion's gains depend entirely on the evaluator signal quality. On small instruction-tuned coder models (<7B), the reflector quality degrades faster than the actor, making the reflection noise rather than signal. The episodic buffer is also bounded by context window; modern long-context models can hold more reflections but the diminishing-returns problem (3+ reflections rarely improve) persists.
Current verdict: Use the Reflexion LOOP ARCHITECTURE (actor/evaluator/reflection-buffer) but require an external verifier for the evaluator; never rely on the model evaluating its own output without ground truth.

RELEVANCE TO REASONING-STATE ENGINE:
(a) Cross-boundary state: The episodic memory buffer IS the canonical cross-session state format. Reflections are compressed, high-signal summaries of failure modes - exactly what should persist across context compaction events. The pattern maps directly: short-term = current session trace, long-term = serialized reflection entries that survive context reset.
(b) Candidate/confidence system: The Evaluator component IS the confidence gate. Sure partial outputs (passed evaluator checks) can be committed to the long-term buffer. Failed ones trigger self-reflection before retry. This maps to: commit if pass@evaluator, reflect-then-revise if fail, escalate if max_trials exceeded.
(c) When more compute helps vs hurts: Reflexion adds compute (extra LLM calls for reflection) at the inter-episode boundary, not intra-step. It helps when: (1) the evaluator is a real external oracle (unit tests, verified answer), (2) failures are specific and diagnosable in language. It hurts / adds no signal when the evaluator is weak or the model's own confidence is the only signal. The 3-trial budget is a practical upper bound; beyond that, the failure mode shifts from correctable errors to fundamental knowledge gaps that reflection cannot address.
