Algorithm: Zero-Shot Chain-of-Thought Prompting (Zero-Shot-CoT)
ArXiv: 2205.11916
Paper: Large Language Models are Zero-Shot Reasoners
Authors: Kojima, Gu, Reid, Matsuo, Iwasawa (U. Tokyo + Google Research, 2022)

WHAT IT IS:
Zero-Shot-CoT elicits step-by-step reasoning from LLMs without any few-shot exemplars by appending the trigger phrase "Let's think step by step" to the input question. This is a two-stage prompting procedure: stage 1 generates a reasoning chain, stage 2 extracts the final answer from that chain using a task-appropriate suffix. No hand-written examples are required. The method works because large models have latent reasoning ability that the trigger phrase activates, rather than teaching from demonstrations.

IMPLEMENTATION DETAILS:
Stage 1 prompt (Reasoning Extraction):
  "Q: [question text]\nA: Let's think step by step"
  -> model generates reasoning chain Z

Stage 2 prompt (Answer Extraction):
  "[Stage 1 full prompt][Z]\nTherefore, the answer (arabic numerals) is"
  -> model generates final answer
  Task-specific suffix variants:
    arithmetic: "Therefore, the answer (arabic numerals) is"
    multiple-choice: "Therefore, among A through E, the answer is"
    yes/no: "Therefore, the answer (Yes or No) is"
    free-form: "Therefore, the answer is"

Decoding: greedy decoding (temperature=0, TopK=1 for PaLM). Stop sequence "Q:" to prevent repetition.
Max generation tokens: 128 (OpenAI API), 256 (PaLM).
Trigger phrase alternatives tested (MultiArith accuracy): "Let's think step by step" = 78.7% (best); "First," = 77.3%; "Let's think about this logically." = 74.5%; "Don't think. Just feel." = 18.8% (near-baseline).

STALENESS VERDICT: PARTIALLY-STALE
Models tested are 2022 era. The specific numbers (GPT-3 175B, PaLM 540B) are obsolete. The trigger phrase "Let's think step by step" is now partially absorbed into modern instruction-tuning: many RLHF-tuned models already exhibit CoT behavior by default. However, the trigger STILL provides measurable benefit for task-specific formatting and for models that do not default to extended reasoning. Key 2025 finding: for Qwen2.5 and similar modern >7B instruction-tuned models, zero-shot CoT matches or surpasses few-shot CoT on math word problems; for <7B models the benefit is reduced because instruction-following capacity is the bottleneck (source: emergentmind.com/topics/zero-shot-cot-prompting, 2025 surveys). The two-stage structure (generate chain, then extract answer) remains useful as a design pattern independent of the specific trigger phrase.
Cite: 2025 survey findings at emergentmind.com showing Qwen2.5-14B/72B zero-shot-CoT matches few-shot-CoT.

RELEVANCE TO REASONING-STATE ENGINE:
- Cross-boundary state: the two-stage design is directly applicable — store Z (the reasoning chain) as explicit state, then run the extraction prompt with Z injected; the chain is the cross-boundary artifact.
- Candidate/confidence system: stage 1 and stage 2 are natural gates; confidence can be computed on Z before committing to the answer extraction call, avoiding a second inference on low-confidence chains.
- When more reasoning helps vs hurts: commonsense tasks (CommonsenseQA) showed degradation — the engine should classify task type and skip CoT on tasks where it is known to hurt (commonsense recall, simple factoid lookup).

Inputs:
question | str | free-form problem text | mandatory
stage2_suffix | str | task-specific extraction phrase | mandatory; must match output format (arabic/choice/yes-no)
trigger_phrase | str | "Let's think step by step" | optional default; alternatives degrade up to ~10pp

Outputs:
reasoning_chain (Z) | str | free-form intermediate reasoning | produced in stage 1; must not be empty
final_answer | str | extracted answer | produced in stage 2; must follow the stage2_suffix

Hyperparameters:
temperature | 0 | 0 for greedy | low sensitivity: greedy is canonical
max_tokens_stage1 | 128-256 | 64-512 | set by API/model; too low truncates chain
trigger_phrase | "Let's think step by step" | see ablation | alternatives lose at most ~6pp on MultiArith

Critical invariants (testable assertions):
assert len(reasoning_chain) > 0, "stage 1 must produce non-empty chain before stage 2"
assert stage2_prompt.startswith(stage1_full_prompt), "stage 2 must include stage 1 context"
assert stage2_suffix in stage2_prompt, "extraction trigger must be present in stage 2 prompt"
assert task_type != "commonsense" or explicit_override, "CoT degrades on commonsense tasks"

Complexity:
Time: 2x inference calls per query (stage 1 + stage 2); O(question_len + chain_len) tokens in stage 2
Space: context grows by ~chain_len tokens between stages; chain can reach 256 tokens
Parallelism: stages are sequential; N self-consistency samples from stage 1 can be parallelized

Failure modes:
Model continues reasoning after reaching correct answer then changes to wrong answer (over-generation)
Model rephrases the question instead of reasoning (trigger phrase not strong enough for small models)
Complex arithmetic expressions inside chains fail (model cannot compute ternary expressions reliably)
Model outputs multiple answer candidates when uncertain (stage 2 extraction fails)
Commonsense tasks degrade vs standard zero-shot (CoT introduces confabulation on factual recall tasks)
Below emergence threshold (~<7B modern): trigger phrase has minimal effect, instruction-following capacity is the bottleneck

Implementation pitfalls (do NOT do this):
Do NOT skip stage 2 and read the answer from stage 1 output directly (no extraction suffix = unreliable format)
Do NOT use the same suffix for all task types (wrong format for the answer type causes extraction failure)
Do NOT apply zero-shot-CoT to commonsense recall tasks without testing — paper shows degradation
Do NOT assume the trigger phrase is universal; test alternatives for your specific task domain
Do NOT use max_tokens < 64 for stage 1 (truncates the reasoning chain)
