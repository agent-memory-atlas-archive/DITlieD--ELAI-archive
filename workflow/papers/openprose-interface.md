WHAT IT IS

OpenProse is a natural-language programming system for AI agent workflows. A .prose.md file
is a Markdown contract that declares WHAT must be true (Requires/Ensures) rather than HOW
to achieve it. The AI model reads the contract and "becomes the virtual machine" -- it
interprets and executes the declarative spec, exercising its own judgment on implementation.

Tagline: "Write the future as a Markdown contract agents can run, review, and maintain."

Core thesis (Raymond Weitekamp): the bottleneck in agentic AI is not model capability but
TRUST and RELIABILITY. One-off successful agent sessions are not programs: they evaporate
after the chat. OpenProse converts those sessions into reusable, reviewable, versioned,
inspectable artifacts.

NOT an orchestration framework sitting between you and Claude Code. NOT a prompt template.
It is a language whose runtime IS the LLM session itself.

CORE FILE FORMAT (.prose.md)

YAML frontmatter + Markdown body. Example structure:

  ---
  name: hunter
  kind: responsibility
  services: [analyst, ranker, compiler]
  ---
  requires:
    - data_warehouse_url
    - codebase_ref

  ensures:
    - brief: weekly growth findings, ranked by
        confidence x impact

Sections:
  ### Requires     : inputs needed before execution (mandatory preconditions)
  ### Ensures      : what must be true when complete (the contract / postconditions)
  ### Services     : dependencies on other .prose.md services (composition)
  ### Strategies   : judgment-exercising guidance for known scenarios
  ### Execution    : optional ordering, conditionals, loops (ProseScript, see below)
  ### Tools        : real executables on PATH or MCP servers
  ### Maintains    : world-model schema and fields (for "standing responsibilities")
  ### Continuity   : wake source declaration (for standing responsibilities)

DIRECTORY STRUCTURE (generated by the tool)

src/          : authored .prose.md files
dist/         : compiled manifest (generated)
runs/         : receipts per run (inputs, outputs, logs, artifacts)
state/        : cross-run memory for standing responsibilities
deps/         : pinned service dependencies
prose.lock    : lockfile

EXECUTION MODEL

Each .prose.md service runs in an isolated sub-agent session.
Only outputs declared in ### Ensures cross the session boundary (explicit binding).
This prevents context pollution across multi-stage workflows.
"Standing responsibilities" maintain state across runs via state/ directory.

Commands:
  prose write    : generate .prose.md from natural language description
  prose run      : execute a service

RELIABILITY / VERIFICATION CLAIMS

Stated mechanisms:
  - Receipts: every run writes runs/{run-id}/ with inputs, outputs, logs, artifacts
    ("Done" becomes inspectable evidence, not a vibe)
  - Explicit contracts: Requires/Ensures make assumptions visible and reviewable
  - Versioning: .prose.md files are git-compatible source artifacts
  - Reusability: same contract re-runs with different agents

KNOWN LIMITATIONS (explicitly stated by authors)

1. Non-determinism persists: LLMs remain probabilistic; OpenProse adds structure but
   does NOT guarantee identical outputs across runs.
2. Garbage-in/garbage-out: "A bad Prose program will faithfully and repeatably do the
   wrong thing. The operator still has to know what good looks like."
3. Tool invocation timing is non-deterministic: tools can be declared but the agent's
   decision WHEN to call them is still probabilistic.
4. Not for every workflow: "Reserve this for workflows actually worth making repeatable."
5. Model dependency: "Only the best frontier models can currently do a good job running
   prose programs." Smaller models underperform.
6. Overhead: creating and maintaining .prose.md files has operational cost.

VERDICT AGAINST ELAI

Complementary, not competing. OpenProse addresses a DIFFERENT problem than ELAI's orchestrate:
  - OpenProse: turn one-off successful sessions into reusable declared contracts; the LLM
    IS the runtime; reliability via inspectable receipts + explicit contracts
  - ELAI orchestrate: the main LLM is an explicit controller with typed agent returns, FSM
    gates, wiring-enforcement, and off-agent verifiers; determinism via frozen gates

ELAI's approach is MORE mechanically enforced (frozen checkers, off-agent auditors) but
LESS portable (tied to this harness). OpenProse is MORE portable (any Claude Code session)
but relies on model judgment for execution.

"session-to-prose" tool mentioned: converts Claude Code logs into .prose.md programs.
This is the conversion path if ELAI wanted to export a successful orchestration pattern
as a shareable OpenProse contract -- potentially useful for SAFEDELTA or external sharing.
