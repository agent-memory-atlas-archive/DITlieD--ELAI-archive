DATASET STRUCTURE (ARC-AGI-2)

Public training tasks | 400 tasks | imported from ARC-AGI-1 | fully public | usable for training and Core Knowledge exposure
Semi-Private Evaluation tasks | 120 tasks | not publicly released | exposed to commercial APIs during competition | carries leakage risk
Private Evaluation tasks | 120 tasks | fully private | used for final competition scoring and verification | theoretically free from leakage

Task format: rectangular input grid, up to 30x30 cells, 10 distinct color values (0-9), paired with an output grid. 2+ demonstration pairs per task (median 3). 1+ test inputs per task. 2 attempts allowed per test input.

Human baseline: ARC-AGI-1 private tasks solved 97% and 98% by two individuals, collectively 100%. ARC-AGI-2: 100% of tasks solved by at least 2 independent non-expert human testers (each task attempted by 2-10 humans).

State-of-the-art scores are ONLY reported on Semi-Private and Private Evaluation sets to reduce overfitting and data contamination risk. Section 1.1, Dataset Composition.


CONTAMINATION WARNINGS (Section 4.1, Knowledge Overfitting)

1. New form of overfitting via knowledge coverage:
   AI reasoning systems can now "overfit" a benchmark without directly memorizing test samples, if public training and private test sets are sufficiently similar (i.e. i.i.d.) and the model has been trained on substantial public-domain data covering the task format.
   The paper asserts: "this phenomenon is now occurring with ARC-AGI-1 and ARC-AGI-2 -- accidentally or intentionally, although we cannot determine which."

2. Format-level contamination signal:
   Gemini 3 Deep Think correctly applied ARC color mappings (e.g. "Magenta Square on Green") inside a verification harness that did NOT mention ARC tasks or color formats. The model inferred correct color semantics from the bare structure of 2D JSON integer arrays alone.
   Implication: any model trained on ARC-format data (even unlabeled) may have absorbed task-solving patterns for ARC-AGI-1 and ARC-AGI-2 grids, invalidating novelty claims.

3. Semi-private exposure risk:
   The 120 Semi-Private Evaluation tasks "have been exposed to commercial APIs and thus carry some risk of leakage." Tasks submitted via commercial APIs during competition evaluation period may have entered training corpora of future model versions.

4. Held-out private tasks are the only contamination-resistant split:
   The 120 Private Evaluation tasks are "fully private and theoretically free from leakage" because they were never surfaced via public APIs or released.

5. Contamination is not reliably detectable from score alone:
   Because reasoning systems generalize from knowledge coverage rather than exact memorization, inflated private-set scores can arise without any detectable memorization signal. Standard membership-inference tests may not catch this.


HELD-OUT TEST SET METHODOLOGY (Section 1.1)

Split strategy:
  Training set: fully public (400 tasks, from ARC-AGI-1), used ONLY to expose Core Knowledge priors. Not used for official scoring.
  Semi-private: 120 tasks, used for intermediate leaderboard only.
  Private: 120 tasks, used for final scoring and verification. Never released.

Official score reporting rule: state-of-the-art scores must be reported ONLY on the semi-private or private evaluation splits, NOT on public training tasks. Any score reported on public training tasks is not a valid benchmark claim.

Human validation requirement for new tasks: before inclusion, every task must be solved by at least 2 independent non-expert humans with no prior training (ARC-AGI-2 standard). Each task attempted by 2-10 humans. 100% of included tasks passed this gate.

Task independence requirement: "Every task in the dataset follows a different underlying logic, requiring independent rule discovery." Tasks must not share an underlying transformation rule. Shared rules imply train-test leakage at the conceptual level even with distinct grids.

Core Knowledge constraint: tasks must not require specialized world knowledge (historical facts, language). Only assumed priors are Core Knowledge (objectness, basic topology, elementary integer arithmetic). Priors acquired by children before age 4 and universally shared.

No task recycling from public set to private: public training tasks are from ARC-AGI-1 only. New private tasks must be human-created and novel.


NOVELTY VALIDATION CRITERIA FOR NEWLY-PUBLISHED REPRODUCIBILITY TASKS

(Derived from paper principles in Sections 1.1, 4.1, 4.2; applicable to D-6 held-out task store)

1. Task must be human-solvable without prior training.
   Gate: solved by at least 2 independent non-expert humans before inclusion.

2. Task must require independent rule discovery.
   Gate: the underlying transformation logic must differ from all existing tasks in the public training set. Sharing a rule with a public task allows knowledge-coverage exploitation.

3. Task must not rely on specialized world knowledge.
   Gate: solution requires only Core Knowledge priors (objectness, topology, elementary arithmetic).

4. Grid format must conform to ARC specification.
   Gate: rectangular grid, up to 30x30 cells, values in 0-9 integer range.

5. Task must not appear in any public release or commercial API exposure.
   Gate: newly published reproducibility tasks must be withheld from ALL public APIs and repositories until after the evaluation period. Any API exposure, even temporary, invalidates the held-out guarantee.

6. Tasks must not be i.i.d. with an already-contaminated public set.
   Gate: if the new task is structurally or distributionally similar to public ARC-AGI-1/2 training tasks, the reasoning-system contamination pathway (Section 4.1) applies. Novelty requires both format novelty and distributional separation from existing public grids.

7. Score claims must specify the evaluation split.
   Gate: a score is only valid if it explicitly identifies which split was used (public training, semi-private, or private). Scores on public training tasks are not held-out scores.

FAILURE MODES CITED IN PAPER

1. Knowledge-coverage contamination (Section 4.1):
   Models trained on public ARC data generalize to private test sets via format recognition, not memorization. Benchmark scores inflate without detectable overfitting signals. Cannot determine if intentional or accidental per authors.

2. Semi-private leakage (Section 1.1):
   Tasks submitted to commercial APIs during competition evaluation may enter future model training corpora. Semi-private split carries non-zero leakage risk and cannot be treated as a clean held-out set after competition conclusion.

3. i.i.d. private/public similarity exploited by reasoning systems (Section 4.1):
   Even a private test set resists overfitting only if it is distributionally distinct from the public set. If public and private sets are i.i.d., reasoning systems with knowledge coverage can generalize without direct leakage.

4. Benchmark saturation without AGI (Section 4.2):
   High scores on ARC-AGI-1/2 no longer imply fluid intelligence; they imply knowledge coverage of the ARC domain. The benchmark must be replaced or extended (ARC-AGI-3) when this ceiling is reached.

5. Accuracy gap vs. efficiency gap (Section 4.8):
   Grand Prize accuracy gap is now primarily an engineering bottleneck; efficiency (compute cost) gap remains a fundamental-science bottleneck. A 24% score at $0.20/task is not comparable to a 54% score at $31/task for held-out generalization claims.


IMPLEMENTATION PITFALLS FOR D-6 HELD-OUT TASK STORE (do NOT do this)

Do NOT report scores on public training tasks as held-out benchmark scores.
Do NOT include tasks that share an underlying transformation rule with any ARC-AGI-1 or ARC-AGI-2 public training task.
Do NOT expose candidate held-out tasks to any commercial API (even for testing) before evaluation is complete.
Do NOT treat semi-private evaluation tasks as contamination-free; they have been exposed to commercial APIs.
Do NOT use i.i.d. sampling from existing ARC task distributions for new held-out tasks; distributional separation from public tasks is required to resist knowledge-coverage contamination.
Do NOT claim novelty for a task if the model can infer correct solution behavior from bare 2D JSON integer array structure alone (per Gemini 3 color-mapping evidence, Section 4.1).
Do NOT count a task as human-validated unless at least 2 independent non-expert humans solved it with no prior training.
Do NOT allow more than 2 solution attempts per test input in evaluation harness.
Do NOT include tasks requiring specialized world knowledge, language, or priors beyond Core Knowledge.
