Algorithm: Least-to-Most Prompting (L2M)
ArXiv: 2205.10625
Paper: Least-to-Most Prompting Enables Complex Reasoning in Large Language Models
Authors: Denny Zhou, Nathanael Scharli, Le Hou, Jason Wei, Nathan Scales, Xuezhi Wang, Dale Schuurmans, Olivier Bousquet, Quoc Le, Ed Chi
Published: ICLR 2023

WHAT IT IS
Two-stage prompting strategy for problems harder than the in-context demonstrations. Stage 1: decompose the problem into an ordered list of simpler subproblems. Stage 2: solve subproblems sequentially, feeding each prior answer into the next prompt. No training or fine-tuning. Borrowed from educational psychology ("least-to-most" scaffolding). Addresses the easy-to-hard generalization failure of CoT, which cannot generalize to problems harder than its demonstrations.

IMPLEMENTATION DETAILS
Stage 1 - Decomposition prompt structure:
  [Constant few-shot examples showing decomposition] + [Target question]
  Output: ordered list of subproblems Q1, Q2, ..., Qn
  Examples show how to split: e.g., "think, machine, learning" -> ["think"] -> ["think, machine"] -> ["think, machine, learning"]
  Domain-specific decomposition prompts do NOT generalize across domains; each domain needs its own decomposition examples.

Stage 2 - Sequential solving prompt structure per subproblem Qi:
  [Constant few-shot examples of subproblem solving] + [Q1: A1] + [Q2: A2] + ... + [Qi-1: Ai-1] + [Qi: ?]
  Prior answers A1..Ai-1 are appended verbatim to the prompt before each new subproblem.
  If a prior answer is wrong, the error propagates forward (no correction mechanism in the base algorithm).

Chaining: each new prompt = previous full context + new subproblem. Linear context growth with number of subproblems.

Hyperparameters:
  Few-shot demonstrations: 2 (base), ablated at 4 and 8 (more examples help for harder problems).
  SCAN experiments: 14 exemplars total (8 decomposition + 6 solving).
  Temperature: not explicitly reported; code-davinci-002 defaults used.
  No beam search or sampling; single-pass greedy decoding per subproblem.

Models used: code-davinci-002 (Codex, primary), text-davinci-002 (GPT-3.5 class), PaLM 540B (tested in extended results).
Year: 2022 preprint, ICLR 2023.

TESTS/BENCHMARKS
Last-letter-concatenation (code-davinci-002):
  L=4 (4-word chains): 94.0% vs CoT ~57%
  L=12 (12-word chains): 74.0% vs CoT 31.8%
  -> Demonstrates length generalization (CoT collapses; L2M sustains).

SCAN compositional generalization, length split (code-davinci-002):
  L2M with 14 exemplars: 99.7%
  CoT: 16%
  -> Largest absolute gain reported in paper.

GSM8K math word problems (code-davinci-002):
  Overall: 62.39%
  Problems requiring >= 5 steps: 45.23%
  (CoT baseline on same model ~57-60% overall)

DROP reading comprehension (code-davinci-002):
  Non-football questions: 82.45%
  Football questions: 73.42%

STALENESS VERDICT: PARTIALLY-STALE
Era: code-davinci-002 / Codex (mid-2022), PaLM 540B (2022).
2025-2026 status: The decomposition-first principle remains sound and is embedded in modern agent frameworks (DecomP, DSPy, planning-then-solving patterns). However: (a) modern instruction-tuned models (GPT-4o, Claude 3.5+, Gemini 2.0) perform native multi-step decomposition without explicit L2M scaffolding on many benchmarks where L2M showed gains; (b) 2025 test on Claude-3.5-Sonnet on AMC/AIME with L2M+PAL only matched plain PAL, showing diminished delta on capable models; (c) the domain-specificity of decomposition prompts is a real operational cost that limits plug-and-play use. What survives: the chaining pattern (accumulate prior answers in context) is the right approach for sequential state-dependent subproblems and is foundational in modern agentic pipelines.
Cite: SBSC arxiv 2502.16666 (Feb 2025) uses step-by-step coding lineage; modern prompt engineering survey arxiv 2410.12843 confirms L2M as a baseline but notes capability-overhang on stronger models.

RELEVANCE TO REASONING-STATE ENGINE
- State carriage: the accumulated [Q1: A1] ... [Qi-1: Ai-1] prefix IS the reasoning state. It is external to the model and grows linearly. In a reasoning-state engine, each Ai is a state snapshot; the engine must serialize the prefix and restore it for each subproblem call. This maps cleanly to a sequential state-buffer pattern where each step reads prior state + writes one new entry.
- Candidate system: L2M does NOT generate multiple candidates per subproblem; it is a single-path sequential algorithm. No candidate selector is involved. If combined with self-consistency (sample k L2M chains), majority vote over final answers would be the selector - but this is not part of the base algorithm. L2M is a decomposition strategy, not a search strategy.
- When more reasoning helps vs hurts: Helps when the problem has a natural sequential decomposition where earlier answers strictly constrain later steps (compositional NL tasks, chained math). Hurts or adds no value when the problem is NOT decomposable (single-step lookup, pattern matching), when the model is already strong enough to solve it end-to-end, or when decomposition errors cascade (a wrong A1 poisons A2..An with no recovery). Also degrades when the decomposition prompt domain-mismatch causes wrong subproblem generation.

Implementation pitfalls (do NOT do this):
- Do not reuse decomposition prompts across domains; domain transfer of Stage 1 fails reliably.
- Do not skip feeding prior answers to Stage 2; without accumulated context, subproblems lose their dependency chain.
- Do not apply to problems where subproblems are independent (use parallel calls instead); sequential chaining wastes latency.
- Do not assume the decomposition stage is free of errors; a wrong subproblem list silently causes the solving stage to answer the wrong questions.
- Do not use with greedy sampling and expect generalization past demonstration length without explicit length-scaling exemplars.
