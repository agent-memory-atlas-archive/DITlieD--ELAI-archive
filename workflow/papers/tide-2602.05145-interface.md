Algorithm: TIDE — Temporal Incremental Draft Engine for Self-Improving LLM Inference
ArXiv: 2602.05145
Paper: TIDE: Temporal Incremental Draft Engine for Self-Improving LLM Inference
Authors: Jiyoung Park, Hankyu Jang, Changseok Song, Wookeun Jung (MOREH)
Date: February 5, 2026

Inputs:
target_model         | LLM          | any shape        | dense or MoE transformer; must expose hidden states during verification
draft_model          | EAGLE-3      | single decoder layer + LM head | initialized from prior offline training; hot-swappable
inference_requests   | token stream | variable batch   | routed through SGLang or vLLM serving engine
gamma                | int          | scalar           | candidate token count; paper-optimal = 3; range tested 1-5
batch_size_b         | int          | scalar           | live batch size; observed continuously; drives c(b) and beta(b) lookups
alpha_observed       | float        | scalar in [0,1]  | per-request token acceptance rate; measured at runtime
T_n                  | float[]      | shape [B_max]    | profiled target model latency per batch size; collected at init
D0                   | float        | scalar           | profiled base draft model latency; collected at init
ema_short_decay      | float        | scalar           | short-term EMA decay for alpha_short; not fixed in paper, tunable
ema_long_decay       | float        | scalar           | long-term EMA decay for alpha_long; not fixed in paper, tunable
signal_threshold     | int/float    | scalar           | accumulated hidden-state volume that triggers a training round
train_eval_split     | float        | scalar in (0,1)  | fraction of signals used for validation before hot-swap deployment
shared_storage_path  | path         | -                | filesystem path visible to both inference and training engines

Outputs:
decoded_tokens       | token[]      | variable length  | speculative-decoded output; semantically identical to autoregressive (lossless by construction)
acceptance_length    | float        | scalar           | mean accepted tokens per speculation step; invariant: in [1, gamma+1]
practical_speedup    | float        | scalar           | predicted speedup from Equation 5; invariant: used as binary enable/disable threshold (> 1.0 = on)
updated_draft_model  | EAGLE-3      | same arch        | hot-swapped into inference engine after train-eval validation pass
throughput_tokens_s  | float        | scalar           | measured tokens/sec across the serving cluster

Hyperparameters:
gamma                | 3            | 1-5 (paper)      | low sensitivity above 3; Table 4 shows 3 is universally optimal; increase causes verification cost to exceed gain
ema_short_decay      | not stated   | (0,1)            | controls responsiveness to distribution shift; smaller = faster reaction; paper does not fix value
ema_long_decay       | not stated   | (0,1)            | controls trend baseline; must be slower than short decay
signal_threshold     | not stated   | > 0              | governs training frequency; too low = wasteful retraining; too high = slow adaptation
train_eval_split     | not stated   | (0,1)            | gating against regressive deployment; paper mentions validation step without fixing ratio
host_buffer_size     | not stated   | > 0 bytes        | preallocated host memory for async hidden-state transfer; must fit at least one flush batch

Critical invariants (testable assertions):
assert speculation_output_tokens == autoregressive_output_tokens  # lossless by speculative decoding contract (Section 2)
assert 1.0 <= mean_acceptance_length <= gamma + 1  # acceptance length bounded by draft length (Section 5)
assert practical_speedup_formula(alpha=1.0, gamma=3, c=0.0, beta=1.0) > 1.0  # trivial upper bound sanity check (Equation 5)
assert practical_speedup_formula(alpha=0.0, gamma=3, c=any, beta=any) < 1.0  # zero acceptance = no gain (Equation 5)
assert alpha_short_ema_decay < alpha_long_ema_decay  # short EMA must respond faster than long EMA (Algorithm 1)
assert new_draft_model_eval_loss <= old_draft_model_eval_loss  # hot-swap only when validation confirms improvement (Section 2B)
assert hidden_state_transfer_overlaps_with_verification_compute  # zero-overhead invariant; violated = TIDE degrades to SpecForge (Section 3, Figure 4)

Practical speedup formula (Equation 5):
PracticalSpeedup = (1 - alpha^(gamma+1)) / ((1 - alpha) * (c(b)*gamma + beta(b)))
  alpha  = token acceptance rate
  gamma  = candidate token count
  c(b)   = draft-to-target latency ratio at batch size b
  beta(b) = verification latency ratio accounting for compute-bound regime at batch size b
Enable speculation when PracticalSpeedup > 1.0

Selective training control (Algorithm 1 — dual EMA):
  alpha_short <- decay_short * alpha_short + (1 - decay_short) * alpha_observed
  alpha_long  <- decay_long  * alpha_long  + (1 - decay_long)  * alpha_observed
  collect_signals when alpha_short << alpha_long  (distribution shift detected)
  trigger_training when accumulated_signals >= signal_threshold
  pause_collection when alpha_short ~= alpha_long  (convergence)

4-phase acceptance monitor cycle (Figure 3):
  Phase 1 decrease:       acceptance declining, signal collection active
  Phase 2 below_threshold: acceptance < threshold, speculation disabled, training running
  Phase 3 above_threshold: retraining complete, acceptance rising, speculation re-enabled
  Phase 4 converge:       acceptance stable, signal collection paused

Complexity:
Training signal generation: O(0) marginal cost during inference — hidden states already computed by target model verification pass
Signal storage: O(N_tokens * H) where H = hidden state dimension; paper reports 0.19 TB for 100k ShareGPT vs 4.66 TB for SpecForge (25x reduction)
Training: O(same as SpecForge offline) — identical architecture; 9.16 hr vs 15.32 hr (1.67x faster total)
Inference latency: O(1) speculation overhead when compute-bound regime not exceeded; beta(b) rises sharply beyond batch ~48 for dense 120B model
Parallelism: inference and training engines are fully decoupled; asynchronous D2H transfer overlaps with CUDA verification streams

Failure modes:
Prediction model error up to 25% for smaller target models (Llama-3.3-70B-Instruct, Llama-4-Scout) where draft overhead fraction is non-negligible
Minimal throughput gain on high-entropy open-ended workloads (ShareGPT: 1.08x vs NuminaMath: 1.21x)
15-40% acceptance length degradation when draft model encounters out-of-distribution data (Table 3 cross-dataset)
Speculation correctly auto-disabled in compute-bound regime (high batch size); failure to profile T(n) at init will cause incorrect beta(b) and wrong enable/disable decisions
Hot-swap without train-eval validation risks deploying regressed draft model

Implementation pitfalls (do NOT do this):
Do NOT recompute target model hidden states for training signals — TIDE reuses inference-time hidden states via async D2H; recomputing is SpecForge behavior and eliminates the 1.67-3.02x speedup advantage
Do NOT fix speculation always-on — batch size and acceptance rate both affect practical speedup; Equation 5 must be re-evaluated continuously
Do NOT use a single EMA for acceptance monitoring — dual EMA (short + long) is required to distinguish transient fluctuation from genuine distribution shift (Algorithm 1)
Do NOT synchronously transfer hidden states to host — D2H transfer must overlap with subsequent verification CUDA compute (Figure 4); synchronous transfer serializes the pipeline
Do NOT hot-swap draft model without validation — deploy only after train-eval split confirms no regression
Do NOT assume gamma=3 is universally optimal without profiling — it holds for all paper-tested models but the optimum follows from Equation 5 given c(b) and beta(b) for the specific deployment
Do NOT allocate high-end GPUs to training in heterogeneous clusters — inference throughput gap (6.76x H100/MI250) exceeds training gap (2.44x); high-end GPUs belong on inference
Do NOT use SpecForge online mode when TIDE is applicable — online SpecForge is 3.02x slower than TIDE due to redundant signal generation (Table 2)

Verified benchmark numbers:
Training time: TIDE 9.16 hr vs SpecForge offline 15.32 hr vs SpecForge online 27.64 hr (gpt-oss-120b, 100k ShareGPT)
Storage: TIDE 0.19 TB vs SpecForge 4.66 TB
Heterogeneous throughput gains (normalized to all-inference baseline): ShareGPT 1.08x, Science 1.22x, EvolCodeAlpaca 1.17x, NuminaMath 1.21x
Prediction model error: within 3% for large models (120B, 235B), up to 25% for smaller models (70B, 17B)
GPU throughput ratios (normalized to MI250): inference H100 6.76x / MI300X 4.42x; training H100 2.44x / MI300X 1.77x
