Algorithm: PERSONA - Dynamic and Compositional Inference-Time Personality Control
ArXiv: 2602.15669
Paper: PERSONA: Dynamic and Compositional Inference-Time Personality Control via Activation Vector Algebra
Source: (Feb 2026)
Reliability: HIGH (peer-reviewed, quantitative benchmarks verified via WebFetch)

Inputs:
target_model | loaded LLM | any instruction-following model | tested on Qwen2.5-7B-Instruct and others
trait_name | str | one of Big Five (OCEAN): Openness, Conscientiousness, Extraversion, Agreeableness, Neuroticism |
contrastive_prompts | list[tuple[str,str]] | (trait-expressing system prompt, trait-suppressing system prompt) | generated by LLM
activation_layer | int | middle-to-late layers | sweep required per model

Outputs:
persona_vector | tensor | shape [hidden_dim] | unit-norm direction in residual stream for trait
composed_vector | tensor | shape [hidden_dim] | sum of weighted trait vectors for multi-trait control
steered_output | text | | model output after decode-time activation steering

Hyperparameters:
scalar_coefficient | default: 1.0 | range: [-3.0, 3.0] | Pearson r > 0.9 for trait linearity within [-2, 2]; beyond is nonlinear
trait_count_for_composition | default: 1 | max: ~5 before interference | more traits = more vector cross-talk
dynamic_adaptation_window | context-aware | Persona-Flow stage | controls how often steering vector is recomputed

Three-stage architecture (maps to Task 7 implementation):
Stage 1 Persona-Base: extract orthogonal trait vectors via contrastive activation analysis
  - LLM generates (expressing, suppressing) system prompts + eval questions + scoring rubrics
  - Run target model under both conditions; collect residual stream activations
  - Persona vector = mean(expressing_activations) - mean(suppressing_activations), then L2-normalize
Stage 2 Persona-Algebra: algebraic operations on vectors
  - Intensity: persona_vector * scalar_coefficient
  - Composition: vector_A + vector_B (combine multiple traits)
  - Suppression: activations - persona_vector * coefficient (remove a trait)
Stage 3 Persona-Flow: context-aware dynamic adaptation
  - Predict current context requirements -> select + weight trait vectors dynamically
  - Recompose vector per turn based on conversational context

Complexity:
Vector extraction: one-time at boot; O(N_pairs * seq_len * hidden_dim) per forward pass
Steering overhead: O(hidden_dim) per token (vector addition to activations)
Persona-Flow recompute: O(context_len * hidden_dim) when context shifts

Failure modes:
Traits aligned with safety training (e.g., dependable) show ceiling effects -- cannot steer beyond trained range
Safety-misaligned traits (e.g., self-interested, evil) show strong resistance even at high coefficients
Information fidelity metrics remain lower (43-61%) than style metrics -- factual accuracy suffers more than tone
Abliterated model variants behave differently from standard instruct variants for safety-aligned traits
Cross-dimensional trait correlations exist despite orthogonality assumption -- impure single-trait steering

Quantitative results:
PersonalityBench: mean 9.60 (near fine-tuning level 9.61)
Persona-Evolve: win rates 73.2-90.8% across model families; Qwen3-4B: 90.8%
Trait linearity: Pearson r > 0.9 for scalar coefficient in [-2, 2]

Implementation pitfalls (do NOT do this):
Do NOT assume OCEAN Big Five vectors from 2602.15669 map to ELAI-assistant voice traits directly
  -- ELAI needs (ELAI-assistant example, neutral example) contrastive pairs, not Big Five stimuli
Do NOT skip contrastive prompt generation step; canned prompts produce noisy vectors
Do NOT use coefficients > 2.0 without monitoring information fidelity degradation
Do NOT claim 90.8% win rate for Qwen2.5-Coder abliterated 3B/7B without empirical validation
Do NOT compose more than 3 trait vectors simultaneously without cross-talk testing
