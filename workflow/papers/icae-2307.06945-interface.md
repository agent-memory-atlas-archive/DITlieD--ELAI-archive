Algorithm: ICAE (In-Context Autoencoder for Context Compression in a Large Language Model)
ArXiv: 2307.06945
Paper: In-context Autoencoder for Context Compression in a Large Language Model
Authors: Tao Ge, Jing Hu, Lei Wang, Xun Wang, Si-Qing Chen, Furu Wei (Microsoft Research)
Venue: ICLR 2024

COMPRESSION CHARACTERIZATION
Lossy: YES. At 4x compression (512 tokens -> 128 memory slots): BLEU ~0.98 median but EM ~0.6 (only ~300/512 tokens recoverable). Paper explicitly states compression degrades with context length.
LLM call required to compress: YES. Encoding requires a forward pass through the LoRA-adapted encoder LLM. This is a neural network inference step, not a deterministic text transform.
Compression axis: token count (4x ratio); information loss measured on EM (exact match) reconstruction — 40% of content not exactly recoverable at 512 tokens.
Deterministic: NO (model inference; stochastic depending on temperature, though encoding is typically deterministic at inference with greedy decode).

Inputs:
context | str/List[str] | up to 512 tokens per segment (primary experiments) | mandatory; the text to compress
k | int | scalar | mandatory; number of memory slots to produce (default 128, tested 32/64/256)
encoder_lora_weights | LoRA delta weights | rank-128 applied to Q and V projections | mandatory; the learned compression parameters
prompt_or_instruction | str | variable | optional; appended after memory slots for downstream task

Outputs:
memory_slots | FloatTensor | [k, d_model] | continuous vector representations; fed as prefix to decoder
reconstructed_text | str | variable | only in autoencoding mode; lossy reconstruction of original context
response | str | variable | decoder output given memory slots + question

Hyperparameters:
k (memory_slots) | 128 | tested 32, 64, 256 | capacity bottleneck: fewer slots = more loss; 128 is sweet spot for 512-token contexts; paper shows degradation above 400 tokens with k=128
lora_rank | 128 | not varied | applies to Q and V projections only; 1% additional parameters relative to base LLM
lambda_autoencoding | 0.4-0.6 | [0, 1] | weighting between autoencoding and text-continuation loss; paper reports 0.4-0.6 optimal
learning_rate_pretrain | 1e-4 | not tuned | AdamW optimizer
learning_rate_finetune | 5e-5 | not tuned | instruction fine-tuning on PwC dataset
max_context_length | 512 tokens | architectural limit in primary experiments | longer contexts not validated beyond 512

Critical invariants (testable assertions):
assert memory_slots.shape == (k, model.config.hidden_size), "memory slots must match model hidden dim"
assert k <= context_token_count, "cannot have more memory slots than input tokens (no expansion)"
# from paper Figure 4: BLEU collapses for random/incoherent text — structural content assumption
assert bleu_score > 0.5, "BLEU below 0.5 indicates compression failure (random text or too long context)"
# from paper §3: memory slots consumed by decoder as prefix, must precede any instruction tokens
assert memory_slots_position == "prefix_before_instruction", "memory slots must be positioned before prompt"
# from paper: EM drops from ~1.0 at <=300 tokens to ~0.6 at 512 tokens with k=128
assert context_length <= 512 or k > 128, "k=128 is insufficient for contexts longer than ~400 tokens"

Complexity:
Time: O(L^2) encoder forward pass where L = context length (full transformer attention); O(k^2 + L_prompt^2) decoder forward pass; k << L so decoder is fast
Space: O(k * d_model) for memory slots (tiny); O(L^2) encoder KV-cache during encoding
Parallelism: encoding can be parallelized across independent contexts; decoder is causal (sequential); encoder+decoder cannot be fused into one pass for novel contexts

Failure modes:
Memory capacity exhausted: context length > 400 tokens with k=128 shows monotonic BLEU/EM decline (paper Figure 4)
Random/incoherent text: compression nearly fails (BLEU 0.2-3.5 vs 99.3 for natural text) — the encoder exploits text structure
Model scale dependency: only tested on Llama-7B and Llama-2-7B/13B; larger models not validated
Cross-model failure: memory slots from encoder LLM A cannot be consumed by a different decoder LLM B (different embedding spaces)
Out-of-distribution: trained on general text; compression quality degrades on highly technical/code/math content (not measured but expected per BLEU pattern)
Instruction-following regression: ICAE instruction fine-tuning may degrade base LLM instruction-following on tasks not in PwC dataset

Implementation pitfalls (do NOT do this):
Do NOT reuse memory slots across different base LLMs — they are embedding-space-specific
Do NOT use k=128 for contexts longer than 400 tokens without measuring EM degradation first
Do NOT apply to random or highly repetitive/noise text without validation — compression catastrophically fails
Do NOT omit the autoencoding pretraining objective — instruction fine-tuning alone produces poor memory representations
Do NOT treat ICAE as lossless — EM of 0.6 at 512 tokens means 40% information is irrecoverable verbatim
Do NOT skip LoRA for the encoder — full fine-tuning destabilizes the decoder's language modeling
Do NOT compress across segment boundaries without separate memory slots per segment

Benchmark results (verified):
Autoencoding Llama-7b k=128: context <=300 tokens -> ~100% BLEU, ~100% EM; 512 tokens -> median BLEU 98%, EM 0.6
Text continuation PPL (512->128): original context PPL 9.01 vs memory slots PPL 9.50 (+0.49 delta) on WikiText
Instruction following (GPT-4 eval): Llama-2-7b ICAE vs GPT-4 -> 74.2% win+tie; Llama-2-13b ICAE -> 80.8% win+tie
Latency: 8x2048 context -> 3.3x speedup (7.3s vs 24.0s); with KV caching -> up to 7x speedup

ELAI fit:
ICAE COLLIDES with all three ELAI hard rules. (a) Compression requires an LLM encoder forward pass — not a deterministic reversible transform; the ban on LLM-resummarization of cache prefixes directly targets this mechanism. (b) The append-only journal stores text; memory slots are float tensors that cannot be stored in a text journal and recovered. (c) Memory slots are bound to the specific encoder LLM's embedding space — they are not a typed belief-state transferable across models. ICAE is architecturally incompatible unless ELAI abandons cross-model handoffs and switches to a dedicated fixed encoder/decoder pair, at which point the system is no longer "cross-model."
