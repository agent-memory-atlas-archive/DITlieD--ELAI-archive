Inputs:
left_context (X_l) | token sequence | variable length | the code to the left of the cursor in the current file
right_context (X_r) | token sequence | variable length | the code to the right of the cursor in the current file
retrieved_context (CC) | token sequence | optional | cross-file code snippets; absent if model abstains
abstention_threshold (T) | float | [0.0, 1.0] | threshold on P(<cc>) to decide whether to retrieve; task-dependent

Outputs:
retrieval_decision | binary token | {<cc>, phi} | <cc> means retrieve, phi means skip
completed_code (Y) | token sequence | variable length | the code completion filling the masked span
edit_similarity_score | float | [0.0, 1.0] | quality measure used during training label construction


Hyperparameters:
abstention_threshold_T_function | 0.15 (function completion), 0.20 (line/API completion) | [0.0, 1.0] | "T=0.15 for function completion and T=0.2 for the other tasks generally work well for P(<cc>)" (Section 5.2); primary sensitivity knob; lower T -> more retrieval
training_label_threshold | 0.0 (StarCoderBase-1B labeler default) | [0.0, 1.0] | threshold on EditSim improvement to decide label=1 in self-supervised training (Appendix D)
lambda | 1.0 | [0.0, inf) | weight on eval loss vs gen loss; lambda * L_eval + L_gen (Section 4.1)
labeler_model | StarCoderBase-1B | - | model used to generate self-supervised labels during training (Appendix D); authors note larger labeler does not significantly change label quality
training_dataset_size | 240k chunk + 120k function instances | - | label corpus built from The Stack (Appendix D)


Abstention Decision Rule (VERBATIM from paper, anti-hallucination anchor):

Section 3.2: "After observing X_l and X_r, the LM directly self-triggers cross-file retrieval by
generating a special token <cc> or abstains from retrieval via an empty token phi."

Footnote in Section 3.2: "In practice, instead of greedily decoding <cc>, we check whether its
probability exceeds a certain threshold."

Inference algorithm (from Section 3.2 + 5.2):
  1. Append <eof> after the current file context [X_l, X_r]
  2. Forward pass; compute P(<cc> | X_l, X_r, <eof>)
  3. If P(<cc>) >= T: trigger retriever -> append CC to context -> generate Y | X_l, X_r, CC
  4. Else (phi): skip retriever -> generate Y | X_l, X_r  (no CC, no retrieval latency)

The T threshold is set per task, NOT per model or per token. Decision is a single scalar check.


Training Label Construction (VERBATIM from paper, Section 3.3 + Appendix D):

"Sample target lines Y"
"Retrieve CC with/without Y"
"Label whether extending the current file with CC can improve a code LM's code completion
 quality by more than a threshold T, measured by Edit Similarity against Y."

Formal label (from Section 3.3 Equation framing):
  label = 1  iff  EditSim(Y_hat_with_CC) - EditSim(Y_hat_without_CC) > T_label

Self-supervised: labels generated by running StarCoderBase-1B (NOT the trained model itself).
Training data sourced from The Stack. 240,000 chunk instances + 120,000 function instances.


Training Objective (VERBATIM from paper, Section 3.3):

Equation 1: L_eval = -log p_M(<cc> | X_l, X_r)
Equation 2: L_gen = { -log p_M(Y | X_l, X_r, CC)  if label=1
                    { -log p_M(Y | X_l, X_r)        if label=0
Final:       lambda * L_eval + L_gen    (lambda = 1.0 per Section 4.1)

Multi-task: the model jointly learns WHEN to retrieve (L_eval) and HOW to use retrieved context (L_gen).
This is not a separate classifier; the policy is embedded in the LM's next-token distribution.

Architecture Summary:
  Model architecture: extension of fill-in-the-middle (FIM) code LM
  Special tokens added: <cc> (retrieve trigger), phi (abstain)
  Placement of decision: after <eof> token appended to [X_l, X_r]
  Retriever: BM25 or dense retrieval (paper evaluates both; selective policy is retriever-agnostic)
  The policy can run as a SEPARATE smaller model (1B) controlling a LARGER generator (7B, 16B)
  Figure 1(a): "Given the current file context, a policy first assesses whether retrieval is required
  and triggers the retriever selectively."

Complexity:
Time (inference, retrieve path): O(retrieval) + O(LM_generation); same as standard RAG
Time (inference, abstain path): O(1 forward pass for P(<cc>)) + O(LM_generation); ~27% faster
Space: same as base LM + retrieval index; no additional structures at inference time
Parallelism: abstention check is serial with generation; retrieval can be parallelized with prefill


Failure Modes (from paper):
1. Retrieval is harmful ~15-38% of the time (motivates the paper; Table 1 in paper)
2. Function completion has lower abstention precision (0.78) than other task types
3. At high T values (aggressive abstain), performance degrades below no-retrieval baseline
4. Policy trained on 1B may produce miscalibrated P(<cc>) on very different code distributions
5. Self-supervised labels depend on the quality of the labeler model (StarCoderBase-1B)


Implementation Pitfalls (do NOT do this):
Do NOT always retrieve; the paper's core finding is that ~62-78% retrieval rate is optimal
Do NOT use greedy argmax on <cc>; use the probability threshold P(<cc>) >= T
Do NOT use a single threshold T for all task types; function vs line vs API completion differ
Do NOT use the same model for labeling and training (use a frozen labeler for self-supervised labels)
Do NOT treat the policy as a binary classifier trained separately; it is a multi-task LM loss
Do NOT assume the policy must be the same model as the generator; the 1B-as-policy design works


REIMPLEMENTATION NOTES FOR ELAI:

ELAI's existing tier router (FAST/STANDARD/DEEP) is a token-budget / latency tier, NOT a
retrieval-abstention gate. Repoformer adds a NEW orthogonal signal: a per-query P(<cc>) that
decides whether to fire the retriever at all, before any tier selection.

Bolt-on point in ELAI's pipeline:
  1. ELAI's query_class.rs classifies query complexity and selects tier.
  2. INSERT HERE: a Repoformer-style retrieval-gating step at query_expansion.rs or pipeline.rs
     before the BM25/ONNX vector search fires. Signal: P(retrieval_needed | query_tokens).
  3. If P < T_task: skip retrieval, proceed directly to generation with local context only.
  4. If P >= T_task: fire the existing tantivy/ONNX/RRF retriever as normal.

Training signal for ELAI's gate:
  - Label generation: run ELAI's existing generator on held-out completions WITH vs WITHOUT
    retrieval; label=1 iff EditSim improves by > T_label.
  - Loss: same L_eval + L_gen multi-task objective (Equations 1 and 2).
  - The sidecar (Qwen2.5-Coder-7B) is the natural host for P(<cc>) since it already handles
    token-level generation; add <cc>/phi special tokens to the sidecar's vocabulary.

Load-bearing components (4):
  - query_class.rs or pipeline.rs: insertion point for the gate check
  - A new RetrievalGateConfig (T per task type, stored in RuntimeConfig / runtime_config.rs)
  - Self-supervised label generation script (offline, runs once over ELAI's training corpus)
  - Sidecar vocabulary extension for <cc> and phi tokens (server.py tokenizer patch)

Key gap ELAI lacks: the abstention mechanism itself. ELAI always retrieves when a query hits
the retrieval tier. There is NO P(retrieval_needed) signal anywhere in the current pipeline.
This is a genuine new capability Repoformer adds.


CONTRACT TEST STUBS:

def test_abstention_threshold_function():
    # Repoformer Section 5.2: T=0.15 for function completion
    T_function = 0.15
    p_cc_high = 0.9  # should trigger retrieval
    p_cc_low = 0.05  # should abstain
    assert p_cc_high >= T_function, "high confidence should trigger retrieval"
    assert p_cc_low < T_function, "low confidence should abstain"

def test_abstention_threshold_line():
    # Repoformer Section 5.2: T=0.20 for line/API completion
    T_line = 0.20
    p_cc_boundary = 0.20
    assert p_cc_boundary >= T_line, "boundary value should trigger retrieval"

def test_training_label_construction():
    # Section 3.3: label=1 iff ES improves by > T_label when CC added
    import numpy as np
    T_label = 0.0
    es_with_cc = 0.75
    es_without_cc = 0.60
    label = int((es_with_cc - es_without_cc) > T_label)
    assert label == 1, "ES improvement > 0 should yield positive label"

def test_loss_weights():
    # Section 4.1: lambda=1.0
    import numpy as np
    lambda_weight = 1.0
    l_eval = 0.5
    l_gen = 0.8
    total_loss = lambda_weight * l_eval + l_gen
    assert abs(total_loss - (l_eval + l_gen)) < 1e-9, "lambda=1.0 means equal weighting"

def test_abstention_precision_floor():
    # Figure 4: precision > 0.78 on all tasks
    abstention_precision_floor = 0.78
    measured_precision = 0.81  # example measurement
    assert measured_precision >= abstention_precision_floor, "precision must exceed paper floor"
