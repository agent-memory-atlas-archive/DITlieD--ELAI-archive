Algorithm: ReAct - Synergizing Reasoning and Acting in Language Models
ArXiv: 2210.03629
Paper: ReAct: Synergizing Reasoning and Acting in Language Models
Authors: Yao, Zhao, Yu, Du, Shafran, Narasimhan, Cao (ICLR 2023, v3 Mar 2023)

WHAT IT IS:
ReAct interleaves free-form reasoning traces (Thoughts) with environment-facing actions (Actions) in a single LLM generation sequence. The key departure from pure CoT: every action produces an Observation from the environment, and that observation is fed back into the context before the next thought. This grounds reasoning in retrieved external evidence, reducing hallucination relative to closed-loop CoT. The full context c_t grows as (o1, a1, thought1, ..., o_{t-1}, a_{t-1}, thought_{t-1}, o_t, thought_t) and is passed in full on each step.

IMPLEMENTATION DETAILS:

Loop structure:
  Thought_t: free-form language. Does NOT affect environment. Used to reason, plan, diagnose, synthesize observations.
  Action_t: task-specific API call. Examples: Search[entity], Lookup[keyword], Finish[answer] for QA; click[element], type[text] for WebShop.
  Observation_t: environment return (retrieved text, page state, reward signal). Always external.
  Context grows linearly; no pruning described in the original paper.

Prompting: few-shot, manually annotated exemplars.
  HotpotQA: 6 exemplars.
  FEVER: 3 exemplars.
  ALFWorld: 3 exemplars per task type (6 types = 18 total).
  WebShop: 1-2 exemplars.
  Exemplar format: Thought/Action/Observation traces showing question decomposition, retrieval, reasoning, synthesis.

Models:
  Primary: PaLM-540B (frozen, prompted only). Inference: greedy decoding.
  Baseline comparison: GPT-3 text-davinci-002, which outperformed PaLM on several tasks.
  No fine-tuning. No temperature specified for main experiments.

TESTS/BENCHMARKS:
HotpotQA (multi-hop QA): ReAct EM 27.4 vs CoT 29.4 vs Act-only 25.7. SoTA at time: 67.5. Note: ReAct is below CoT on EM but above on hallucination rate (6% false positive vs 14% CoT).
FEVER (fact verification): ReAct 60.9% vs CoT 56.3% vs Act-only 58.9%. SoTA: 89.5%.
ALFWorld (embodied navigation, 134 envs): ReAct 71% task success vs Act-only 45% vs BUTLER 37%.
WebShop (e-commerce task): ReAct 40.0 SR vs Act-only 30.1 vs IL+RL 28.7.
Model era: PaLM-540B, GPT-3 text-davinci-002 (2022-2023). Neither is instruction-tuned in the fine-tuned sense; davinci-002 is an RLHF-tuned base model.

STALENESS VERDICT: PARTIALLY-STALE (what survives is the architecture, not the performance claims)
What survives: ReAct is the de-facto standard tool-use loop in production agentic systems (LangChain, LangGraph, CrewAI, Claude tool-use, OpenAI Assistants all implement this Thought/Action/Observation pattern). The Thought step improves task success on navigation/interactive tasks vs Action-only baselines - this result holds across model generations.
What is stale:
(1) The performance numbers. Both PaLM-540B and text-davinci-002 are 2022 models. Modern instruction-tuned models (Claude 3, GPT-4o, Llama-3) follow the ReAct format without few-shot exemplars due to RLHF/SFT on tool-use trajectories.
(2) The reasoning-as-cause claim. arXiv:2405.13966 (May 2024, "Brittle Foundations of ReAct") established that performance is minimally influenced by the interleaved reasoning trace itself; what drives performance is exemplar-query similarity. The Thought token is useful for grounding but not for genuine multi-step causal reasoning.
(3) HotpotQA/FEVER absolute numbers are far below 2025 SoTA. Current instruction-tuned models with RAG achieve >80% on HotpotQA EM.
Current verdict: The Thought/Action/Observation loop is correct and essential for tool-augmented generation. The reasoning trace is a useful intermediate output for tracing and debugging, not a guarantee of logical soundness. Production systems add: loop termination (max steps), error recovery on bad actions, and plan-then-execute for well-defined multi-step tasks.

RELEVANCE TO REASONING-STATE ENGINE:
(a) Cross-boundary state: The full trajectory context c_t IS the reasoning state. Every Thought/Action/Observation triple is a serializable state frame. At a context boundary, the reasoning state = the compressed history of (thought, action, observation) tuples. The Thought field is the most compressible (it is reasoning about the observation, not the observation itself). A cross-model handoff packages: current task, observations so far, last N thought-action-observation triples, pending action if any.
(b) Candidate/confidence system: The Thought step is where confidence signals live naturally. A sure step emits Thought="I have confirmed X from observation, proceeding to Y." An uncertain step emits Thought="The observation is ambiguous; I will search for Z before deciding." A reasoning engine can intercept after Thought but before Action, evaluate confidence (e.g. PRM score on the thought, or ask: does this thought commit to a verifiable claim?), and either proceed, request additional tool calls, or escalate to the external validator before executing the Action.
(c) When more compute helps vs hurts: More Thoughts before each Action reduce hallucination (grounding effect) but add latency linearly. The 2405.13966 finding implies: exemplar quality matters more than reasoning depth for task success. For a reasoning engine: invest compute in better exemplar selection (retrieval-augmented few-shot) rather than more Thought tokens per step. Adding more Observation-gathering actions (deeper search) helps more than deeper reasoning on stale information. Hard limit: if the agent enters a repetitive loop (same thought-action pair for 2+ steps), the reasoning state is stuck - a forced escalation is better than more self-loops.
