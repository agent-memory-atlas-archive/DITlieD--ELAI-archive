Algorithm: DeNovoSWE - Divide-and-Conquer Pipeline for Repository Generation Training Data
ArXiv: 2606.10728
Paper: DeNovoSWE: Scaling Long-Horizon Environments for Generating Entire Repositories from Scratch

Inputs:
source_repositories | GitHub repos | N repos | original unit-test pass rate >= 90%, test coverage >= 50%, permissive OSS license (MIT/Apache-2.0/BSD)
documentation | text | per-repo | auto-generated from source via Draft-Critic-Repair cycle; covers capability decomposition + module-level specs
rollout_trajectories | agent execution traces | 3 rollouts per instance (6 for failed) | generated by DeepSeek-V4-Pro via OpenHands framework; includes tool invocations
difficulty_score | float | scalar per instance | range [0.0, 1.0]; weighted combo of 3 signals: structural (exec Python lines log-norm), LLM-judge (two annotators 1-5 scale), empirical (mean pass rate across rollouts)

Outputs:
training_dataset | jsonl | 4818 instances | each instance: documentation + reference repository + filtered trajectories; 11k trajectories after filtering from ~34k raw
filtered_trajectories | agent traces | ~11k total | pass-rate above adaptive threshold per difficulty band; loss masking applied to failed tool invocations
fine_tuned_model | LLM weights | Qwen3-30B-A3B or Qwen3.5-35B-A3B | evaluated on BeyondSWE-Doc2Repo and NL2RepoBench

Hyperparameters:
learning_rate | 1e-5 | range not stated; standard SFT value | not flagged as sensitive in paper
batch_size | 128 | not varied in ablation | not flagged as sensitive
context_length | 131072 tokens | hard ceiling; matches Qwen3 window | critical: repo-scale generation requires full context
warmup_ratio | 0.05 | standard | not flagged as sensitive
max_agent_steps_eval | 400 | hard cap during evaluation | limits recovery from early mistakes
max_new_tokens_eval | 32768 | per-step ceiling | combined with 262144 total token budget
total_token_budget_eval | 262144 | hard ceiling | agents that exhaust budget score 0
difficulty_weights | [w_structural, w_llm, w_empirical] | grid-searched to maximize abs Pearson r with empirical pass rate | sensitive: poor weights degrade trajectory quality
adaptive_threshold_bands | [0.90, 0.85, 0.80, 0.70, 0.60] for difficulty [0,0.2), [0.2,0.4), [0.4,0.6), [0.6,0.8), [0.8,1.0] | validated via ablation | key design choice: fixed thresholds uniformly worse

Critical invariants (testable assertions):
assert original_repo_pass_rate >= 0.90, "repos below 90% pass rate must be excluded from dataset"
assert original_repo_coverage >= 0.50, "repos below 50% test coverage excluded"
assert len(rollouts_per_instance) >= 3, "minimum 3 rollouts required; 6 for initially-failed instances"
assert difficulty_score >= 0.0 and difficulty_score <= 1.0, "difficulty score must be in unit interval"
assert trajectory_pass_rate >= adaptive_threshold(difficulty_score), "trajectory filtered out if below adaptive band threshold"
assert "pip install" not in eval_environment and "git clone" not in eval_environment, "evaluation sandbox must block package fetch and repo clone to prevent leakage"
assert total_tokens_used <= 262144, "agent must not exceed total token budget during evaluation"

Complexity:
Dataset construction: O(N * K * R) where N=repos, K=capabilities per repo (varies), R=critic-repair iterations
Rollout generation: 3-6 LLM agent runs per instance; parallelizable across instances
Training: standard SFT on ~11k trajectories with 131072-token context; dominant cost is per-token at context length
Evaluation: 400 max steps * up to 262144 tokens per instance; parallelizable across instances
Parallelism: instance-level parallelism for both construction and evaluation; no inter-instance dependencies

Failure modes:
Leakage bypass: agents may attempt git clone or pip install to fetch reference implementation; static rules insufficient, requires LLM-as-judge audit
Documentation incompleteness: Critic-Repair cycle may not converge on complete specs for repos with complex implicit contracts not covered by unit tests
Difficulty score miscalibration: LLM annotator disagreement (two independent annotators on 5-point scale) injects noise into weights; poor Pearson r means thresholds misaligned
Context overflow: repos with >131072 tokens of context cause truncation; large repos underrepresented
Evaluation variance: results averaged over 3 independent execution trials; high-variance tasks inflate/deflate measured performance
Fixed format evaluation: NL2RepoBench and BeyondSWE-Doc2Repo may not capture all valid repository structures

Implementation pitfalls (do NOT do this):
Do NOT apply a fixed pass-rate threshold uniformly across all difficulty levels; adaptive thresholds are strictly better per ablation
Do NOT skip loss masking on failed tool invocations during training; including failed-step loss degrades learning signal
Do NOT evaluate without sandboxing; agents trained on this data will attempt to fetch the reference implementation
Do NOT assume 3 rollouts is sufficient for hard instances (difficulty >= 0.4); hard instances need 6 rollouts to get enough successful trajectories
Do NOT use test-file callers to validate documentation completeness; only unit-test pass rate on generated code counts
Do NOT reuse the same DeepSeek-V4-Pro rollouts across train/eval splits without deduplication by repo identity
