Algorithm: Tree of Thoughts (ToT)
ArXiv: 2305.10601
Paper: Tree of Thoughts: Deliberate Problem Solving with Large Language Models
Authors: Shunyu Yao, Dian Yu, Jeffrey Zhao, Izhak Shafran, Thomas L. Griffiths, Yuan Cao, Karthik Narasimhan
Published: NeurIPS 2023

WHAT IT IS
Frames problem solving as tree search over intermediate reasoning steps ("thoughts"). Each node is a partial solution state s=[x, z1..zi]. The model generates multiple candidate thoughts at each step, scores/evaluates them (using the same or a separate LLM call), then applies BFS or DFS to navigate the tree. Enables backtracking and lookahead that linear CoT cannot do.

IMPLEMENTATION DETAILS
Thought generation - two strategies:
  (A) i.i.d. sampling: sample k candidates independently from a CoT-style prompt. Used when thought space is rich (e.g., paragraphs of prose).
  (B) sequential proposal: generate k thoughts in one prompt listing them. Used when thoughts are constrained (equations, words).

Thought evaluation - two strategies:
  (A) independent value: prompt LLM to score each state independently; output scalar 1-10 OR classification (sure/likely/impossible). Aggregate: average or mode over n=3 value samples.
  (B) comparative vote: prompt LLM to pick the most promising state from a set; aggregate over n=5 votes by majority.

Search algorithms:
  BFS: maintain b best states per step. At each depth, generate k candidates per state, evaluate all, keep top-b. Used for shallow problems (depth 3). b=5 in all reported experiments.
  DFS: explore most-promising state first via recursive descent. Prune when V(s) <= v_th (value threshold). Backtrack to parent when pruned or step limit exceeded.

Hyperparameters (from paper, task-specific):
  k (candidates per step) = 5 across tasks
  b (BFS beam width) = 5
  T (max steps) = 3 (Game of 24), 2 (Creative Writing), up to 10 (Crosswords)
  n (evaluation samples) = 3 for values, 5 for votes
  DFS step limit = 100 (Crosswords)
  v_th = task-specific (Crosswords: if evaluator marks impossible, prune)

Prompt structure:
  Propose prompt: "Given [remaining state], propose possible next steps..." (k outputs)
  Value prompt: "Given [state], evaluate if this is on track to solve [goal]. Rate sure/maybe/impossible or 1-10."
  Vote prompt: "Given [set of states], which is most promising? Vote for one."
  All prompts are few-shot with 2-5 in-context examples.

Decoding: temperature sampling for generation (paper does not specify exact temperature; GPT-4 API default used). Greedy for evaluation prompts implied.

TESTS/BENCHMARKS
Models: GPT-4 (primary), GPT-3.5-turbo (comparison baseline). Year: 2023 models.

Game of 24 (100 test games):
  IO prompting (GPT-4): 7.3%
  CoT (GPT-4): 4.0%
  Best-of-100 CoT (GPT-4): 49%
  ToT b=1 (GPT-4): 45%
  ToT b=5 (GPT-4): 74%
  ToT b=5 (GPT-3.5): 19%

Creative Writing (100 tasks, automatic score 1-10):
  IO (GPT-4): 6.19
  CoT (GPT-4): 6.93
  ToT (GPT-4): 7.56
  Human preference: ToT favored in 41/100 comparisons vs CoT

Mini Crosswords (20 games):
  IO (GPT-4): 14% word-level
  CoT (GPT-4): 15.6%
  ToT (GPT-4): 60% word-level, 4/20 fully solved

Ablation (Mini Crosswords):
  Full ToT: 60%
  Without pruning: 41.5%
  Without backtracking (greedy BFS): 20%
  -> Backtracking is the single biggest contributor.

Cost: ToT requires 5-100x more tokens than single CoT call. Game of 24: $0.74/case ToT vs $0.47/case best-of-100 CoT.

STALENESS VERDICT: PARTIALLY-STALE
Era: GPT-4 (March 2023 vintage, base GPT-4 not GPT-4o/4.1).
2025-2026 status: The core branching-and-evaluation mechanism still delivers gains (+5pp over CoT for medium/large models >=20B on math word problems per 2025 benchmarks). However: (a) modern instruction-tuned models (GPT-4o, Claude 3.5+) are much stronger at single-pass CoT, narrowing the gap; (b) the LLM-as-evaluator step is now known to be unreliable (self-evaluation bias - models rate their own outputs too favorably); (c) Process Reward Models (PRMs) trained separately are demonstrably superior selectors vs LLM self-scoring (ReST-MCTS* and related 2024-2025 work); (d) 8B models still lack capacity for effective branch evaluation. What survives: the tree-search scaffolding as a framework for combining with external evaluators/PRMs. Self-evaluation component specifically is the stale part.
Cite: QM-ToT arxiv 2504.12334 (Apr 2025) shows ToT still beneficial in medical reasoning on quantized models; Plan of Thoughts arxiv 2404.19055 (2024) extends the search policy.

RELEVANCE TO REASONING-STATE ENGINE
- State carriage: ToT state s=[x, z1..zi] is exactly a reasoning-state object that carries context across steps. BFS/DFS requires externalizing this state (the tree) entirely outside the model - directly maps to a candidate buffer in a reasoning-state engine. Each node is a snapshot that can be resumed, forked, or abandoned.
- Candidate system: Multiple reasoning paths generated in parallel, evaluated, and the best advances. The SELECTOR is the LLM scoring its own candidate paths (self-evaluation). This is the weakest link: the same model that generated a candidate also scores it, creating an in-boundary artifact. In 2025 the preferred replacement is an external PRM or a deterministic checker when one exists (e.g., proof checker, code execution result, test suite pass/fail). External signal is strictly superior when available.
- When more reasoning helps vs hurts: Helps on combinatorial/search tasks where the solution space has multiple valid intermediate states and wrong early choices can be corrected by backtracking (Game of 24, crosswords, multi-step math). Hurts (or wastes compute) on tasks where the model's first-pass CoT is already near-optimal and the evaluator cannot distinguish candidates better than chance - particularly on open-ended generation tasks or tasks where the LLM evaluator is poorly calibrated. ToT adds no value when the problem is solvable greedily or when all k candidates collapse to the same answer.

Implementation pitfalls (do NOT do this):
- Do not use the same model temperature for both generation and evaluation; evaluation should use lower temperature or greedy.
- Do not skip the value aggregation (n=3 samples); single-sample evaluation is noisy.
- Do not use BFS for deep trees (>5 steps); exponential branching factor makes it intractable.
- Do not treat ToT as a drop-in CoT replacement; it requires task-specific propose and value prompt design.
- Do not assume the LLM evaluator is reliable; replace with external signal whenever possible.
