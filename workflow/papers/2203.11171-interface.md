Algorithm: Self-Consistency
ArXiv: 2203.11171
Paper: Self-Consistency Improves Chain of Thought Reasoning in Language Models
Authors: Xuezhi Wang, Jason Wei, Dale Schuurmans, Quoc Le, Ed Chi, Sharan Narang, Aakanksha Chowdhery, Denny Zhou
Published: ICLR 2023

WHAT IT IS
Replaces greedy decoding in chain-of-thought prompting with temperature sampling of m diverse reasoning paths, then aggregates final answers by majority vote. The core insight: for a reasoning task with a deterministic correct answer, sampling diverse paths and taking the most common final answer is more robust than any single greedy path. No additional training, no auxiliary model, no modification to the base model.

IMPLEMENTATION DETAILS
Algorithm (3 steps):
  1. Prompt: standard few-shot CoT prompt (same as base CoT; no modification to prompt structure).
  2. Sample: generate m reasoning paths via temperature sampling (m=40 in primary experiments). Each path ends with a final answer.
  3. Aggregate: majority vote over final answers only. Aggregation formula: argmax_a sum_i 1[a_i = a]. Final answer = the answer appearing most frequently across m paths. Full reasoning paths are NOT compared or scored; only the final answer string matters.

Sampling settings (model-specific):
  UL2-20B: temperature T=0.5, top-k=40
  LaMDA-137B: temperature T=0.5, top-k=40
  PaLM-540B: temperature T=0.7, top-k=40
  GPT-3 (text-davinci-002): temperature T=0.7, no top-k truncation (nucleus sampling)

Sample count ablation: performance improves from m=1 (greedy) through m=5, m=10, m=20, m=40. Gains saturate after ~20 samples for most tasks. 40 is safe upper bound.

Greedy CoT = m=1 (no sampling). Beam search is a worse alternative: produces lower diversity in outputs, self-consistency with sampling outperforms beam search on UL2-20B AQuA (26.9% vs 15.0%).

Answer normalization: answers are matched as strings after normalization (stripping units, whitespace). No semantic equivalence checking.

Models tested: UL2-20B, LaMDA-137B, PaLM-540B, GPT-3 text-davinci-002, Codex (code-davinci-001/002). Year: 2022 preprint, ICLR 2023.

STALENESS VERDICT: STILL-VALUABLE
Era: PaLM-540B, GPT-3 text-davinci-002, LaMDA (2022 models). Technique is model-agnostic.
2025-2026 status: Self-consistency remains a first-line inference-time scaling method. Active research area in 2025: Confidence-Improved Self-Consistency (CISC, ACL 2025 Findings) adds self-assessed confidence weighting; Confidence-Guided Early Stopping (CGES, arxiv 2511.02603) reduces average samples by 69.4% while maintaining accuracy; Mirror-Consistency (2025) integrates minority-view reflective feedback. The core majority-vote mechanism is not obsolete but is being extended with confidence signals rather than replaced. Key 2025 finding (arxiv 2603.06612 "Consensus is Not Verification"): majority vote FAILS for truthfulness/factual claims because all m paths share the same systematic bias; it only works when errors are independently random, which holds for math/reasoning but not for knowledge recall. External verifiers (PRMs, code execution, proof checkers) consistently outperform majority vote when available (optimal aggregation: arxiv 2510.13918).
Cite: CGES arxiv 2511.02603v1 (Nov 2025), CISC ACL 2025 Findings (proceedings.iclr.cc via search result), "Consensus is Not Verification" arxiv 2603.06612.

RELEVANCE TO REASONING-STATE ENGINE
- State carriage: each sampled reasoning path is a complete independent reasoning chain. Self-consistency does NOT carry state across model/context boundaries mid-path; each of the m paths is generated from scratch. In a reasoning-state engine, self-consistency applies at the OUTPUT SELECTION layer: generate m complete states, vote on the final answer. The state management challenge is holding m parallel contexts simultaneously, which is a fan-out/gather pattern not a sequential state-accumulation pattern.
- Candidate system: m reasoning paths ARE candidates. The SELECTOR is majority vote over final answers - this is NOT self-evaluation by an LLM; it is a statistical aggregation (count frequencies). No LLM judges which path is best. The model does not score its own outputs; it just produces them and an external counting procedure selects. This makes self-consistency's selector STRUCTURALLY different from and more reliable than ToT's LLM-scored evaluator. HOWEVER: when a deterministic external checker exists (test suite execution, proof verification, symbolic math checker), the external checker is strictly superior to majority vote because it provides ground-truth signal rather than consensus - a wrong answer that appears in 30 of 40 samples still fails the checker. Majority vote is the right fallback ONLY when no external signal is available.
- When more reasoning helps vs hurts: Helps when: (a) errors are independently random across paths (not systematic), (b) the correct answer appears in at least some paths even if not the majority, (c) the task has a deterministic final answer (math, formal reasoning). Hurts or is neutral when: (a) all paths share the same systematic error (factual recall, knowledge cutoff issues), (b) the problem requires open-ended generation (no single correct answer to vote on), (c) the model is so weak that all m samples collapse to the same wrong answer. Also: beyond ~20 samples, marginal gain per sample is near zero on most benchmarks.

Implementation pitfalls (do NOT do this):
- Do not aggregate full reasoning paths; aggregate final answers only. Path comparison is noisy and unnecessary.
- Do not use beam search as a substitute; beam search hurts diversity and underperforms temperature sampling.
- Do not apply to factual/knowledge tasks expecting accuracy improvements; consensus does not correct systematic bias.
- Do not use m=40 blindly; m=20 saturates for most tasks (run ablation at m=5,10,20 first).
- Do not treat majority vote as equivalent to verification; if an external checker (code execution, symbolic verifier) is available, prefer it over vote counting - a checker that returns a deterministic pass/fail on each of the m candidates is strictly superior.
- Do not use T=0 (greedy) when intending self-consistency; zero temperature produces identical paths, making voting meaningless.
