========================================================================
0. DESIGN INTENT
========================================================================
Inspiration: KIMI dashboard screenshot.
  - Left sidebar: mode/category strip, not a plan tree.
  - Centered chat window with integrated input, not a one-line command strip.
  - Dual region beyond chat (chat + visual slot).
The dashboard-design.txt is a BASE; the user's vision is:
  A. sidebar (icon rail + mode indicator) + main area with TWO windows:
     one chat window, one visual window.
  B. visual window is polymorphic — type still being decided. Plan treats
     "visual" as a slot whose content type (ACTIVITY / REVIEW / PLAN /
     PREVIEW / MONITOR / EXPLORE) switches by FSM state and user choice.
Anti-regression: do not lose any already-wired feature. Every tauri command
currently invoked must continue to work end-to-end after the shell rewrite.

Findings / deferrals carried forward to later tiers
(all three audit WARNs plus the additional finding surfaced during the
Tier 1 grounding sweep):

  1. SSB_CHECK_CONSTRAINT_MCP_LATENT_BUG — pre-existing, NOT fixed in
     Tier 1. CREATE_SSB_TABLE lines 39..67 (pre-Tier-1) omit three mcp_*
     action-type strings that the enum / as_sql_str / from_str all
     reference: 'mcp_server_connected', 'mcp_tool_called',
     'mcp_server_disconnected'. Source: batch-ful-d (commit bc43953)
     added the enum variants but forgot the CHECK list. Effect: fresh
     SSB databases silently reject those rows with SQLITE_CONSTRAINT;
     existing dev DBs skip the problem because CREATE TABLE IF NOT
     EXISTS never rewrites an existing CHECK constraint on a
     SCHEMA_VERSION bump. Owner: any tier that touches ssb.rs is
     expected to add the three strings to the CHECK list and bump
     SCHEMA_VERSION by 1. Not owned by Tier 2 unless that tier is
     already editing ssb.rs for a separate reason.

  2. CONTEXT_PACKAGE_STALE_CONSTANTS — future-tier discipline, not a
     code bug. context-compiler cached numeric facts (SCHEMA_VERSION,
     invoke_handler count, SsbActionType variant count) whose values
     had drifted well past the cache. Real values at Tier 1 start were
     19 / 43 / 71; context package said 8 / 35 / 32. Rule for later
     tiers: grep-verify every numeric claim in context-package.md
     before acting on it. The SSB_ACTION_TYPE_14_SITE_EXTENSION gotcha
     now explicitly calls this out.

  3. chat_history silent mismatched-row skip (WARN, deferred):
     crates/orchestrator/src/ssb_viewer.rs chat_history loop silently
     `continue`s when the action_type column disagrees with the
     decoded SsbPayload variant. A poisoned row vanishes without a
     trace. Fix: add `tracing::warn!(seq = seq, "chat_history row
     action_type/payload mismatch; skipping")` in a future patch.
     Same fix pattern applies to any future viewer methods that filter
     msgpack-decoded rows.

  4. chat_history LIMIT-before-filter scoping (WARN, deferred):
     Tier 1 implementation applies SQL `LIMIT ?3` before the in-memory
     `payload.project_id` filter. An SSB holding rows from multiple
     projects can return << `limit` entries to the dashboard even when
     more matching rows exist further back in the log. Documented as
     a scoping tradeoff in decisions §8. Fix in Tier 2 (or whichever
     tier expands project-scoping): either promote project_id to a
     dedicated SQL column indexed alongside action_type, OR iterate
     in two scans (fetch 2x the requested limit, then filter).

  5. ChatWindow silent-catch on refresh polls (WARN, deferred):
     refreshHistory / refreshInterventions / refreshRecentTasks /
     refreshFsm in ChatWindow.svelte swallow `await invoke(...)`
     errors. Low-severity (the polls fire before current_project is
     selected), but a real failure would vanish silently. Fix:
     `console.debug(e)` inside each `catch`. Any future tier that
     forks this poll pattern should adopt the same.

  6. SVELTE5_AUTOFOCUS_A11Y_WARNING pattern: Vite/svelte emits the
     `a11y_autofocus` warning for plain `<input autofocus>`. Standard
     fix: `onMount(() => inputEl?.focus())` with `bind:this={inputEl}`.
     Applied in SlashPalette.svelte. Use this pattern in every new
     overlay / modal / form entry.

6. TIER 2 — VISUAL PANES (polymorphic slot)
========================================================================
Goal: materialize the remaining window types so the SECONDARY slot (and any
user-requested PRIMARY override) can hold any of them. Wire FSM-based default
routing so the slot follows the work without user intervention.

Default routing table (read by layoutState on FSM/gate change):
  FSM state                              PRIMARY          SECONDARY
  IDLE                                   CHAT             empty (recent feed)
  PLANNING | TESTING_FIRST | EXECUTING   CHAT             ACTIVITY
  AUDITING                               CHAT             REVIEW
  RESEARCHING                            CHAT             RESEARCH
  CONFIGURING                            SETTINGS         CHAT
  MEMORIZING                             ACTIVITY         CHAT
  COMPLETE                               CHAT             MONITOR
  gate=autonomous (any state)            MONITOR          ACTIVITY
  SSB emits preview_available            (no change)      PREVIEW
User override is sticky — once the user picks a tab manually, autoroute is
disabled for that slot until the task ends.

Window components to build (each a Svelte file under src-frontend/src/windows/):

  ActivityWindow.svelte
    Reuses ActivityFeed + ActivityEntry.
    Adds: [reasoning] / [edit] / [validate] / [test] / [cloud] entry types
      (currently ActivityFeed renders only actions/commits/feasibility/rules).
    Needs: mapping from SSB action types to entry visual types.
    Live indicator: 2px teal pulse on the last entry while FSM=EXECUTING.
    No new tauri commands.

  PlanWindow.svelte
    Reuses PlanTree but adds hierarchical view: Concept > Phase > Step >
      BabyStep (today PlanTree only renders Phase + Step).
    Below tree: phase detail pane (description / expected outcome /
      dependencies / estimated steps remaining).
    New tauri commands:
      get_decomposition_tree(project_id: String, task_id: Option<String>)
          -> DecompositionTreeSnapshot
      get_phase_detail(phase_id: String) -> PhaseDetail
      get_baby_step_detail(baby_step_id: String) -> BabyStepDetail (8 blocks)

  ReviewWindow.svelte
    Wraps DiffViewer. Adds multi-file tab bar when >1 file in the action.
    Adds per-hunk Accept/Decline (purple hover buttons).
    Adds Ctrl+Shift+A / Ctrl+Shift+R shortcuts.
    No new tauri commands (get_action_detail already returns full payload).

  MonitorWindow.svelte
    Per dashboard-design.txt lines 661..736.
    Sections: identity (task name + elapsed), progress (bar + phase dots),
      status snapshot (currently / health / model / spend), interventions
      (only when present), timeline (last 15 events).
    Consumes: get_auto_advance_stats, get_gate_status,
      get_active_optimizations, get_recent_actions.
    New tauri command:
      get_monitor_snapshot(project_id: String) -> MonitorSnapshot
          (aggregates the above in one call to avoid 500ms × N polling)

  ExploreWindow.svelte
    Read-only Q&A. Simple input + answer region with file citations.
    Routes through /explore intent, which issues a knowledge-engine query
      via the sidecar.
    New tauri commands:
      submit_explore_query(project_id: String, question: String)
          -> explore_id
      get_explore_result(explore_id: String)
          -> { answer, sources: Vec<{path, range, score}>, citations }
    Citations are clickable — open REVIEW window read-only at that path+range.

  PreviewWindow.svelte
    Shows iframe of the current preview_available URL.
    Tab bar when multiple preview slots active (draft vs live).
    Fallback panel when no preview active: "no preview running — start a web
      scaffold task".
    New tauri commands:
      get_preview_state(project_id: String) -> PreviewState
          (returns {slot, url, port, pid, status} for draft and live)
      stop_dev_server(preview_id: String) -> ()

  SettingsWindow.svelte (Tier 4 expansion of existing Settings.svelte)
    Placeholder in Tier 2 so the sidebar settings icon routes here.

Grounding / test strategy:
  - Each window has a contract test: mount it with a mocked layoutState,
    verify the tauri commands it invokes return the data shape it expects.
  - ReviewWindow: open a real DiffViewer via get_action_detail to confirm
    the migration didn't break existing multi-file rendering.
  - Routing table: unit test that every FSM-state transition produces the
    expected default arrangement.
  - preview_available integration: write a dummy SSB row and verify
    PreviewWindow picks it up within one poll tick.
Exit criteria:
  - User can hold CHAT in primary and switch secondary between all seven
    visual window types without losing state.
  - DiffViewer no longer replaces ActivityFeed — both visible simultaneously.
