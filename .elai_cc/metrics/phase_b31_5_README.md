# B-31.5 — Resumable Indexing Scale Benchmark

This directory holds the 6 metric TOMLs produced by the scale-benchmark
harness under `scripts/scale_test/`. The benchmark validates that the
B-31 resumable indexing + cross-process lock + graceful shutdown pipeline
holds up under load: real wall-time, peak RSS, crash-resume identity,
contention semantics, deadline honouring, and long-tail memory plateau.

## Files

- `phase_b31_5_tier_a.toml` — Tier A baseline (uninterrupted indexing).
- `phase_b31_5_tier_b.toml` — Tier B crash-resume identity (kill at 10/50/90%).
- `phase_b31_5_tier_c.toml` — Tier C cross-process lock contention.
- `phase_b31_5_tier_d.toml` — Tier D graceful shutdown.
- `phase_b31_5_tier_e.toml` — Tier E long-tail memory.
- `phase_b31_5_scale.toml` — Aggregate summary (overall_pass).

## What `overall_pass = true` means

The summary TOML's `[summary].overall_pass` is true when every tier-N
script exited 0 and the corresponding contract test under
`crates/orchestrator/tests/scale_*_contract.rs` passes. The contract tests
read the metric TOMLs at runtime and assert the invariants below.

| Tier | Pass invariant |
|---|---|
| A | wall_secs / peak_rss_mb / batch counts populated; no schema drift |
| B | every kill point has identity_diff_lines == 0 AND files_skipped_on_resume > 0 AND ssb_index_resume_action_count == 1 |
| C | two_instance_race.instance_b_exit_ms < 1000; stale_pid_reclaim.reclaim_wall_secs < 5 |
| D | graceful_shutdown_clean.deadline_honored == true; graceful_shutdown_forced.forced_release_logged == true |
| E | rss_30min_samples_mb has >=3 samples AND is NOT monotonically increasing past a 5% noise threshold |

## Reproducing on the synthetic fixture (default)

```bash
# Generate fixture + run all 5 tiers + summary.
cd .elai_cc
bash scripts/scale_test/run_all_tiers.sh
```

The synthetic fixture is a 200-file deterministic Rust crate generated by
`scripts/scale_test/make_synth_fixture.sh`. Wall time on a modern laptop is
~15-20 minutes (Tier E dominates with its 30-min sampling interval).

## Reproducing on production-scale fixtures (Linux / Chromium / VSCode / Postgres)

DECISION-B31.5-1: the production-scale fixtures are out-of-scope for the
session that ships this harness — 30+ GB of clones at 6-14h each. To run
them yourself when a long terminal is available:

```bash
# 1. Clone each repo at the snapshot the original plan calls for.
mkdir -p ~/elai_scale_fixtures
cd ~/elai_scale_fixtures
git clone --depth 1 --branch v6.7 https://github.com/torvalds/linux.git linux
git clone --depth 1 --branch 121.0.6167.85 https://github.com/chromium/chromium.git chromium
git clone --depth 1 --branch 1.94.2 https://github.com/microsoft/vscode.git vscode
git clone --depth 1 --branch REL_17_0 https://github.com/postgres/postgres.git postgres

# 2. Run a single tier against one of them:
ELAI_SCALE_FIXTURE_ROOT=~/elai_scale_fixtures TIER=linux bash scripts/scale_test/run_tier_a.sh

# 3. Or run the full suite:
ELAI_SCALE_FIXTURE_ROOT=~/elai_scale_fixtures TIER=linux bash scripts/scale_test/run_all_tiers.sh
```

Expected wall-time budgets per tier (on the linux fixture, modern hardware):

| Tier | Budget |
|---|---|
| A | 3-6 h |
| B | 6-12 h (3 kill points × resume re-run) |
| C | 5 min (no full index needed) |
| D | 5 min |
| E | 4-8 h (long-tail with 30-min sampling) |

Override the Tier E sample interval for faster smoke tests via
`TIER_E_SAMPLE_INTERVAL_SECS=300 bash run_tier_e.sh` (5-min sampling instead
of 30-min).

## Windows equivalents

Each shell script can be invoked via Git Bash on Windows. PowerShell users
who don't have Git Bash installed can map them onto cmd by running the
elai launcher directly + sourcing the metric TOMLs by hand — the contract
tests don't depend on bash for parsing, only on the TOML files existing.

```powershell
# Generate fixture + run Tier A via bash interpreter:
& "C:\Program Files\Git\bin\bash.exe" scripts/scale_test/run_tier_a.sh
```

## Why these particular metrics

- **identity_diff_lines == 0** — the resume path MUST produce DKG output
  identical to the single-pass run. Any drift means resume is doubly
  emitting or skipping, neither of which is acceptable for downstream
  rule-engine queries.
- **files_skipped_on_resume > 0** — proves the BLAKE3 hash skip-path
  actually fired on the second run; without skips, resume == cold start.
- **instance_b_exit_ms < 1000** — `IndexLock::try_acquire` is supposed to
  fast-fail. If a contender takes longer than 1s to bounce, the lock
  acquisition logic is doing something heavy (an unintended file scan).
- **rss_30min_samples_mb plateau** — distinguishes "growing working set"
  from "leak". A plateau anywhere in the run is sufficient evidence; we
  do not require all samples to be flat (early-batch RSS naturally grows
  as caches warm up).

## Re-generating metrics from a real run

Every script writes its TOML directly. After a real-fixture run completes,
re-run the contract tests to verify the new metrics:

```bash
cd .elai_cc
cargo test -p elai-orchestrator --test scale_resume_identity_contract \
    --test scale_lock_contention_contract \
    --test scale_long_tail_memory_contract
```

A red test means the harness ran but the SLA was violated — open the
relevant tier's TOML to inspect what fell out of bounds.
